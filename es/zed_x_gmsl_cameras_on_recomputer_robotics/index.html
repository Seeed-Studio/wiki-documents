Usar cámaras GMSL ZED X-Series con reComputer Robotics

Seeed Studio × Stereolabs

Visión de profundidad ZED X, lista para reComputer Robotics

Lleva visión estéreo GMSL2 robusta y de largo alcance a robots compactos, máquinas autónomas y sistemas de IA física. Las plataformas reComputer Robotics de Seeed Studio combinan cómputo NVIDIA Jetson, E/S preparada para robótica y conectividad GMSL escalable en hardware listo para despliegue.

Jetson Orin & ThorHasta 8 cámaras GMSL2JetPack 6.2 & 7.2Vista previa de profundidad en ZED Studio

Esta guía explica cómo usar cámaras GMSL2 Stereolabs ZED X-series con el hardware de robótica de Seeed Studio. Las instrucciones de configuración están disponibles para reComputer Robotics J50 Mini, J50 (J501) y J40 (J401). Se están preparando recursos de controladores específicos para J601.

reComputer Robotics J50 Mini​

Lo que necesitas​

  • reComputer Robotics J50 Mini con la placa de extensión GMSL
  • Una cámara ZED X-series GMSL2 compatible
  • Un cable o mazo GMSL2 Fakra/Mini-Fakra compatible
  • JetPack 6.2.x o JetPack 7.2
  • Acceso a Internet, una pantalla, teclado y ratón para ZED Studio
info

Esta guía cubre la configuración del controlador de la plataforma de Seeed y del ZED SDK. La compatibilidad con el modelo de cámara puede depender de la versión del ZED SDK instalada. Usa el ZED SDK más reciente compatible con tu versión de JetPack/L4T.

1. Conectar la cámara​

  1. Apaga completamente el reComputer.
  2. Desconecta la entrada de alimentación de CC.
  3. Conecta la cámara ZED X a un puerto GMSL2 usando el cable o mazo compatible. Asegúrate de que el conector esté completamente insertado y bloqueado.
  4. Vuelve a conectar la alimentación e inicia el dispositivo.
aviso

No conectes ni desconectes en caliente la cámara GMSL. Siempre corta la alimentación antes de conectar o desconectar la cámara o el mazo GMSL.

2. Habilitar la compatibilidad con ZED X GMSL​

Elige una de las siguientes rutas. Flashear el BSP más reciente se recomienda para un despliegue limpio; instalar el DEB es más rápido cuando quieres mantener un sistema existente.

  • Opción 1 · Flashear el BSP más reciente
  • Opción 2 · Instalar DEB

Comprueba la información de compilación del BSP ya instalada en el dispositivo:

cat /etc/nv_tegra_release

Busca el campo DATE. Si el BSP se compiló el 24 de septiembre de 2026 o después, la compatibilidad con ZED X GMSL ya está incluida y puedes continuar con la instalación del ZED SDK.

Si la compilación es anterior, flashea la imagen más reciente de JetPack 7.2 / L4T 39.2.0 con fecha 24 de septiembre de 2026 siguiendo los pasos a continuación. Las dos variantes de módulo usan imágenes diferentes, así que selecciona la pestaña que coincida con el módulo Jetson instalado en tu J50 Mini.

aviso

El flasheo reescribe el almacenamiento de destino. Haz una copia de seguridad de los datos de la aplicación, archivos de configuración y credenciales antes de comenzar.

Preparar el host y descargar la imagen​

Prepara un equipo host físico con Ubuntu 20.04, 22.04 o 24.04, un cable de datos USB Type-C y el J50 Mini con su SSD NVMe instalado. Descarga la imagen que coincida con tu módulo directamente en el host Ubuntu:

  • AGX Orin 64GB
  • AGX Orin 32GB
Descargar BSP de 64GB ↗

Nombre de archivo:

mfi_recomputer-mini-agx-orin-64g-j501-7.2.0-39.2.0-2026-09-24.tar.gz
Descargar BSP de 32GB ↗

Nombre de archivo:

mfi_recomputer-mini-agx-orin-32g-j501-7.2.0-39.2.0-2026-09-24.tar.gz
tip

Si quieres mantener una instalación existente de JetPack 6.2.x, usa Opción 2 · Instalar DEB en lugar de flashear esta imagen de JetPack 7.2.

Entrar en modo de recuperación forzada​
  1. Apaga el J50 Mini y desconecta su alimentación.
  2. Mantén pulsado el botón REC.
  1. Conecta el cable de alimentación y luego suelta el botón REC.
  2. Conecta el J50 Mini al host Ubuntu con un cable de datos USB Type-C a través del puerto de flasheo que se muestra a continuación.
  1. En el host Ubuntu, verifica el modo de recuperación:
lsusb

La salida debe incluir el ID USB de tu módulo:

Módulo JetsonSalida esperada
AGX Orin 64GB0955:7023 NVidia Corp.
AGX Orin 32GB0955:7223 NVidia Corp.

Ejecuta los comandos para el módulo que seleccionaste. Si tu navegador guardó el archivo en otro lugar, reemplaza ~/Downloads con el directorio de descargas real.

  • AGX Orin 32GB

sudo ./tools/kernel_flash/l4t_initrd_flash.sh \
  --flash-only --massflash 1 --network usb0 --showlogs
cd ~/Downloads

cd mfi_recomputer-mini-agx-orin-32g-j501-7.2.0-39.2.0-2026-09-24

Primero, identifica la versión de Jetson Linux instalada:

Usa solo el paquete que coincida con la versión L4T indicada. No instales ambos paquetes.

El siguiente comando coincide con el nombre de archivo del controlador para esta placa y versión de L4T. Si tu directorio de descargas contiene varias versiones coincidentes, reemplaza el comodín por el nombre de archivo exacto que descargaste.

  • JetPack 7.2

3. Instalar el ZED SDK​

Ve a la página de descarga de Stereolabs ZED SDK y selecciona el instalador de NVIDIA Jetson que coincida con la versión indicada por cat /etc/nv_tegra_release:

Sistema instaladoSeleccionar en la página del ZED SDK
JetPack 6.2.x / L4T 36.4.xZED SDK for JetPack 6.1 and 6.2 (L4T 36.4)
JetPack 7.2 / L4T 39.2ZED SDK for JetPack 7.2 (L4T 39.2)

Instala zstd, haz que el instalador descargado sea ejecutable y ejecútalo. Reemplaza el marcador a continuación con el nombre de archivo real descargado.

sudo apt update
sudo apt install -y zstd
cd ~/Downloads
chmod +x ZED_SDK_Tegra_L4T<release>_v<version>.zstd.run
./ZED_SDK_Tegra_L4T<release>_v<version>.zstd.run

Sigue las indicaciones del instalador y mantén seleccionadas las herramientas ZED. Reinicia después de que finalice la instalación:

sudo reboot
tip

La versión de L4T en el nombre del instalador del ZED SDK debe coincidir con la versión L4T del reComputer. Un SDK o DEB de cámara que no coincida puede impedir que se detecte la cámara.

ZED_Studio

También puedes iniciarlo directamente desde el directorio de instalación del SDK:

reComputer Robotics J50 (J501)​

Utiliza esta sección para reComputer Robotics J501 con la placa de extensión GMSL y una cámara ZED de la serie X compatible. Las dos opciones de configuración son: flashear un BSP con soporte ZED X GMSL, o mantener tu sistema actual e instalar el controlador DEB correspondiente. Consulta la guía de hardware e introducción de J501 para el diseño de la placa e instrucciones completas de flasheo.

1. Conectar la cámara​

Apaga el J501 y desconecta la alimentación de CC. Conecta la cámara a un puerto GMSL2 con un cable Fakra/Mini-Fakra compatible, bloquea el conector y luego vuelve a conectar la alimentación e inicia el dispositivo.

2. Habilitar el soporte ZED X GMSL​

Elige una opción. Flashea el BSP para una instalación limpia de JetPack 7.2; instala el DEB para mantener un sistema JetPack 6.2.1 o 7.2 existente y compatible.

  • Opción 1 · Flashear JetPack 7.2 BSP
  • Opción 2 · Instalar controlador DEB

Los paquetes BSP de JetPack 7.2 / L4T 39.2.0 que se muestran a continuación incluyen soporte ZED X GMSL. Selecciona la imagen que coincida con el módulo AGX Orin instalado en el Robotics J501:

Modelo Robotics J501Módulo JetsonBSP
J5011AGX Orin 32GBDownload J5011 BSP
J5012AGX Orin 64GBDownload J5012 BSP
aviso

El flasheo borra los datos del SSD NVMe de destino. Haz una copia de seguridad de los datos importantes antes de comenzar y mantén la alimentación y el USB conectados hasta que el flasheo se complete. Usa la Opción 2 si quieres conservar el sistema actual.

Preparar el host y el J501​

Prepara el siguiente equipo:

  • reComputer Robotics J501 con el módulo AGX Orin correspondiente
  • SSD NVMe instalado en el J501
  • PC host físico con Ubuntu ejecutando Ubuntu 20.04, 22.04 o 24.04
  • Cable de transmisión de datos USB tipo C
  • Pantalla, teclado y ratón para la configuración del primer arranque

Recomendamos un host Ubuntu físico en lugar de una máquina virtual. Para JetPack 7.2, Ubuntu 24.04 admite el flasheo y la instalación de componentes en el dispositivo de destino; usa Ubuntu 20.04 o 22.04 si necesitas componentes de desarrollo en el host.

Descarga el BSP para tu módulo J501 en el host Ubuntu. El archivo es grande y puede tardar alrededor de 60 minutos en descargarse; espera a que la descarga termine antes de extraerlo.

Entrar en modo de recuperación forzada​

  1. Apaga el J501. Conecta un cable de datos USB tipo C entre el PC host y el puerto USB 2.0 DEVICE del J501.
  2. Usa un pin para mantener presionado el botón RECOVERY.
  1. Mientras mantienes presionado RECOVERY, conecta la fuente de alimentación del J501.
  2. Suelta RECOVERY.
  3. En el host Ubuntu, ejecuta lsusb para verificar que el J501 haya entrado en modo de recuperación forzada:
Módulo J501ID lsusb esperado
AGX Orin 32GB (J5011)0955:7223 NVidia Corp.
AGX Orin 64GB (J5012)0955:7023 NVidia Corp.

Si el ID esperado no aparece, verifica que hayas usado el puerto USB DEVICE y un cable con capacidad de transmisión de datos, luego repite los pasos de recuperación.

Extraer y flashear el BSP​

En el host Ubuntu, extrae el archivo específico del módulo que descargaste. Sustituye el marcador de posición por el nombre de archivo exacto descargado anteriormente:

cd ~/Downloads
sudo tar xpf <downloaded-J501-BSP>.tar.gz

Cambia al directorio BSP extraído. Usa ls -d mfi_* para identificar su nombre si es necesario:

cd <extracted-J501-BSP-directory>

Con el J501 aún conectado en modo de recuperación forzada, flashea JetPack en el SSD NVMe:

sudo ./tools/kernel_flash/l4t_initrd_flash.sh \
  --flash-only --massflash 1 --network usb0 --showlogs

El comando de flasheo suele tardar entre 2 y 10 minutos. Un flasheo correcto termina con el mensaje de finalización que se muestra a continuación:

Después de flashear, desconecta el cable USB y apaga y enciende de nuevo el J501. Conéctalo a una pantalla usando un adaptador PD a HDMI, o usa una pantalla que acepte vídeo USB-C/PD directamente, y luego completa la configuración inicial de Ubuntu:

Completa la Configuración del sistema según sea necesario. Este BSP ya incluye el controlador ZED X GMSL para Robotics J501, así que continúa directamente con 3. Instalar el ZED SDK.

Usa esta opción para conservar el sistema existente. Primero comprueba la versión instalada de Jetson Linux:

cat /etc/nv_tegra_release

reComputer Robotics J40 (J401)​

Esta sección cubre las placas carrier Robotics J401 con módulos J3010 / J3011 (Orin Nano) o J4011 / J4012 (Orin NX) y la placa de extensión GMSL. Usa una cámara GMSL2 ZED de la serie X compatible y un cable Fakra/Mini-Fakra compatible. La guía de la placa carrier Robotics J401 proporciona el diseño de la placa y los detalles de las interfaces.

1. Conectar la cámara​

  1. Apaga el reComputer y desconecta la alimentación de CC.
  2. Conecta la cámara ZED X a un puerto GMSL2 en la placa de extensión. Inserta completamente y bloquea el conector.
  3. Vuelve a conectar la alimentación e inicia el dispositivo.
aviso

Apaga el equipo antes de conectar o desconectar la cámara o el mazo GMSL.

2. Habilitar compatibilidad ZED X GMSL​

Elige una opción: flashear un BSP con el controlador ZED X GMSL incluido, o instalar el DEB correspondiente para mantener el sistema existente.

  • Opción 1 · Flashear Robotics J401 BSP
  • Opción 2 · Instalar DEB del controlador
Preparar el host y el hardware​

Prepara el siguiente equipo:

  • Placa carrier Robotics J401 con un módulo Orin Nano 4GB/8GB u Orin NX 8GB/16GB y refrigeración activa
  • SSD NVMe M.2 2280 instalado en la placa
  • PC host con Ubuntu y un cable de transmisión de datos USB Type-C
  • Fuente de alimentación, pantalla, teclado y ratón para la configuración del primer arranque

Utiliza un host físico con Ubuntu. Selecciona su versión de Ubuntu según la versión de JetPack en el BSP descargado:

Versión de BSP JetPackHost Ubuntu 20.04Host Ubuntu 22.04Host Ubuntu 24.04
JetPack 6.xCompatibleCompatible—
JetPack 7.2CompatibleCompatibleCompatible para flasheo e instalación de componentes en el dispositivo

Para los componentes de desarrollo de host de JetPack 7.2, utiliza Ubuntu 20.04 o 22.04.

aviso

El flasheo borra el SSD NVMe de destino. Haz una copia de seguridad de tus datos antes de continuar y mantén la alimentación y el USB conectados hasta que el flasheo termine. Usa la Opción 2 para conservar tu sistema actual.

Descargar el BSP para tu módulo​

Descarga el archivo correspondiente directamente en el host Ubuntu. Los cuatro BSP siguientes incluyen el controlador ZED X GMSL. Elige el paquete para el módulo instalado:

  2. Coloca el interruptor de la placa en RESET, como se muestra a continuación.
  1. Conecta el cable de alimentación para encender la placa.
  2. Conecta el puerto de dispositivo/debug USB 2.0 Type-C de la placa al host Ubuntu con un cable de datos.
  3. En el host Ubuntu, abre una terminal y ejecuta:
lsusb

Extraer y flashear el BSP​

En el host Ubuntu, ve al directorio de descargas y extrae el archivo. Sustituye el marcador de posición por el nombre de archivo completo descargado para tu módulo:

cd ~/Downloads
sudo tar xpf <downloaded-J401-BSP>.tar.gz

Entra en el directorio BSP extraído. Usa ls -d mfi_* para identificar el directorio si es necesario:

cd <extracted-J401-BSP-directory>

Con la placa aún conectada en modo force recovery, flashea JetPack en el SSD NVMe:

sudo ./tools/kernel_flash/l4t_initrd_flash.sh \
  --flash-only --massflash 1 --network usb0 --showlogs

El comando de flasheo normalmente tarda 2–10 minutos. Espera al mensaje de finalización correcta que se muestra a continuación:

Completar la configuración del primer arranque​

Después de que el flasheo se complete correctamente, desconecta el cable de datos USB y apaga la placa. Devuelve el interruptor de RESET a su posición de funcionamiento normal y luego enciende la placa.

Conecta una pantalla mediante la salida USB-C DisplayPort usando un adaptador USB-C/DP-a-HDMI compatible, o conéctala directamente a una pantalla que admita vídeo por USB-C. Completa la Configuración del sistema de Ubuntu, incluyendo tu cuenta de usuario y la configuración regional:

El BSP ya incluye el controlador ZED X GMSL. Continúa con 3. Instalar el ZED SDK.

Usa esta opción para mantener el sistema existente. En el reComputer, comprueba la versión instalada de Jetson Linux:

cat /etc/nv_tegra_release

Descarga el paquete Robotics J401 para la versión de JetPack instalada. Comprueba la versión L4T del paquete descargado frente a la versión del sistema antes de instalarlo. Sustituye el nombre de archivo de marcador de posición en los comandos por el nombre de archivo descargado exacto.

dpkg -l | grep stereolabs-zedx

3. Instalar el ZED SDK​

Comprueba cat /etc/nv_tegra_release, luego descarga el instalador NVIDIA Jetson correspondiente desde la página de descarga de Stereolabs ZED SDK:

Sistema instaladoCompilación ZED SDK
JetPack 6.2 / L4T 36.4.xZED SDK para JetPack 6.1 y 6.2 (L4T 36.4)
JetPack 7.2 / L4T 39.2ZED SDK para JetPack 7.2 (L4T 39.2)

Instala zstd, haz que el instalador sea ejecutable y ejecútalo. Sustituye el marcador de posición del instalador por el nombre de archivo descargado:

sudo apt update
sudo apt install -y zstd
cd ~/Downloads
chmod +x ZED_SDK_Tegra_L4T<release>_v<version>.zstd.run
./ZED_SDK_Tegra_L4T<release>_v<version>.zstd.run

Sigue las indicaciones del instalador y mantén seleccionadas las herramientas ZED. Reinicia cuando la instalación se complete:

sudo reboot

En el escritorio del reComputer, inicia ZED Studio:

/usr/local/zed/tools/ZED_Studio

Confirma que la cámara conectada es detectada, abre su vista en vivo y habilita Depth. Una imagen estable y una vista de profundidad que se actualiza en tiempo real confirman que la configuración Robotics J401 ZED X GMSL está funcionando.

Solución de problemas​

  • Cámara no detectada: Confirma que el DEB, el BSP y el ZED SDK coinciden con la versión L4T instalada. Luego apaga y vuelve a insertar el cable de la cámara.
  • APT informa de una discrepancia de paquetes: No fuerces la instalación. Descarga el paquete para la versión L4T mostrada por cat /etc/nv_tegra_release.
  • ZED Studio no se abre: Confirma que el escritorio gráfico se está ejecutando e inicia /usr/local/zed/tools/ZED_Studio desde una terminal para ver la salida de error.
  • La imagen aparece pero la profundidad no está disponible: Confirma que instalaste el ZED SDK completo con herramientas y que el modelo de cámara seleccionado es compatible con esa versión del SDK.
  • Vídeo intermitente: Apaga y verifica el cable Fakra/Mini-Fakra, la posición de bloqueo y la longitud de cable admitida antes de probar de nuevo.
