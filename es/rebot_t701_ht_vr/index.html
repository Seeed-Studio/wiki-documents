Teleoperación VR del reBot Arm T701 HT

Star on GitHub0

Usa los controladores de VR izquierdo y derecho para controlar los brazos T701 HT correspondientes, incluido el seguimiento de la pose del efector final y el control de la garra. El navegador del visor lee los datos de los controladores mediante WebXR y los envía al ordenador a través de WebSocket. El servidor de streaming los reenvía después al controlador de doble brazo por UDP.

Compatibilidad de dispositivos

Esta demo se ha probado en Quest. Los usuarios de Pico pueden conectarse mediante la misma canalización WebXR → WebSocket → UDP usando un navegador del visor compatible con WebXR. Las instrucciones siguientes usan Quest como ejemplo y cubren tanto conexiones por USB como por WiFi.

Entorno y conexiones​

Obtén el SDK e instala sus dependencias usando las instrucciones de instalación de inicio rápido del T701 HT. Completa el mapeo serie, comprueba la retroalimentación de las articulaciones y de la garra y establece las posiciones cero. El brazo izquierdo usa CAN1 y el derecho CAN2.

Prepara un visor de VR y ambos controladores. El modo USB también necesita un cable de datos USB; el modo WiFi necesita que el visor y el ordenador estén en la misma LAN.

Ejecuta los comandos siguientes desde la raíz del SDK. En cada nueva terminal, vuelve a ese directorio y activa el entorno t701-ht.

conda activate t701-ht

Iniciar el streaming​

En la primera terminal, inicia la interfaz de streaming:

python Quest_controller_stream/quest_stream_tui.py

Usa Arriba/Abajo para seleccionar un campo, Izquierda/Derecha para ajustarlo, E para editar direcciones o puertos y Enter para activar un botón. Los valores predeterminados iniciales son WiFi / 8080, y la interfaz guarda tu configuración. Al cambiar de modo, selecciona primero Stop Server, luego establece el modo y los puertos que se muestran en la pestaña correspondiente.

  • USB (Con cable)
  • WiFi (Inalámbrico)

Conexión y ajustes​

Activa el modo desarrollador en el visor, conéctalo al ordenador que ejecuta el SDK con un cable de datos USB y autoriza la depuración USB en el visor. Comprueba la conexión en otra terminal:

adb devices

El dispositivo debe mostrar el estado device. Si muestra unauthorized, confirma la autorización en el visor. En Ubuntu, instala un adb que falte con sudo apt install adb.

Configura la interfaz de streaming como sigue:

AjusteValor
ModeUSB
Force HTTPSFalse
HTTP Host / Port0.0.0.0 / 8080
WS Host / Port0.0.0.0 / 8765
UDP IP / Port127.0.0.1 / 5005
Verify Port5005

Iniciar y abrir la página​

Selecciona Start Server. El programa usa adb reverse para reenviar los puertos 8080 y 8765 del visor al ordenador. Abre esta URL en el navegador del visor:

http://localhost:8080/index.html?ws=ws://localhost:8765

Configura la entrada de WebSocket de la página como ws://localhost:8765. El modo USB usa HTTP / WS y no necesita un certificado HTTPS. Aquí, localhost llega al ordenador a través del reenvío por USB.

Inicio por línea de comandos (opcional)​

Sin la interfaz de streaming, ejecuta este comando desde la raíz del SDK. No lo ejecutes junto con un servidor iniciado por la interfaz:

python Quest_controller_stream/start_stream_server.py --http-host 0.0.0.0 --http-port 8080 --ws-host 0.0.0.0 --ws-port 8765 --udp-ip 127.0.0.1 --udp-port 5005 --adb auto

Conexión y ajustes​

Conecta el visor y el ordenador que ejecuta el SDK a la misma LAN. Este modo no requiere cable USB, ADB ni autorización de depuración USB.

En el ordenador, encuentra su IP de la LAN y comprueba OpenSSL:

hostname -I
openssl version

Usa la IP real del ordenador en esa LAN, no una dirección de adaptador de Docker o VPN. En Ubuntu, instala un OpenSSL que falte con sudo apt install openssl.

Configura la interfaz de streaming como sigue:

AjusteValor
ModeWiFi
Force HTTPSTrue
HTTP Host / Port0.0.0.0 / 8080
WS Host / Port0.0.0.0 / 8765
UDP IP / Port127.0.0.1 / 5005
Verify Port5005
Cert File.certs/quest-controller.crt
Key File.certs/quest-controller.key

Iniciar y abrir la página​

Selecciona Start Server. El modo WiFi usa HTTPS / WSS. Si faltan el certificado y la clave privada, el programa genera un certificado autofirmado con OpenSSL.

Abre en el navegador del visor la URL WiFi que se muestra en la interfaz, comprobando que use la IP real de la LAN del ordenador. Por ejemplo, si la IP del ordenador es 192.168.1.100:

https://192.168.1.100:8080/index.html?ws=wss://192.168.1.100:8765

Sustituye la IP de ejemplo por la IP real del ordenador. En el primer acceso, gestiona el aviso del certificado autofirmado en el navegador y recarga la página. Configura la entrada de WebSocket como wss://ACTUAL_COMPUTER_IP:8765, no localhost ni ws://.

Los valores 0.0.0.0 de HTTP Host y WS Host son direcciones de escucha, no direcciones que se deban abrir en el visor. Cuando el servidor de streaming y el controlador de doble brazo se ejecutan en el mismo ordenador, el destino UDP sigue siendo 127.0.0.1:5005.

Inicio por línea de comandos (opcional)​

Sin la interfaz de streaming, ejecuta este comando desde la raíz del SDK. No lo ejecutes junto con un servidor iniciado por la interfaz. --adb never desactiva el reenvío ADB y habilita automáticamente HTTPS / WSS.

python Quest_controller_stream/start_stream_server.py --http-host 0.0.0.0 --http-port 8080 --ws-host 0.0.0.0 --ws-port 8765 --udp-ip 127.0.0.1 --udp-port 5005 --adb never

Después de conectar con el modo seleccionado, elige Start XR Stream en la página del visor. Comprueba los siguientes valores de estado:

Estado de la páginaValor esperado
WebSocketConnected
XRRunning
Both controllersTracking

La página restaura la configuración de WebSocket guardada. Después de cambiar de modo, comprueba que el protocolo, la IP y el puerto de la entrada coincidan con la pestaña seleccionada y luego guarda la configuración.

Comprobar los datos de los controladores​

Selecciona Start Verify en la interfaz de streaming del ordenador. Mueve ambos controladores y comprueba que el recuento de paquetes aumente y que los datos de pose y botones cambien con tu entrada.

Luego selecciona Stop Verify. Mantén en ejecución el servidor, el modo USB o WiFi seleccionado y el streaming XR del visor. Verify y el controlador de doble brazo usan el mismo puerto UDP 5005 y no pueden recibir simultáneamente.

Tecla en la terminalFunción
1 / 2 / 3 / 4Abrir Controles, Mano izquierda, Mano derecha y Registros.
TabCambiar de página.
QDetener el servidor de streaming y salir de la interfaz.

Iniciar el control de doble brazo​

Despeja el rango de movimiento antes de empezar

Detén Verify, udp_receiver_test.py y cualquier otro receptor UDP 5005. Después de recibir datos de los controladores, el programa mueve primero el brazo izquierdo y luego el derecho a sus poses iniciales de VR. Asegura el robot, retira las cargas y despeja el rango de movimiento y la trayectoria de retorno. Permanece junto al robot y mantente alejado de los puntos de pellizco de articulaciones y garra.

En una segunda terminal, desde la raíz del SDK:

conda activate t701-ht
cd scripts
python t701_ht_vr_dual_cartesian_qp_control.py

Esta entrada controla ambos brazos directamente, sin un menú de selección de brazo. Los brazos izquierdo y derecho usan T701-HT_robot_param/T701-HT_left.yaml y T701-HT_right.yaml, respectivamente.

Espera a que terminen los movimientos iniciales y a que el programa muestre su mensaje de inicio de control, luego usa los siguientes controles:

EntradaComportamiento del robot
Mantener pulsado Squeeze en el controlador izquierdo o derechoEl brazo correspondiente sigue la pose del controlador.
Soltar SqueezeMantener la posición actual.
Usar Trigger mientras mantienes SqueezeAbrir o cerrar la garra correspondiente.
Pulsar el botón principal, etiquetado como A en el programaRestablecer suavemente ese brazo a sus ángulos articulares iniciales para esta ejecución.
Pulsar Ctrl+C en la terminal de controlDevolver los brazos a cero en modo MIT y detener los motores. Espera a que termine el apagado.

Después de que el controlador salga, pulsa Q en la interfaz de streaming para detener el servidor y salir.

Solución de problemas​

SíntomaComprobación y acción
La página USB no se abreConfirma la autorización de depuración USB, el estado device en adb devices y que el servidor de streaming esté en ejecución. Usa http://localhost:8080.
La página WiFi no se abreConfirma que el visor y el ordenador estén en la misma LAN. Usa https://ACTUAL_COMPUTER_IP:8080, gestiona el aviso del certificado y comprueba que el ordenador permita conexiones en los puertos 8080 y 8765.
WebSocket alterna entre Connecting y ReconnectingUSB usa ws://localhost:8765 con Force HTTPS desactivado; WiFi usa wss://ACTUAL_COMPUTER_IP:8765. Comprueba si la página restauró la configuración del otro modo.
No se puede enlazar UDP 5005Detén Verify, udp_receiver_test.py u otro receptor que use el puerto.
No hay paquetes de controladores en los 10 segundos posteriores al inicioSelecciona Start XR Stream en el visor, comprueba que WebSocket esté conectado y establece el destino UDP en 127.0.0.1:5005. El programa sale antes de inicializar los brazos.
El modo de conexión cambia después de restablecer la configuraciónReset Defaults o eliminar la configuración guardada restaura WiFi / 8080. Vuelve a establecer el modo y los puertos en la pestaña seleccionada; cambiar de modo no restablece los puertos automáticamente.

Interfaz de escritorio (opcional)​

La interfaz de escritorio es Quest_controller_stream/quest_stream_ui.py. Requiere la dependencia opcional PyQt5 y usa una configuración .quest_stream_ui.json independiente. Se aplican los mismos requisitos de protocolo y direcciones para USB y WiFi; configúralos por separado en la interfaz de escritorio.
