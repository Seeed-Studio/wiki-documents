Introducción a XIAO STM32C5

Consigue uno ahora 🖱️

Descripción general​

Conoce el primer XIAO basado en STM32. Construido alrededor del STM32C5A3CG con un núcleo Arm Cortex-M33 a 144MHz, XIAO STM32C5 aporta conectividad CAN FD, 16MB de Flash externa y una IMU de seis ejes con calentamiento programable al formato compacto XIAO. Resistencias de calentamiento dedicadas alrededor de la IMU permiten un calentamiento controlado por firmware para proyectos de robótica y detección de movimiento. Dos controladores CAN FD nativos, incluido un canal con un transceptor TCAN3403-Q1 integrado en la placa, proporcionan un punto de partida para adaptadores USB-a-CAN, sensores conectados y proyectos de control de robots. USB-C y carga de batería integrada admiten tanto el desarrollo de escritorio como aplicaciones portátiles.

Características​

  • El primer XIAO basado en STM32: Construido con el STM32C5A3CG, que incorpora un procesador Arm Cortex-M33 a 144MHz, soporte de coma flotante e instrucciones DSP para control embebido y procesamiento de sensores.
  • Conectividad CAN FD integrada: Dos controladores CAN FD nativos, con un canal conectado a un transceptor TCAN3403-Q1 integrado en la placa y pads accesibles CANH/CANL. Añade un transceptor externo para usar el segundo canal.
  • IMU de 6 ejes con calentamiento programable: El acelerómetro y giróscopo LSM6DS3TR-C integrado se combinan con resistencias de calentamiento dedicadas alrededor del sensor. El calentamiento controlado por GPIO permite un calentamiento programable y, con firmware de retroalimentación de temperatura, regulación de temperatura en lazo cerrado para ayudar a reducir la deriva relacionada con la temperatura en aplicaciones de robótica y detección de movimiento.
  • Flash externa de 16MB: Almacena datos de aplicación, registros de sensores, archivos de configuración y registros de mensajes CAN mediante el firmware de la aplicación.
  • Cristal externo para temporización de comunicaciones: Un cristal externo de alta velocidad integrado en la placa proporciona una referencia de reloj para CAN FD y otras aplicaciones sensibles a la temporización.
  • USB-C y carga de batería: Desarrolla a través de USB-C o construye dispositivos alimentados por batería utilizando el circuito de carga de baterías de litio integrado y los pads de conexión de batería.
  • Diseño compacto y fácil de integrar: El formato XIAO y los pads bordeados tipo castellated admiten prototipado en breadboard con pines y la integración en placas portadoras personalizadas.

Uso del bootloader​

El XIAO STM32C5 viene de fábrica con un bootloader compatible con UF2, destinado principalmente a actualizaciones de firmware. Antes de flashear un archivo .uf2, pulsa dos veces rápidamente el botón de Reset integrado. En tu PC se montará una unidad de almacenamiento masivo llamada XIAOC5BOOT. A continuación, puedes copiar el archivo de firmware a esta unidad para completar el flasheo.

Compilar y subir​

Paso 1. Escribir el programa de parpadeo del LED

El XIAO STM32C5 incorpora un LED de usuario asignado al GPIO PB12. El LED se enciende con un nivel lógico bajo; este ejemplo lo configura para parpadear cada 500 ms.

El proyecto consta de tres archivos principales:

  • main.c: Programa principal que contiene la lógica de la aplicación.
  • app.overlay: Archivo de superposición Devicetree para la configuración de periféricos de hardware.
  • prj.conf: Archivo de configuración del proyecto para habilitar los módulos necesarios de Zephyr.

Sigue los pasos a continuación para encender el LED:

  • Abre tu proyecto recién creado y crea el archivo devicetree app.overlay dentro de la carpeta zephyr.
/* USB CDC console and the user LED are configured by the board DTS. */
  • Crea el archivo de configuración prj.conf dentro de la carpeta zephyr.
# GPIO for LED control
CONFIG_GPIO=y
  • Copia el código de referencia que se muestra a continuación en main.c.
/*
 * Copyright (c) 2026 Seeed Technology Co., Ltd.
 * SPDX-License-Identifier: Apache-2.0
 *
 * Blinky example for XIAO STM32C5 with TinyUF2 bootloader support.
 * Based on Zephyr samples/basic/blinky.
 *
 * The 1200-bps UF2 bootloader trigger is armed automatically by the
 * board support package — no code changes needed in this example.
 */

#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>

#define SLEEP_TIME_MS 500

#define LED0_NODE DT_ALIAS(led0)

static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(LED0_NODE, gpios);

int main(void)
{
	int ret;
	bool led_state = true;

	if (!gpio_is_ready_dt(&led)) {
		return 0;
	}

	ret = gpio_pin_configure_dt(&led, GPIO_OUTPUT_ACTIVE);
	if (ret < 0) {
		return 0;
	}

	while (1) {
		ret = gpio_pin_toggle_dt(&led);
		if (ret < 0) {
			return 0;
		}

		led_state = !led_state;
		printk("LED state: %s\n", led_state ? "ON" : "OFF");
		k_msleep(SLEEP_TIME_MS);
	}

	return 0;
}

Uso de la batería​

En la parte posterior del XIAO STM32C5 se reserva un conector de batería BAT para la alimentación mediante una batería de ion‑litio de 3,7 V‑4,2 V.

Leer el voltaje de la batería​

El XIAO STM32C5 incorpora circuitería de detección de voltaje de batería y circuitería de carga de batería.

Dentro del circuito de detección, BAT_EN / PA15 habilita el chip TPS22916CNYFPR, mientras que BAT_Reading / PA4 lee el voltaje de la batería. Se utilizan dos resistencias divisoras de voltaje de 10 kΩ, por lo que el valor medido equivale a la mitad del voltaje real de la batería de ion‑litio.

El Charge_LED parpadea durante la carga de la batería y se apaga cuando la carga se completa.

  • Modifica el código de aplicación correspondiente.
app.overlay
/ {
	/* Expose the battery ADC input to the application. */
	zephyr,user {
		io-channels = <&adc1 4>;
	};
};

&adc1 {
	/* Add the battery input on PA4 (ADC1_IN4). */
	pinctrl-0 = <&adc1_in0_pa0 &adc1_in1_pa1 &adc1_in2_pa2
		     &adc1_in3_pa3 &adc1_in4_pa4>;

	channel@4 {
		reg = <4>;
		zephyr,gain = "ADC_GAIN_1";
		zephyr,reference = "ADC_REF_INTERNAL";
		zephyr,acquisition-time = <ADC_ACQ_TIME(ADC_ACQ_TIME_TICKS, 289)>;
		zephyr,resolution = <12>;
	};
};
prj.conf
# Battery voltage measurement. USB CDC console support is supplied by the board.
CONFIG_ADC=y
CONFIG_GPIO=y
main.c
/*
 * Copyright (c) 2026 Seeed Technology Co., Ltd.
 * SPDX-License-Identifier: Apache-2.0
 *
 * Read the XIAO STM32C5 battery voltage once per second.
 * printk() output uses USB CDC;
 * BAT_Reading/PA4 is added by app.overlay. BAT_EN/PA15 and USB CDC are
 * supplied by the board devicetree.
 */

#include <zephyr/device.h>
#include <zephyr/drivers/adc.h>
#include <zephyr/drivers/gpio.h>
#include <zephyr/kernel.h>
#include <zephyr/sys/printk.h>

#if !DT_NODE_EXISTS(DT_PATH(zephyr_user)) || \
	!DT_NODE_HAS_PROP(DT_PATH(zephyr_user), io_channels)
#error "No battery ADC io-channel specified"
#endif

#define BATTERY_ADC_NODE        DT_PATH(zephyr_user)
#define BAT_EN_NODE             DT_ALIAS(baten)
#define BATTERY_ENABLE_DELAY_MS 5
#define ADC_AVG_SAMPLES         16
#define SAMPLE_PERIOD_MS        1000

static const struct adc_dt_spec battery_adc =
	ADC_DT_SPEC_GET_BY_IDX(BATTERY_ADC_NODE, 0);
static const struct gpio_dt_spec bat_en =
	GPIO_DT_SPEC_GET(BAT_EN_NODE, gpios);

int main(void)
{
	uint16_t raw;
	struct adc_sequence sequence = {
		.buffer = &raw,
		.buffer_size = sizeof(raw),
	};
	int err;

	if (!device_is_ready(battery_adc.dev) || !gpio_is_ready_dt(&bat_en)) {
		printk("Battery ADC hardware is not ready\n");
		return 0;
	}

	err = gpio_pin_configure_dt(&bat_en, GPIO_OUTPUT_ACTIVE);
	if (err) {
		printk("BAT_EN configure failed: %d\n", err);
		return 0;
	}

	k_msleep(BATTERY_ENABLE_DELAY_MS);

	err = adc_channel_setup_dt(&battery_adc);
	if (err) {
		printk("Battery ADC channel setup failed: %d\n", err);
		return 0;
	}

	err = adc_sequence_init_dt(&battery_adc, &sequence);
	if (err) {
		printk("Battery ADC sequence init failed: %d\n", err);
		return 0;
	}

	printk("Battery voltage monitor (USB CDC)\n");

	while (1) {
		uint32_t raw_sum = 0;
		uint16_t raw_avg;
		int32_t adc_mv;

		/* Discard the first conversion after the one-second idle period. */
		err = adc_read(battery_adc.dev, &sequence);
		for (int i = 0; !err && i < ADC_AVG_SAMPLES; i++) {
			err = adc_read(battery_adc.dev, &sequence);
			raw_sum += raw;
		}

		if (!err) {
			raw_avg = raw_sum / ADC_AVG_SAMPLES;
			adc_mv = raw_avg;
			err = adc_raw_to_millivolts_dt(&battery_adc, &adc_mv);
			if (err) {
				printk("Battery voltage conversion failed: %d\n", err);
			} else {
				/* The 1:1 divider halves the battery voltage. */
				printk("Battery: %d mV\n", adc_mv * 2);
			}
		} else {
			printk("Battery ADC read failed: %d\n", err);
		}

		k_msleep(SAMPLE_PERIOD_MS);
	}

	return 0;
}

IMU​

El XIAO STM32C5 incorpora un LSM6DS3TR‑C sensor inercial de 6 ejes a bordo, que integra un acelerómetro de 3 ejes y un giroscopio de 3 ejes. Puede aplicarse a la detección de actitud, reconocimiento de movimiento, monitorización de vibraciones y otros casos de uso.

Para mitigar el impacto de la variación de la temperatura ambiente en el sesgo del sensor y la estabilidad de la medición, la placa implementa un circuito de calentamiento de compensación activa de temperatura. Las resistencias de calentamiento colocadas alrededor de la IMU proporcionan un calentamiento uniforme para el sensor, y la potencia de calentamiento puede ajustarse mediante señales PWM. Combinado con las lecturas internas de temperatura de la IMU, el control por software mantiene el sensor funcionando a una temperatura relativamente estable. Esto reduce la deriva de medición causada por la deriva de temperatura y mejora la consistencia de los datos durante el funcionamiento a largo plazo y en condiciones de temperatura variable.

  • Uso de referencia: Uso de la IMU del XIAO STM32C5

CAN FD​

El XIAO STM32C5 tiene dos controladores CAN FD. FDCAN1 expone pines TX y RX a nivel lógico y requiere un transceptor CAN externo para la conexión a un bus CAN. FDCAN2 está conectado al transceptor integrado TCAN3403-Q1 y se conecta al bus a través de las almohadillas CAN_H y CAN_L. La placa también puede intercambiar tramas CAN Clásico. Sin embargo, los nodos solo CAN Clásico no pueden decodificar tramas CAN FD, por lo que debes confirmar que los nodos activos en el bus admiten CAN FD antes de transmitir tráfico FD. CAN FD admite cargas útiles de hasta 64 bytes y, cuando la conmutación de velocidad de bits está habilitada, una velocidad de bits más alta durante la fase de datos.

La placa tiene una resistencia de terminación integrada de 120 Ω desconectable, habilitada por defecto. Mantenla habilitada cuando el XIAO esté en un extremo físico del bus CAN y ese extremo no tenga otro terminador. Desactívala cuando el XIAO sea un nodo intermedio o ya haya otro terminador instalado en el mismo extremo. Asegúrate de que el extremo opuesto del bus también esté correctamente terminado. El transceptor admite el modo de espera para reducir el consumo de energía cuando no se necesita comunicación CAN.
