EO-1: 汎用ロボット制御のためのオープンな統一身体性基盤モデル

  • ロボット制御
arXiv論文を読む↗

前提知識：入力と出力​

説明： 模倣学習は、人間の操作を記録したデータから動き方を学習します。VLA は言語理解を追加し、典型的には画像、タスク文、ロボット状態を入力として受け取ります。

「トマトを買い物袋に入れて」の場合、画像は物体の位置を特定し、状態はアームを記述し、テキストは目標を定義し、アクションは把持と配置を制御します。EO-1 は「次は何をするべきか？」「終わったか？」にも答えることができ、行動の前後の判断をつなぎます。

概念ここでの意味
観測マルチビュー画像とロボット状態。新しい画像はカメラから取得される。
状態関節などの低次元ロボット値。次元数はプラットフォームによって異なる。
アクションプラットフォームとデータセットに依存した物理的意味を持つ連続制御。
アクションチャンク複数の将来アクションをまとめて予測するもの。EO-1 は 16 ステップを使用。
身体性推論物体、空間、進捗、物理的相互作用に関する判断。

単一ステップ予測は current observation → aₜ、チャンク化は current observation → [aₜ, aₜ₊₁, …, aₜ₊₁₅] です。イラスト： ある 1 次元のアクションであれば [0.1, 0.12, 0.15] のようになり得ますが、実際の EO-1 は多次元の 16 ステップ配列を出力します。

アクションチャンクにより、モデルは動きの一部分をまとめて配置できますが、チャンク長はモデル呼び出し間隔ではありません。論文では、すべてのプラットフォームに共通する実行比率、再計画レート、制御レートは示されておらず、チャンク長から 1 秒あたりのモデル呼び出し回数を推定することはできません。

要約：翻訳とコメント​

翻訳​

人間は、オープンな世界において、マルチモーダルな推論と物理的な相互作用を自然に交互に行います。VLA はロボットと画像テキストの共同学習を通じて汎用的な制御を前進させてきましたが、推論と相互作用を結びつける柔軟性は依然として低いままです。

EO-Robotics は EO-1 と EO-Data1.5M から構成されます。EO-1 は、インタリーブされた視覚・テキスト・アクション事前学習を通じて、身体性推論と制御を学習します。画像、テキスト、動画、アクションを受け取るアーキテクチャと、インタリーブされた理解を重視した 150 万件超の高品質な身体性推論サンプルを組み合わせています。

EO-1 は EO-Data1.5M 上で、自己回帰デコーディングとフローマッチングによるノイズ除去を用いて学習され、ロボットアクション生成をマルチモーダルな身体性推論と結びつけます。複数のロボット形態および長期・巧緻なマニピュレーションタスクにわたる広範な実験により、オープンワールドの理解と汎化に対するインタリーブ学習の有効性が検証されます。本論文は、身体性基盤モデルの参考として、アーキテクチャ、データ構築、および学習手法を記述しています。

コメント​

  • 推論とアクションの結びつきが変化する。 画像と指示からアクションを生成するだけでなく、モデルは新しい画像を用いてアクション後に再評価することを学習します。

  • アーキテクチャとデータの両方が必要。 ネットワークはテキストと連続アクションを扱える必要があり、サンプルはそれらを時間的に結びつけていなければなりません。

  • 150 万超というのはデータセット全体を指す。 すべてのサンプルが完全なインタリーブアクションを含むわけではなく、テキストではインタリーブされた視覚・テキスト・アクション例は約 12.2 万件と別途報告されています。

  • 有効性は実験範囲に制約される。 複数プラットフォームでの結果は、人間レベルや任意シーンでの汎用性を示すものではありません。

中核手法：1 つのバックボーン、2 つの出力​

モダリティ固有インターフェースを持つ共有処理​

テキストは「何を」「なぜ」を扱い、アクションは動きを指定します。どちらも同じ物体、目標、進捗に依存しています。EO-1 は、計画と制御の分離を減らすために、事前学習済みバックボーンを共有します。

論文： Qwen2.5-VL から初期化されたデコーダ専用 Transformer は、画像・動画用の視覚エンコーダとテキスト用のトークナイザを保持します。状態とノイズ付きアクションは、共有特徴空間へ射影されます。

トークンは系列要素であり、必ずしも離散単語とは限りません。視覚、状態、アクションのトークンは連続特徴ベクトルであり得ます。

生入力エンコーディングバックボーン表現
マルチビュー画像と動画フレーム事前学習済み視覚エンコーダ幅 D の視覚系列。
指示と推論 QAトークナイザと埋め込み層幅 D のテキスト系列。

D はバックボーンの幅、d_q はプラットフォームの状態次元です。状態・アクション次元と完全なトークン数はプラットフォーム間で一様には指定されていないため、記号のままにしています。

出力は LM ヘッド（テキストトークンを予測）と フローヘッド（隠れ特徴を連続アクション更新に写像）に分岐します。最終チャンクは 16 × d_a であり、d_a はプラットフォーム固有のアクション次元です。

形状例： 仮に 7 次元インターフェースであれば、出力は 16 × 7、すなわち 112 個の値になります。これは普遍的な構成ではありません。射影により幅 D から d_a へ戻しますが、幅を直接足し合わせるわけではありません。

注意： 「アクション固有パラメータの追加なし」は、アクション専用の別バックボーンがない、という意味で読むべきです。状態・アクション射影や出力ヘッドには依然としてパラメータが含まれます。

テキストは逐次生成し、アクションはチャンクとしてノイズ除去​

自己回帰は、既存のコンテキストから次のテキストトークンを予測します：

w_j はトークン j、c_j はその前にあるマルチモーダルコンテキストです。例： 「next, pick up」の後に、モデルは「the tomato」を予測し、その際に過去の画像やアクション履歴も利用します。

アクションにはフローマッチングを用います。制御をテキストとして逐語的に綴るのではなく、ランダムな配列を完全な軌道へ近づける更新量を繰り返し予測します。

インタリーブされたシーケンス：行動後に再び推論する​

標準的な行動例は次のように書けます：

Image → Task text → State → Action chunk

EO-1 もこの時間構造を学習します：

Current image → Planning QA → State → Action chunk
→ New image → Completion QA → Next-step planning → Next chunk

論文: 各モダリティには境界マーカーがあり、画像には [BOI]/[EOI]、状態には [BOR]/[EOR]、行動には [BOA]/[EOA] が含まれます。因果的アテンションは将来の答えではなく、先行するコンテキストに条件付けされます。

例: トマトを袋に入れようとした後、新しい画像にトマトがまだグリッパにある様子が写っているかもしれません。モデルは配置が完了していないと判断し、さらに行動を生成できます。これはフィードバック構造を示すものであり、確実なリカバリを保証するものではありません。

EO-1 はテキストと行動を生成し、将来のカメラ画像や状態は生成しません。環境側が新しい観測を提供します。また、インタリーブはすべての制御点の前に必ず言語的な回答を要求するわけではありません。

インタリーブされた Rectifying Sampling：履歴はクリーン、現在の行動はノイズ付き​

現在の行動を学習するにはノイズが必要ですが、その後のテキストは完了した行動に条件付けされるべきです。過去の行動をノイズ付きのままにすると、実際に実行された履歴とのミスマッチが生じます。

論文: インタリーブされた rectifying sampling は、N 個の行動セグメントを持つシーケンスを、行動境界で N+1 個の学習用プレフィックスに分割します。履歴中の行動はクリーンであり、現在生成中の行動のみがノイズ付きです。

最小例: 2 つの行動を持つシーケンス：

Image₁ / Text₁ → Action₁ → Image₂ / Text₂ → Action₂ → Image₃ / Text₃

N=2 の場合、3 つのプレフィックスを構成します：

サンプルコンテキストとターゲット
Sample1Image₁ / Text₁ → ノイズ付き action₁；action₁ のノイズ除去を学習。
Sample2Image₁ / Text₁ → クリーンな action₁ → Image₂ / Text₂ → ノイズ付き action₂；後続テキストと action₂ を学習。
Sample3両方の行動がクリーンな履歴；最終テキスト text₃ を学習。

行動は生成されるときにノイズ除去の教師信号を受け、後続の予測に対してはクリーンなコンテキストとして勾配に寄与します。モデルは行動生成と、行動履歴に基づく推論の両方を学習します。

制約とコスト: プレフィックスを再処理することで計算量が増えますが、これは個別には測定されておらず、単独の除去アブレーションもありません。クリーンな学習履歴は記録から得られますが、デプロイ時の履歴にはモデルの誤りが含まれる可能性があります。Rectifying sampling はこのミスマッチを解消せず、ACT の時間的アンサンブルや行動スムージングでもありません。

学習と推論の全体像​

学習: 画像・テキストソース、ロボット記録、インタリーブされた例 → モダリティをエンコード → 現在の行動にノイズを加え、履歴はクリーンに保持 → 共有バックボーン → テキストのクロスエントロピー損失とフロー損失 → 共同更新。QA のみのサンプルは、作り物の行動を伴わないテキストの教師信号を提供します。

推論: 画像、指示、状態、履歴 → 必要なテキストを生成 → 新しいノイズを 10 回の更新で 16 ステップのチャンクに洗練 → 実行 → 新しい観測をコンテキストに追加。KV キャッシングはコンテキスト計算を再利用しますが、再観測の代わりにはなりません。

実装では、事前学習 5 エポック、平均パック長 16,384、バッチサイズ 1 が報告されています。言語／マルチモーダル射影の学習率は 5×10⁻⁵、ビジュアルエンコーダは 1×10⁻⁵ です。これらは実験上の設定であり、普遍的な最適値ではありません。

パイプライン：多様なシーンを保持し、その後に推論を追加​

論文: 視覚的な動画特徴をクラスタリングし、クラスタごとにサンプリングして、繰り返しシーンを減らすために手動で確認します。動画をサブタスクに分割し、モデルと人手で行動記述を作成し、テンプレートベースの質問を構築し、候補回答を生成し、それらを手動で選択または書き換え、最後にルールと文言をクリーンアップします。

時間的タスクには、物理的コモンセンス、プランニング、動画記述、アフォーダンス QA、検証、サブタスク QA、失敗検出が含まれます。空間的タスクには、関係性、軌跡予測、バウンディングボックス、ポインティング、マルチビュー・ポインティングが含まれます。

説明: 1 つの把持記録から、「何をつかむか」「どこにアプローチするか」「配置が成功したかどうか」に答えることができます。これらのアノテーションは、あらゆる可能な行動を探索した結果ではなく、デモンストレーションから得られたものです。

3 種類のインタリーブ形式はどのように QA と行動を結びつけるか​

形式接続学習の焦点
時間的推論画像 → 次のサブタスク QA → 答えを指示文に挿入 → 行動 → 新しい画像と検証。何をすべきか、完了しているかどうか。
空間的推論画像 → 軌跡 QA → 軌跡を指示文に挿入 → 行動 → 新しい画像と検証。空間的な目標を動きに変換する。
自由形式 QA画像 → その他の推論 QA → 元のタスク指示 → 行動 → 検証。制御コンテキスト内で多様な推論を保持する。

空間的軌跡は関節コマンドではなく、画像平面上の [x,y] 座標です。(480,125) → (485,144) は画像上の経路を表し、連続行動生成は依然として実際の動きを学習します。

実機ロボットでは何がテストされたか？​

28 のタスク設定には、7 つの Franka Panda ピック＆プレースタスク、13 の WidowX 250 S の「箱から出してすぐ」テスト、4 つの AgiBot G-1 長期ホライゾン巧緻タスク、4 つの推論・制御タスクが含まれます。SO100 も関与しています。

モデルは視点、状態、指示を受け取り、制御信号を出力します。付録 Table 6 の学習データ構成には、AgiBot の ego／左／右ビュー（30 FPS）、DROID の左／右／手首ビュー（15 FPS）、SO100 の第三者視点／手首ビュー（30 FPS）、IPEC-Franka の第三者視点／手首ビュー（10 FPS）が含まれます。これらのソース設定は、評価時のカメラ台数や制御レートの普遍的な値ではありません。

長期ホライゾンのファインチューニングでは、タスクごとに 150 デモを 25 エポック学習し、サブタスクとフルタスクのデータを 9:1 で混合し、その後タスクごとに 10 回評価します。スイートごとに約 50 万フレームと 8 ステップが報告されていますが、これはタスク時間の一様な長さを意味しません。

注意: 長期ホライゾンスコアは、サブタスク指示の下での完了率を平均したものであり、1 つの包括的な指示からのフルタスク自律成功率ではありません。また、「箱から出してすぐ（out of the box）」という表現も、そのエンボディメントが事前学習に一切含まれていなかったことを意味するわけではありません。

推論は行動を改善するか？​

EO-1 は三目並べ、画像参照に基づく並べ替え、サンドイッチ作り、ステーキ調理でそれぞれ 0.76, 0.79, 0.84, 0.55 を記録しています。三目並べのベースラインは π0 が 0.24、GR00T-N1.5 が 0.36 であり、この設定において盤面判断と配置の統合がより良いことを示唆します。

これらのタスクには、800 件の並べ替えデモと 450 件の三目並べサンプルという特化データとファインチューニングが用いられています。ベースラインは外部の GPT-4o プランナーとコントローラを組み合わせる一方で、EO-1 は統一されたデコーダを用います。結果は、個々のコンポーネント単体やゼロショットの新タスク学習ではなく、システム全体と学習手法の有効性を支持するものです。

汎化とデータの役割​

視覚・言語・行動の変動に対する達成スコアはそれぞれ 0.72, 0.79, 0.67 で、全体では 0.73 です。行動の変動は主に物体の位置、ロボットの視点、物体インスタンスを変えるものであり、任意の未知スキルを変えるものではありません。テキストと図中のタスク総数は一致していないため、Figure 9 の「18 Tasks」は論文全体の試行回数としては扱いません。

4 つの構成が比較されています：fast は完全自己回帰型の FAST 行動、base は制御データのみで学習された連続フロー・マッチング付きの共有バックボーン、llava は汎用の画像‐テキスト指示を追加したもの、interleaved は関連するインタリーブドデータを追加したものです。

表 5 から 2 つの重要な観察が得られます：

  • 連続生成は有効である： LIBERO の base は 98.2% に達し、fast は 88.0% です。これは、この設定においてハイブリッドデコーディングが有効であることを支持するものであり、離散行動が普遍的に劣っているという意味ではありません。

  • モダリティを増やすだけでなく、関連性が重要である： WidowX の全体達成率は base の 0.71 から interleaved の 0.80 に上昇する一方で、汎用データである llava は 0.34 にとどまります。タスクとの整合性が重要であり、Web データが常に有害というわけではありません。

利得には限界があります：AgiBot のサンドイッチにおける行動汎化スコアは、base と interleaved の両方で 0.75 のままです。インタリーブドラベルは、デモに存在しない動作の多様性を自動的に供給するわけではありません。

結論の解釈​

支持される結論： この設定において、インタリーブされたエンボディドデータを用いた共有バックボーンは、タスク関連の推論と連続制御を改善します。これは、行動の前の推論とその後の再評価のための、学習可能なインターフェースを提供します。

3 つの境界を保ちます：

  • 統合されていても、完全に信頼できるわけではない。 ステーキ調理のような複雑なタスクは依然として弱く、EO-Bench は完全からは程遠く、ナビゲーション、回避、失敗解析、協調といった課題は今後の研究対象として残っています。

  • 推論と動作は、任意に同時進行するわけではない。 効率的なアーキテクチャと非同期推論は、今後の課題として残っています。インタリービングは時間的依存関係を表現するものであり、人間のような思考と行動の同時性を意味するものではありません。

  • 再現には実装の詳細が必要である。 カウントやフローの符号には矛盾があり、状態／行動の次元や実行スケジュールは図から推測することはできません。RTX 4090 1 枚で推論時に約 6 GB のメモリを要すると報告されていますが、レイテンシや制御レートの包括的な測定はなく、どのプラットフォームでもリアルタイム実行が保証されているわけではありません。

説明： EO-1 は、意味的判断と制御を同時に学習するためのルートを提供します。共有ネットワークは結合情報を処理し、インタリーブドデータは時間的関係を与え、補正サンプリングは過去の行動と現在のノイズ除去とを区別します。実際の成果は依然として、デモのカバレッジ、タスク、および実行システムに依存します。
