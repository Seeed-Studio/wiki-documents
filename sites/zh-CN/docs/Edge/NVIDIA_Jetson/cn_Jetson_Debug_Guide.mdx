## 调试前提条件

### 硬件准备

- Seeed Jetson 开发板（正常供电）
- USB 数据线（根据载板型号选择 USB-C 或 Micro-B）/ 3.3V USB 转 UART 模块
- 主机电脑（任意 Windows / Linux / macOS）

### 推荐的软件工具

| 系统 | 推荐工具 |
|---|---|
| **Windows** | PuTTY / MobaXterm 等 |
| **Linux** | `screen` / `minicom` / `picocom` 等 |
| **macOS** | `screen` / `minicom` 等 |

:::note 系统说明
本文中的 Linux 命令基于 **Ubuntu 22.04 LTS** 测试，其他发行版可能需要调整包管理器（如 `dnf`、`pacman`）或路径配置。
:::

## UART 串口调试（核心）

UART 串口是 Jetson 调试的**底层入口**，可查看完整 Bootloader 与内核启动日志，解决黑屏、无法启动、串口被占用等核心问题。

:::danger 电压警告
所有 Seeed Jetson 调试口均为 **3.3V 电平**，**严禁使用 5V 模块**，否则会造成设备永久损坏！

板载 USB-C 调试口已集成电平转换，直接用 USB 数据线连接即可。
:::

### 各系列调试口连接方式

可以在 [reComputer 系列介绍](/cn/reComputer_Intro/) 页面，找到对应的设备型号，查看其调试口（Debug Port）位置，然后使用 USB 数据线将调试口连接到主机即可。

:::warning USB 数据线要求
必须使用**支持数据传输的 USB 数据线**，而非仅供电的充电线。部分廉价 USB-C 线仅供电不传数据，会导致设备管理器中无法识别串口。如果连接后主机无任何反应，请优先更换 USB 线缆。
:::

### USB 转串口芯片与驱动

Seeed Jetson 载板的调试口使用不同的 USB 转串口芯片，各芯片在不同操作系统上的驱动支持情况如下：

| 芯片型号 | USB VID | Windows | Linux | macOS |
|---|---|---|---|---|
| **Silicon Labs CP210x** | `10C4` | 需安装 [VCP 驱动](https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers) | 内核自带 | 需安装 VCP 驱动 |
| **WCH CH340/CH343** | `1A86` | 需安装 [WCH 驱动](https://www.wch.cn/downloads/CH343SER_EXE.html) | 内核自带 | 需安装 WCH 驱动 |
| **FTDI FT232** | `0403` | 需安装 [FTDI 驱动](https://ftdichip.com/drivers/vcp-drivers/) | 内核自带 | macOS 12+ 内置 |

:::tip 快速判断芯片型号
- **Windows**：设备管理器中查看 `Ports (COM & LPT)` 下的设备名称
- **Linux**：执行 `lsusb` 查看 `ID xxxx:xxxx` 字段
- **macOS**：系统信息 → USB → 查看 USB 设备树
:::

### 串口识别与连接（波特率：115200）

连接调试线后，在主机上识别对应的串口设备并建立连接：

<Tabs groupId="host-os">
<TabItem value="windows" label="Windows" default>

**识别端口**：按 `Win + R`，输入 `powershell`，回车打开终端，执行以下命令：

```powershell
Get-PnpDevice | Where-Object { $_.FriendlyName -match 'COM' } | Select-Object FriendlyName, Status | Format-Table -AutoSize
```

该命令通过 Windows 即插即用（PnP）接口检索所有名称中包含 `COM` 的设备，并显示其友好名称和连接状态。输出示例：

```text
FriendlyName                                  Status
------------                                  ------
Silicon Labs CP210x USB to UART Bridge (COM8) OK
```

其中 `Silicon Labs CP210x USB to UART Bridge (COM8)` 即为 Jetson 调试口对应的串口设备，端口号为 `COM8`。

:::tip 设备管理器替代方案
也可通过设备管理器（`Win + X` → 设备管理器）查看，展开 **Ports (COM & LPT)** 节点。但部分 USB 转串口设备在驱动未正确安装时不会出现在该节点下，可能显示在 **其他设备** 中并带有黄色感叹号，此时命令行方式更为可靠。
:::

**驱动安装（如设备未识别）**：

如果 PowerShell 输出中**没有 CP210x / Silicon Labs 字样**，说明驱动未安装。用以下命令按 USB VID 检索设备（不受驱动是否安装影响）：

```powershell
Get-PnpDevice | Where-Object { $_.InstanceId -match 'VID_10C4' } | Select-Object FriendlyName, Status | Format-List
```

如果 `Status` 显示为 `Error`，需下载并安装 Silicon Labs CP210x VCP 驱动：

```powershell
# 下载并解压 CP210x VCP 驱动
Invoke-WebRequest -Uri "https://www.silabs.com/documents/public/software/CP210x_VCP_Windows.zip" -OutFile "$env:TEMP\CP210x_VCP_Windows.zip" -UseBasicParsing
Expand-Archive -Path "$env:TEMP\CP210x_VCP_Windows.zip" -DestinationPath "$env:TEMP\CP210x_VCP_Windows" -Force

# 静默安装（会弹出 UAC 提示，点击「是」即可）
Start-Process -FilePath "$env:TEMP\CP210x_VCP_Windows\CP210x_VCP_Windows\CP210xVCPInstaller_x64.exe" -ArgumentList "/s" -Verb RunAs -Wait
```

安装后重新运行识别命令，确认 `Status` 变为 `OK`。

:::tip 其他芯片驱动
如果你的载板使用其他 USB 转串口芯片，请下载对应驱动：
- **CH343**（VID:1A86）：[CH343 驱动下载](https://www.wch.cn/downloads/CH343SER_EXE.html)
- **FT232**（VID:0403）：[FTDI VCP 驱动下载](https://ftdichip.com/drivers/vcp-drivers/)
:::

**串口连接（PuTTY）**：若未安装 PuTTY，先通过 winget 安装：

```powershell
winget install PuTTY.PuTTY
```

安装后重启终端，执行以下命令直接以串口模式启动 PuTTY：

```cmd
putty -serial COM8 -sercfg 115200
```

将 `COM8` 替换为实际识别到的端口号。连接后按一次回车即可看到登录提示。

**串口连接（MobaXterm GUI）**：

MobaXterm 是一款功能强大的 Windows 终端工具，支持串口连接，适合偏好图形界面的用户。下载地址：[https://mobaxterm.mobatek.net/download.html](https://mobaxterm.mobatek.net/download.html)

操作步骤：
1. 打开 MobaXterm，点击工具栏 **Session** 按钮
2. 选择 **Serial**（串口）
3. **Serial port** 选择 `COM8`（即前面识别到的端口）
4. 确认波特率为 `115200`，数据位 8，停止位 1，无校验
5. 点击 **OK** 建立连接

![MobaXterm 串口设置界面](https://files.seeedstudio.com/wiki/jetson_debug_guide/mobaxterm_serial_settings.png)

连接后按一次回车触发登录提示，输入用户名 `seeed`，密码 `seeed` 即可登录。

![MobaXterm 串口登录界面](https://files.seeedstudio.com/wiki/jetson_debug_guide/mobaxterm_serial_login.jpg)

:::tip MobaXterm 优势
MobaXterm 支持标签页管理、内置 SFTP 文件传输、可保存会话配置，适合反复调试场景。
:::

**识别端口**：

```bash
# 查看 USB 设备列表，找到对应的 UART Bridge 芯片
lsusb
```

输出示例（关键行）：

```text
Bus 003 Device 005: ID 10c4:ea60 Silicon Labs CP210x UART Bridge
```

```bash
# 查看内核识别到的串口设备节点
dmesg | grep -i ttyUSB
```

```text
[ 1234.567890] usb 3-1: cp210x converter now attached to ttyUSB0
```

```bash
# 确认设备节点存在
ls -l /dev/ttyUSB*
```

```text
crw-rw---- 1 root dialout 188, 0  7月 22 19:00 /dev/ttyUSB0
```

通常显示为 `/dev/ttyACM0` 或 `/dev/ttyUSB0`。

**串口连接（screen）**：

```bash
# 安装 screen（如未安装）
sudo apt install screen

# 连接串口
sudo screen /dev/ttyUSB0 115200

# 带日志记录的连接
sudo screen -L -Logfile /tmp/serial.log /dev/ttyUSB0 115200
```

退出 `screen` 快捷键：先按 `Ctrl+A`，然后按 `K`，确认 `y`。

**串口连接（picocom）**：

```bash
# 安装 picocom
sudo apt install picocom

# 连接串口
sudo picocom -b 115200 /dev/ttyUSB0

# 带日志记录的连接（记录所有输入输出到文件）
sudo picocom -b 115200 --logfile /tmp/serial.log /dev/ttyUSB0
```

退出 `picocom`：按 `Ctrl+A` 然后按 `Ctrl+X`。

**串口权限设置**：

Linux 系统下，串口设备默认属于 `dialout` 组，普通用户需要加入该组才能免 `sudo` 访问。

```bash
# 方法1: 将用户加入 dialout 组（永久生效，需重新登录或重启）
sudo usermod -aG dialout $USER

# 方法2: 每次使用 sudo 访问（临时）
sudo picocom -b 115200 /dev/ttyUSB0

# 方法3: 配置 udev 规则（推荐，免 sudo）
sudo bash -c 'echo "SUBSYSTEM==\"tty\", ATTRS{idVendor}==\"10c4\", MODE=\"0660\", GROUP=\"dialout\", TAG+=\"uaccess\"" > /etc/udev/rules.d/99-tegra-serial.rules'
sudo udevadm control --reload-rules && sudo udevadm trigger
```

:::tip idVendor 说明
上方 udev 规则中 `idVendor=="10c4"` 对应 Silicon Labs CP210x 芯片。若使用其他芯片（如 CH340 `1a86`、FTDI `0403`），需替换为对应的 VID。
:::

:::warning ModemManager 串口占用
Linux 主机上的 `ModemManager` 服务可能误占用 Jetson 调试串口，导致连接失败或无输出。如果连接后无响应，执行以下命令释放：

```bash
sudo systemctl stop ModemManager
sudo systemctl disable ModemManager
```
:::

<TabItem value="macos" label="macOS">

**识别端口**：

```bash
# 查看所有串口设备（cu.* 用于连接，tty.* 用于监控）
ls /dev/cu.* /dev/tty.*
```

输出示例：

```text
/dev/cu.SLAB_USBtoUART     /dev/tty.SLAB_USBtoUART
```

:::tip cu.* 与 tty.* 的区别
- `/dev/cu.*`（Call-Up）：用于从主机向外连接设备，**推荐使用**
- `/dev/tty.*`：用于呼叫进入（如调制解调器），会等待 DCD 信号
:::

也可通过 **系统信息**（`Cmd + Space` → "系统信息" → USB）查看已连接的 USB 设备。

**串口连接（screen）**：

macOS 自带 `screen` 命令，无需额外安装：

```bash
# 连接串口
screen /dev/cu.SLAB_USBtoUART 115200
```

退出 `screen` 快捷键：先按 `Ctrl+A`，然后按 `K`，确认 `y`。

**串口连接（minicom）**：

如需更多功能（如文件传输、配置保存），可安装 `minicom`：

```bash
# 通过 Homebrew 安装
brew install minicom

# 连接串口
minicom -D /dev/cu.SLAB_USBtoUART -b 115200

# 首次使用可进入配置界面
minicom -s
```

退出 `minicom`：按 `Ctrl+A` 然后按 `X`，选择 `Yes` 确认。

:::tip 驱动安装
部分 USB 转串口芯片在 macOS 上需要手动安装驱动：
- **Silicon Labs CP210x**：[VCP 驱动下载](https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers)
- **CH340/CH343**：[WCH 官方驱动下载](https://www.wch.cn/downloads/CH343SER_EXE.html)
- **FTDI FT232**：macOS 12+ 已内置驱动，通常无需额外安装
:::

:::warning macOS 权限问题
如果连接时提示 `Permission denied`，可能是 macOS 的 TCC（透明度、同意与控制）机制阻止了终端访问串口设备。解决方法：
1. 使用 `sudo` 运行：`sudo screen /dev/cu.SLAB_USBtoUART 115200`
2. 或在 **系统设置 → 隐私与安全性** 中允许终端访问串行端口
:::

### 非交互式批量执行命令

通过管道自动发送命令并记录输出，适合脚本化操作：

```bash
# 批量发送多条命令
echo "seeed" | sudo -S bash -c '
rm -f /tmp/serial.log
(sleep 0.5
printf "uname -a\n"; sleep 1
printf "cat /etc/nv_tegra_release\n"; sleep 1
printf "lsusb\n"; sleep 2
printf "free -h\n"; sleep 1
sleep 1
) | timeout 10 picocom -b 115200 --logfile /tmp/serial.log /dev/ttyUSB0 2>&1
cat /tmp/serial.log
' < /dev/null 2>&1
```

**参数说明**：
- `sleep 0.5`：等待 picocom 初始化
- `printf "cmd\n"`：发送命令（含换行符）
- `sleep N`：等待命令执行完成（复杂命令需更长时间）
- `timeout 10`：picocom 最大运行时间
- `--logfile`：记录所有串口输入输出
- `< /dev/null`：防止 sudo 密码干扰 bash stdin

## 系统启动与内核调试

通过 UART 串口，你可以完整捕获 Jetson 启动日志，用于定位启动卡死、内核崩溃等问题。

### 启动三阶段

```text
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│  Bootloader     │ →  │  Kernel Boot     │ →  │  System Init     │
│  CBoot/U-Boot   │    │  Linux Load Drivers│   │  systemd Service│
│  Serial Only    │    │  Core Debug Info  │    │  User Mode      │
└─────────────────┘    └──────────────────┘    └─────────────────┘
```

### 启用完整启动日志

默认情况下，`quiet` 参数会隐藏大量日志。你可以通过以下步骤将其开启：

1. 编辑启动配置文件：

```bash
sudo vim /boot/extlinux/extlinux.conf
```

2. 找到 `APPEND` 行，**删除** `quiet`，**添加** `ignore_loglevel`
3. 重启后，即可通过串口查看完整内核日志

启动配置文件示例（`extlinux.conf`）：

```text
TIMEOUT 30
DEFAULT primary

MENU TITLE L4T boot options

LABEL primary
      MENU LABEL primary kernel
      LINUX /boot/Image
      FDT /boot/dtb/tegra234-p3768-0000+p3767-0005-nv-super.dtb
      INITRD /boot/initrd
      OVERLAYS /boot/tegra234-p3767-camera-p3768-imx477-quad-seeed.dtbo
      APPEND ${cbootargs} root=PARTUUID=71ff5c5e-33ca-40de-a4ac-34e8fb444c56 rw rootwait rootfstype=ext4 mminit_loglevel=4 console=ttyTCU0,115200 firmware_class.path=/etc/firmware fbcon=map:0 nospectre_bhb video=efifb:off console=tty0
```

:::tip 远程场景
如果可以通过 SSH 连接，也可以直接查看内核日志：

```bash
dmesg --follow
journalctl -k -f
```

:::

### 内核日志查看

通过串口或 SSH 查看内核日志：

```bash
# 查看最近的内核日志
sudo dmesg | tail -30
```

输出示例：


## 刷机与恢复

当系统崩溃或无法启动时，可以使用官方工具重新刷机。详细刷机步骤请参考 **[Flashing Jetson Linux](/cn/flash/jetpack_to_selected_product)** 页面，其中涵盖 BSP 下载、环境准备、各设备专用刷机步骤及常见问题排查。

### 刷机调试日志

当刷机失败时，请务必收集两类日志用于排查：

1. **主机侧**：刷机终端的完整输出日志
2. **目标侧**：通过 UART 串口捕获的 Jetson 启动日志（核心排查依据）

:::tip 调试小贴士
- 刷机失败时，优先查看 UART 串口日志，通常可以直接暴露根因
- 常见问题包括：BSP 版本不匹配、USB 连接问题、主机环境配置等
- 如需协助，请收集完整日志并联系技术支持
:::

## 常见问题排查

<div className="card margin-bottom--lg" style={{borderLeft: '4px solid #f59e0b'}}>
  <div className="card__body">

| 问题 | 排查方向 |
|---|---|
| **串口连接失败** | 检查 USB 线缆、端口号、电压标准（3.3V） |
| **无启动日志** | 确认调试口连接正确；移除内核 `quiet` 启动参数 |
| **刷机失败** | 优先查看 UART 串口日志；确认载板型号与 JetPack 版本匹配 |
| **串口权限不足** | Linux: 将用户加入 `dialout` 组；`sudo usermod -aG dialout $USER` |
| **串口被 ModemManager 占用** | `sudo systemctl stop ModemManager`；或永久禁用 |
| **设备无法进入恢复模式** | 检查跳线/按键是否正确；尝试更换 USB 线或端口 |

  </div>
</div>
