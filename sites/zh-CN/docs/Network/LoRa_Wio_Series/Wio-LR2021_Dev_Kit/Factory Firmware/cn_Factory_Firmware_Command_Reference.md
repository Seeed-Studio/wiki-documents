## 符号约定

| 符号 | 含义 | 示例 |
| --- | --- | --- |
| `[ ]` | 可选参数；省略时使用默认值 | `[-p <port>]` |
| `< >` | 需要你提供的具体值 | `-g <gpio>` |
| `\|` | 在列出的值中选择一个 | `<0\|1>` |
| 无括号的单词 | 必选 | `ping <host>` |
| `cmd>` | 固件提示符；不要输入它 | `cmd> help` |

数值始终写成 `-flag value` 的形式，例如 `gpio_set -g 4 -l 1`。如果固件同时注册了长格式参数，则会在参数表中列在短格式旁边。

## LoRa / 射频 {#lora-rf}

这七条命令通过两种调制方式驱动板载 LR2021 收发器：LoRa 侧重距离，FLRC 侧重速度。每一条发射命令都需要在匹配的连接器上接好天线：Sub-GHz 载波频率使用 `SUB-1G`，2400 ~ 2500 MHz 频段使用 `LR-2.4G`。两板互联测试时，两端的射频参数必须完全一致。

**注意**：`lora_rx`、`flrc_rx`、`lora_tx -n 0` 和 `flrc_tx -c 0` 会一直运行，直到你按下 `Ctrl+C`。

### 1. lora_tx

**`lora_tx [-f <freq_hz>] [-s <5-12>] [-b <0-9>] [-c <1-7>] [-p <dbm>] [--crc <0|1>] [--hdr <0|1>] [--iq <0|1>] [--net <0|1>] [-i <interval_ms>] [-d <text>] [-n <count>] [-hp <n>] [-dc <n>] [-lf <n>]`**

按配置的频率、扩频因子和功率发送 LoRa 数据包。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-f <freq_hz>` | 发射频率 | `150000000 ~ 2500000000` Hz；默认：`868000000` |
| `-s <5-12>` | 扩频因子 | `5 ~ 12`；数值越高速率越慢、覆盖越远；默认：`7` |
| `-b <0-9>` | 带宽索引 | `0`=31k，`1`=41k，`2`=62k，`3`=125k（默认），`4`=200k，`5`=250k，`6`=400k，`7`=500k，`8`=800k，`9`=1000k |
| `-c <1-7>` | 编码率 | `1 ~ 7`；`1`=4/5 最快，`4`=4/8 最稳健；默认：`1` |
| `-p <dbm>` | 发射功率 | Sub-GHz `-10 ~ +22` dBm，2.4 GHz `-17 ~ +12` dBm；默认：`10` |
| `--crc <0\|1>` | CRC 校验 | `0`=关闭，`1`=开启；默认：`1` |
| `--hdr <0\|1>` | 头部类型 | `0`=隐式，`1`=显式；默认：`1` |
| `--iq <0\|1>` | IQ 模式 | `0`=标准，`1`=反转；默认：`0` |
| `--net <0\|1>` | 网络类型和同步字 | `0`=私有（同步字 `0x12`），`1`=公共（同步字 `0x34`）；默认：`1` |
| `-i <interval_ms>` | 数据包间隔 | 毫秒；默认：`200`；`0`=背靠背发送 |
| `-d <text>` | 负载文本 | 默认：`hello` |
| `-n <count>` | 数据包数量 | `0`=一直发送直到 `Ctrl+C`；默认：`10` |
| `-hp <n>` | PA 半功率寄存器 | 仅调试用；正常使用时保持未设置 |
| `-dc <n>` | PA 占空比寄存器 | 仅调试用；正常使用时保持未设置 |
| `-lf <n>` | PA 低频 slice 寄存器 | 仅调试用；正常使用时保持未设置 |

**示例：**

```bash
lora_tx -f 868000000 -s 7 -b 3 -p 14 -d hello -n 10
```

:::note
先装好天线，然后在第二块板上用相同的 `-f`、`-s`、`-b`、`-c`、`--hdr`、`--crc`、`--iq` 和 `--net` 参数启动 `lora_rx`。超出范围的数值会打印 `out of bounds` 警告并回退：`-f` 回退到默认频率，`-s` 回退到 `7`，`-b` 回退到 `3`，`-c` 回退到 `1`；`-p` 会被钳制在频段限制内。非数字的 `-f`，或负数的 `-i` 或 `-n` 会中止命令且不发送任何数据。
:::

### 2. lora_rx

**`lora_rx [-f <freq_hz>] [-s <5-12>] [-b <0-9>] [-c <1-7>] [--crc <0|1>] [--hdr <0|1>] [--plen <0-255>] [--iq <0|1>] [--net <0|1>]`**

持续接收 LoRa 数据包并对其计数。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-f <freq_hz>` | 接收频率 | `150000000 ~ 2500000000` Hz；默认：`868000000` |
| `-s <5-12>` | 扩频因子 | `5 ~ 12`；默认：`7` |
| `-b <0-9>` | 带宽索引 | `0`=31k，`3`=125k（默认），`9`=1000k |
| `-c <1-7>` | 编码率 | `1 ~ 7`；默认：`1` |
| `--crc <0\|1>` | CRC 校验 | `0`=关闭，`1`=开启；默认：`1` |
| `--hdr <0\|1>` | 头部类型 | `0`=隐式，`1`=显式；默认：`1` |
| `--plen <0-255>` | 接收端期望的负载长度 | 字节；显式模式下 `0`=任意长度，隐式模式在省略时假定为 `5`；默认：`0` |
| `--iq <0\|1>` | IQ 模式 | `0`=标准，`1`=反转；默认：`0` |
| `--net <0\|1>` | 网络类型和同步字 | `0`=私有（`0x12`），`1`=公共（`0x34`）；默认：`1` |

**示例：**

```bash
lora_rx -f 868000000 -s 7 -b 3
```

:::note
该命令会阻塞控制台直到按下 `Ctrl+C`，此时会打印 `rx_done`、`rx_hdr_err` 和 `rx_crc_err`。两块板必须使用相同的 `--hdr` 值；一端隐式、一端显式将永远收不到。隐式模式下请将 `--plen` 设为发射端的负载长度：值更大会在尾部附加垃圾数据，更小则会截断。测试中发现隐式模式配合 `--crc 1` 会产生 CRC 失败，因此请将 `--hdr 0` 与 `--crc 0` 搭配使用。近距离时若长时间出现 `hdr err`，说明数据包背靠背到达；将发射端的 `-i` 提高到 `100` ~ `200`，并保持其长于单个数据包的空中时间。
:::

### 3. lora_cw

**`lora_cw [-f <freq_hz>] [-p <dbm>]`**

发射未调制的连续波，用于射频功率测量。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-f <freq_hz>` | 载波频率 | `150000000 ~ 2500000000` Hz；默认：`868000000`；超出范围或非数字值会中止命令 |
| `-p <dbm>` | 发射功率 | Sub-GHz `-10 ~ +22` dBm，2.4 GHz `-17 ~ +12` dBm；默认：`10`；会被钳制在频段限制内 |

**示例：**

```bash
lora_cw -f 868000000 -p 10
```

:::note
载波会一直保持，直到输入 `lora_cw_stop`。若要在测试过程中改变功率或频率，请使用新参数再次运行 `lora_cw`；配置会自动重新启动。
:::

### 4. lora_cw_pa

**`lora_cw_pa [-f <freq_hz>] [-p <dbm>] [-h <n>] [-d <0-31>] [-l <0-15>]`**

发射连续波，并直接控制 PA 寄存器。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-f <freq_hz>` | 载波频率 | `150000000 ~ 2500000000` Hz；默认：`868000000` |
| `-p <dbm>` | 发射功率 | Sub-GHz `-10 ~ +22` dBm，2.4 GHz `-17 ~ +12` dBm；默认：`10` |
| `-h <n>` | PA 半功率值 | 0.5 dB 步进；Sub-GHz `-19 ~ 44`，2.4 GHz `-39 ~ 24` |
| `-d <0-31>` | PA 占空比 | `0 ~ 31` |
| `-l <0-15>` | PA 低频 slice 数 | `0 ~ 15` |

**示例：**

```bash
lora_cw_pa -f 868000000 -h 22 -d 0 -l 0
```

:::note
只要提供了 `-h`、`-d` 或 `-l` 中任意一个参数，命令就会切换到直接参数模式并覆盖功率表。超出范围的数值会被钳制在频段限制内，并打印 `out of bounds` 警告。使用 `lora_cw_stop` 停止载波。
:::

### 5. lora_cw_stop

**`lora_cw_stop`**

停止由 `lora_cw` 或 `lora_cw_pa` 启动的连续波。

此命令不带任何参数。

**示例：**

```bash
lora_cw_stop
```

### 6. flrc_tx

**`flrc_tx [-f <freq_hz>] [-p <dbm>] [-b <0-7>] [-l <1-255>] [-c <count>]`**

以递增负载发送 FLRC 数据包，每秒发送一个数据包。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-f <freq_hz>` | 发射频率 | `415000000 ~ 940000000` Hz；默认：`915000000`；超出范围会回退到默认值 |
| `-p <dbm>` | 发射功率 | `-10 ~ +22` dBm；默认：`22`；会被钳制在限制范围内 |
| `-b <0-7>` | 速率与带宽组合 | `0`=2.6 Mbps（最快）到 `7`=0.26 Mbps；默认：`0`；超出范围会回退到 `7` |
| `-l <1-255>` | 数据包长度 | 字节；默认：`200`；超出范围会回退到默认值 |
| `-c <count>` | 数据包数量 | 默认：`100`；`0`=一直发送直到 `Ctrl+C`；大于 `500` 的值会被限制为 `500` |

**示例：**

```bash
flrc_tx -f 868000000 -p 14 -l 200 -c 100
```

:::note
每秒发出一个数据包，因此一分钟大约发送六十个数据包。将 `-c 0` 设为无限发送，直到 `Ctrl+C`。
:::

### 7. flrc_rx

**`flrc_rx [-f <freq_hz>] [-b <0-7>]`**

接收 FLRC 数据包，并统计有效包、头部错误和 CRC 错误数量。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-f <freq_hz>` | 接收频率 | `415000000 ~ 940000000` Hz；默认：`915000000`；超出范围会回退到默认值 |
| `-b <0-7>` | 速率与带宽组合 | `0 ~ 7`；默认：`0`；超出范围会回退到 `7` |

**示例：**

```bash
flrc_rx -f 868000000 -b 0
```

:::note
按下 `Ctrl+C` 会停止接收器并打印计数器。
:::

## BLE {#ble}

蓝牙在上电时不会启动。第一次执行 `ble -a 1` 会初始化 BLE 协议栈并开始广播；`ble -a 0` 会停止广播并卸载协议栈以释放其内存。设备名以 `wio-lr2021-` 开头，广播允许连接。

### 1. ble

**`ble -a <0|1>`**

打开或关闭蓝牙广播。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-a <0\|1>` | 广播开关 | `1`=开始广播（首次使用时初始化协议栈），`0`=停止广播并释放协议栈；必选 |

**示例：**

```bash
ble -a 1
```

:::note
在带有 nRF Connect 的手机上搜索 `wio-lr2021-`；当设备出现在列表中时，说明其状态正常。连接后，应用可以向设备发送命令，并读取其打印的日志行。
:::

### 2. ble_status

**`ble_status`**

打印设备名称、MAC 地址、发射功率、广播参数和连接状态。

此命令不带参数。

**示例：**

```bash
ble_status
```

:::note
如果蓝牙尚未初始化，该命令会提示你先运行 `ble -a 1`。
:::

## Wi-Fi 与网络 {#wifi-network}

Wi-Fi 会在启动时自动初始化并启动，因此这些命令都不需要手动执行 `wifi init`。它们大多封装了 Espressif 的 Wi-Fi 测试组件，并带有许多选项；下面的参数表列出了已文档化的选项。连接路由器需要你自备 2.4 GHz 接入点及其密码。

### 1. wifi

**`wifi <status|stop|start|restart|init|deinit>`**

查询 Wi-Fi 状态，或启动、停止并重新初始化射频。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `status` | 显示初始化状态和连接信息 | 最常用的查询 |
| `stop, start` | 停止或启动射频，驱动保留 | 功耗测试和干扰排除 |
| `restart` | 完整重启：stop、deinit、init、start | 在 `deinit` 之后恢复 |
| `init, deinit` | 初始化或卸载驱动 | 仅用于研发调试 |

**示例：**

```bash
wifi status
```

:::note
在已初始化的系统上运行 `wifi init` 会被跳过，只打印一条 `WiFi already initialise.` 警告。`wifi deinit` 在射频仍在运行时会先停止它，而 `wifi status` 会分别打印 `initialized` 和 `started`。
:::

### 2. wifi_count

**`wifi_count [query|clear]`**

打印或重置 Wi-Fi 发送和接收的数据包计数器。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `query` | 打印计数器 | 未给参数时的默认行为 |
| `clear` | 将两个计数器都重置为零 | — |

**示例：**

```bash
wifi_count
```

### 3. wifi_mode

**`wifi_mode <sta|ap|apsta>`**

设置设备的 Wi-Fi 角色。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `sta` | 连接到其他热点，例如手机 | — |
| `ap` | 作为热点工作 | — |
| `apsta` | 同时扮演两种角色 | — |

**示例：**

```bash
wifi_mode sta
```

### 4. wifi_protocol

**`wifi_protocol [protocol] [-i <ap|sta>]`**

查询或设置 802.11 协议组合。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `<protocol>` | 协议组合 | `b`、`b/g`、`b/g/n`；默认：查询当前值 |
| `-i <ap\|sta>` | 应用该设置的接口 | `ap` 或 `sta`；默认：`sta` |

**示例：**

```bash
wifi_protocol b/g/n
```

### 5. wifi_bandwidth

**`wifi_bandwidth [20|40] [-i <ap|sta>]`**

查询或设置信道带宽。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `<20\|40>` | 以 MHz 为单位的信道带宽 | `20` 或 `40`；默认：查询当前值 |
| `-i <ap\|sta>` | 应用该设置的接口 | `ap` 或 `sta`；默认：`sta` |

**示例：**

```bash
wifi_bandwidth 20
```

### 6. wifi_ps

**`wifi_ps <0|1|2>`**

设置 Wi-Fi 省电等级。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `0` | 不省电，性能最高 | 必需 |
| `1` | 中等省电 | — |
| `2` | 最大省电 | — |

**示例：**

```bash
wifi_ps 0
```

### 7. wifi_country

**`wifi_country [code] [-s <start_channel>] [-n <channel_count>] [-p <auto|manual>]`**

查询或设置国家代码和可用信道范围。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `<code>` | 两字母国家代码 | 例如 `US`；默认：查询当前值 |
| `-s <start_channel>` | 允许范围的首个信道 | 信道号；默认：未设置 |
| `-n <channel_count>` | 范围内的信道数量 | 数量；默认：未设置 |
| `-p <auto\|manual>` | 信道规划选择方式 | `auto` 或 `manual`；默认：未设置 |

**示例：**

```bash
wifi_country US
```

### 8. ap_set

**`ap_set <ssid> [pass] [-a <authmode>] [-n <channel>] [-m <max_conn>]`**

将设备变成一个 Wi-Fi 热点，以便手机或电脑可以连接。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `<ssid>` | 热点名称 | 必需 |
| `<pass>` | 热点密码 | 至少 8 个字符；可选 |
| `-a <authmode>` | 安全模式 | `open`、`wep`、`wpa2`；无法识别的名称会被报告，热点会回退到 `open`；默认：未设置 |
| `-n <channel>` | 热点信道 | 信道号；默认：未设置 |
| `-m <max_conn>` | 最大同时客户端数量 | 默认：`2` |

**示例：**

```bash
ap_set MyTestAP 12345678
```

**别名**：`ap`（与 `ap_set` 相同）。

:::note
在共享网络上长时间开启热点前请先修改密码，并在测试结束后关闭热点。
:::

### 9. ap_query

**`ap_query`**

显示当前热点配置以及已连接的客户端数量。

此命令不带参数。

**示例：**

```bash
ap_query
```

### 10. sta_connect

**`sta_connect <ssid> <pass> [-n <channel>]`**

以 station 身份加入你提供的 Wi-Fi 热点。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `<ssid>` | 热点名称 | 必需 |
| `<pass>` | 热点密码 | 必需 |
| `-n <channel>` | 要加入的信道 | 可选；已知信道可以加快连接速度 |

**示例：**

```bash
sta_connect MyHomeWiFi 12345678
```

**预期输出：**

```bash
got ip:192.168.<x>.<y>
```

IP 地址会随网络而变化；成功的判据是日志中出现 `got ip:` 这一行，它会出现在连接日志行中。

**别名**：`sta`（与 `sta_connect` 相同）。

:::note


**别名**：`disconnect`（与 `sta_disconnect` 相同）。

## IO 扩展器 {#io-expander}

GPIO 编号是 ESP32-S3 的 GPIO 编号；引脚功能列在 [Wio-LR2021 Dev Kit Pin Map](/cn/wio_lr2021_dev_kit_getting_started) 中。IO 扩展器是 I²C 地址为 `0x21` 的 PCA9535。它提供 16 个引脚，编号 0 ~ 15；其中有 4 个用于控制相机、音频、OLED 和 Grove 供电轨。

:::note
在上电后，没有被任何外设占用的引脚会保持为悬空输入（上拉/下拉电阻关闭），因此直接 `gpio_get` 会读到噪声。先运行 `gpio_config`：`-m 0` 表示输入（可选上拉/下拉），`-m 1` 表示推挽输出，`-m 2` 表示开漏输出。
:::

### 1. gpio_set

**`gpio_set -g <gpio> -l <0|1>`**

将某个 GPIO 驱动为高电平或低电平。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-g <gpio>` | GPIO 编号 | 必需 |
| `-l <0\|1>` | 输出电平 | `1`=高电平（约 3.3 V），`0`=低电平（0 V）；必需 |

**示例：**

```bash
gpio_set -g 4 -l 1
```

:::note
在驱动引脚之前，先用 `gpio_config -m 1` 配置方向，并使用万用表或回环线接到另一个 GPIO 来验证电平。
:::

### 2. gpio_get

**`gpio_get -g <gpio>`**

读取某个 GPIO 当前的电平。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-g <gpio>` | GPIO 编号 | 必需 |

**示例：**

```bash
gpio_get -g 4
```

### 3. gpio_config

**`gpio_config -g <gpio> -m <0|1|2> [-p <0|1|2|3>]`**

设置某个 GPIO 的方向和上下拉电阻。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-g <gpio>` | GPIO 编号 | 必需 |
| `-m <0\|1\|2>` | 方向 | `0`=输入，`1`=输出，`2`=开漏输出；必需 |
| `-p <0\|1\|2\|3>` | 上下拉电阻 | `0`=悬空（默认），`1`=上拉，`2`=下拉，`3`=上下拉都启用 |

**示例：**

```bash
gpio_config -g 5 -m 0 -p 1
```

### 4. i2c_scan

**`i2c_scan [-b <0|1>]`**

扫描一个或两个 I²C 总线并列出有响应的地址。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-b <0\|1>` | 要扫描的总线编号 | `0` 或 `1`；默认：扫描两条总线 |

**示例：**

```bash
i2c_scan -b 0
```

:::note
在一块健康的板子上，总线 0 会显示地址为 `0x21` 的 PCA9535，并且在显示供电轨打开后，会显示地址为 `0x3D` 的 OLED。缺失的地址意味着芯片未焊接、未上电或未响应。
:::

### 5. io_exp_set

**`io_exp_set -i <0-15> -l <0|1>`**

将 IO 扩展器的一个引脚驱动为高电平或低电平。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-i <0-15>` | 扩展器引脚编号 | `0 ~ 15`；必选 |
| `-l <0\|1>` | 输出电平 | `1`=高电平，`0`=低电平；必选 |

**示例：**

```bash
io_exp_set -i 3 -l 1
```

:::note
引脚 `0 ~ 3` 用于切换外设电源轨；驱动它们会改变摄像头、音频、OLED 和 Grove 接口的电源状态。
:::

### 6. io_exp_get

**`io_exp_get -i <0-15>`**

读取 IO 扩展器的一个引脚。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-i <0-15>` | 扩展器引脚编号 | `0 ~ 15`；必选 |

**示例：**

```bash

```

### 7. io_exp_config

**`io_exp_config -i <0-15> -m <0|1>`**

将 IO 扩展器的一个引脚设置为输入或输出。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-i <0-15>` | 扩展器引脚编号 | `0 ~ 15`；必选 |

**示例：**


### 8. io_exp_print

**`io_exp_print`**

此命令不带任何参数。

**示例：**

```bash
io_exp_print
```

## 摄像头 {#camera}

摄像头是 Media HAT 上的 2 MP GC2145；工厂固件以 RGB565 读取并以 JPEG 帧进行流式传输。`camera_http_start` 是最短的端到端检查，因为它通过一个命令就启动热点、摄像头和 Web 服务器。

### 1. camera_start

**`camera_start [-q <1-100>] [-r <qqvga|qvga|vga>] [-F <hz>]`**

给摄像头上电并初始化。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-q <1-100>` | JPEG 压缩质量 | `1 ~ 100`；默认：`80` |
| `-r <qqvga\|qvga\|vga>` | 采集分辨率 | `qqvga`=160×120，`qvga`=320×240（默认），`vga`=640×480 |
| `-F <hz>` | 摄像头控制总线（I²C）时钟 | Hz；默认：`100000` |

**示例：**

```bash
camera_start -r vga
```

:::note
再次运行 `camera_start` 并使用不同的 `-r` 或 `-F` 会重启摄像头并切换设置。启动后的前几帧会作为预热被丢弃。该命令也是确认摄像头是否成功初始化的最快方式。
:::

### 2. camera_stop

**`camera_stop`**

停止摄像头并关闭电源。

此命令不带任何参数。

**示例：**


### 3. camera_http_start

**`camera_http_start [-s <ssid>] [-p <pwd>] [-c <1-13>] [-q <1-100>] [-f <1-30>] [-P <port>] [-r <qqvga|qvga|vga>] [-F <hz>]`**

通过一个命令启动热点、摄像头和 MJPEG Web 预览。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-s <ssid>` | 热点名称 | 默认：`wio-lr2021-camera` |
| `-p <pwd>` | 热点密码 | 8 ~ 63 个字符，留空则为开放网络；默认：`12345678` |
| `-c <1-13>` | 热点信道 | `1 ~ 13`；默认：`1` |
| `-q <1-100>` | JPEG 质量 | 越高越清晰，占用带宽越多；默认：`80` |
| `-f <1-30>` | 帧率上限 | 每秒帧数；默认：`20` |

**用法**：使用密码 `12345678` 加入热点 `wio-lr2021-camera`，然后在浏览器中打开 `http://192.168.4.1`。若能看到实时图像，则说明摄像头和 Wi-Fi 通路都工作正常。

网页没有身份验证。请不要将热点接入任何共享或办公网络，并使用 `camera_http_stop` 将其关闭。
:::

**`camera_http_stop`**

停止 Web 服务器并关闭摄像头和热点。

**示例：**

## 音频 {#audio}

音频槽是 RAM 中的录音缓冲区，因此不需要 SD 卡：先录制到槽中，然后回放，或通过设备热点将其流式传输到 PC。

### 1. audio_init

**`audio_init`**

给音频电路上电并初始化编解码器和麦克风。

此命令不带任何参数。

**示例：**

```bash
audio_init
```

:::note
固件在启动时会运行一次该命令；可在 `audio_deinit` 之后用它进行恢复。
:::

### 2. audio_deinit

**`audio_deinit`**

关闭音频电路电源。

此命令不带任何参数。

**示例：**

```bash
audio_deinit
```

:::note
在 `audio_init` 再次运行之前，录音和回放都不可用。可用于功耗测试。如果自启动以来从未初始化过音频，则该命令会被拒绝，因此连续第二次运行 `audio_deinit` 不会产生任何效果。
:::

### 3. audio_slot_record

**`audio_slot_record [-d <100-60000>] [-m <20.0-37.5>]`**

从麦克风录音到音频槽中。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-d <100-60000>` | 录音时长 | 毫秒；`100 ~ 60000`；默认：`10000` |
| `-m <20.0-37.5>` | 麦克风增益 | dB；`20.0 ~ 37.5`；默认：`37.5`（最大值） |

**示例：**

```bash
audio_slot_record -d 5000 -m 30
```

:::note
该槽保存的是未经任何软件处理的原始麦克风数据。录音时请靠近麦克风说话。音频在启动时已初始化；在 `audio_deinit` 之后，请先运行 `audio_init`，否则命令会被拒绝。
:::

### 4. audio_slot_play

**`audio_slot_play [-v <0-100>]`**

通过扬声器播放已录制的槽内容。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-v <0-100>` | 回放音量 | `0 ~ 100`；默认：保持当前音量 |

**示例：**

```bash
audio_slot_play -v 80
```

:::note
将扬声器连接到 Media HAT 上的 `SPK` 接口。该命令会播放槽当前保存的内容，因此请先录音；当音频未初始化或槽为空时，命令会被拒绝。
:::

### 5. audio_slot_send

**`audio_slot_send [-p <port>]`**

通过设备热点将槽内容以 WAV 文件形式流式传输到 PC。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-p <port>` | PC 连接的 TCP 端口 | 默认：`3444` |

**示例：**

```bash
audio_slot_send
```

**用法**：在 PC 上连接热点 `wio-lr2021-audio`（密码 `12345678`），然后运行 `python tools/recv_wav_from_device.py -o slot.wav`。脚本会连接到 `192.168.4.1:3444`，读取 8 字节的头部（`AUDF` magic 加上音频长度），然后读取音频字节；文件一写完即可播放。

:::note
命令会立即返回，传输在后台进行。传输结束后热点不会关闭，因此可以连续发送多段录音；使用 `audio_slot_stop` 将其关闭。
:::

### 6. audio_slot_stop

**`audio_slot_stop`**

停止任何正在进行的传输并关闭音频热点。

此命令不带任何参数。

**示例：**

```bash
audio_slot_stop
```

:::note

:::

### 7. audio_slot_info

**`audio_slot_info`**

**示例：**

```bash
audio_slot_info
```

## Flash {#flash}

Flash 的耐久性和速度测试仅在专用的 `flashtest` 分区内工作，因此固件镜像和用户数据不会被触及。`flash_endurance` 作为后台任务运行，在持续写入的同时控制台仍可使用。

### 1. flash_info

**`flash_info`**

读取 Flash JEDEC ID、厂商和容量，并验证测试分区的起始和结束位置。

此命令不带任何参数。

**示例：**

```bash
flash_info
```

:::note
返回码 `0` 表示通过；边界写入检查可以捕获容量被夸大的闪存芯片。
:::

### 2. flash_endurance

**`flash_endurance -a <start|stop|status> [-m <minutes>] [-s <sectors>] [-d <ms>]`**

在闪存测试分区中运行擦除、写入和回读的浸泡测试。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-a <start\|stop\|status>` | 操作 | `start`、`stop` 或 `status`；必填 |
| `-m <minutes>` | 运行时长 | 分钟；`0` 表示一直运行直到停止；默认：`1440` |
| `-s <sectors>` | 每轮写入的扇区数 | `0`=整个测试分区；默认：`0` |
| `-d <ms>` | 扇区之间的延迟 | 毫秒；`0`=全速；默认：`0` |

**示例：**

```bash

```

:::note
该命令会立即返回，浸泡测试在后台运行；使用 `-a status` 检查进度，并用 `-a stop` 结束测试。每一轮都会磨损闪存，因此应在样品上运行，而不是在每一块板子上都运行。
:::

### 3. flash_speed

**`flash_speed [-t <kb>]`**

测量页编程时间、扇区擦除时间以及读/写吞吐量。

| 项目 | 描述 | 数据 |
| --- | --- | --- |
| `-t <kb>` | 吞吐量测试使用的数据量 | KB；默认：`64` |


:::note
返回码 `0` 表示每一项测量都在数据手册限制范围内。
:::

| `wifi_scan` | `sta_scan` | 功能相同；优先使用主命令名称。 |
| `scan` | `sta_scan` | 功能相同；优先使用主命令名称。 |

## 结果字符串与返回码

固件会在串口上以纯文本行的形式报告结果，然后返回到 `cmd>` 提示符。下面这些标记是针对固件 V2.1.0 记录在案的；日志前缀的完整清单有待在硬件上进行串口抓取。

| 标记 | 出现位置 | 含义 |
| --- | --- | --- |
| `cmd>` | 每个命令 | 提示符；固件已准备好接收下一个命令 |
| `got ip:` | `sta_connect` | 工作站已获得地址；连接成功 |
| 返回码 `0` | `flash_info`、`flash_speed` | 所有检查均通过；任何其他代码都表示失败 |
| `AUDF` | `audio_slot_send` 接收端头部 | 8 字节头部开头的魔数，后面跟着音频长度 |
| `Alias of` | `help` 列表 | 该条目是兼容性别名，而不是单独的命令 |
| `out of bounds` | 参数警告 | 该值被钳制或替换；命令仍会运行 |
| `rx_done` / `rx_hdr_err` / `rx_crc_err` | `lora_rx` 退出 | 在按下 `Ctrl+C` 后打印的接收计数器 |
| `WiFi already initialise.` | `wifi init` | 驱动已初始化，因此跳过此次调用 |

无法解析的值会中止命令并打印一行英文错误；超出范围的值通常会记录 `out of bounds` 并回退到文档中说明的默认值。不同命令的措辞各不相同，因此请修正被标记的值并重新运行命令，而不是依赖匹配整句。
