## 記号の表記規則

| 記号 | 意味 | 例 |
| --- | --- | --- |
| `[ ]` | 省略可能なパラメータ。省略時はデフォルト値が適用されます | `[-p <port>]` |
| `< >` | ユーザーが指定しなければならない具体的な値 | `-g <gpio>` |
| `\|` | 列挙された値のいずれかを選択 | `<0\|1>` |
| 角括弧のない単語 | 必須 | `ping <host>` |
| `cmd>` | ファームウェアのプロンプト。入力しないでください | `cmd> help` |

値は常に `-flag value` の形式で記述します。例えば `gpio_set -g 4 -l 1` のようになります。ファームウェアがロングフォームも登録している場合は、パラメータ表でショートフォームの隣にロングフォームを併記します。

## General {#general}

### 1. help

登録されているすべてのコマンドを 1 行説明付きで一覧表示します。

このコマンドにはパラメータはありません。

**例：**

```bash
help
```

## LoRa / RF {#lora-rf}

これら 7 つのコマンドは、オンボードの LR2021 トランシーバを 2 つの変調方式で駆動します。LoRa は長距離向け、FLRC は高速向けです。すべての送信コマンドは、対応するコネクタにアンテナが必要です。サブ GHz 搬送周波数には `SUB-1G`、2400 ～ 2500 MHz 帯には `LR-2.4G` を使用します。2 枚のボードでリンクテストを行う場合は、両側で同一の無線パラメータを設定する必要があります。

**注意**: `lora_rx`、`flrc_rx`、`lora_tx -n 0`、`flrc_tx -c 0` は、`Ctrl+C` を押すまで動作し続けます。

### 1. lora_tx

**`lora_tx [-f <freq_hz>] [-s <5-12>] [-b <0-9>] [-c <1-7>] [-p <dbm>] [--crc <0|1>] [--hdr <0|1>] [--iq <0|1>] [--net <0|1>] [-i <interval_ms>] [-d <text>] [-n <count>] [-hp <n>] [-dc <n>] [-lf <n>]`**

設定した周波数、スペクトラム拡散率、出力で LoRa パケットを送信します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-f <freq_hz>` | 送信周波数 | `150000000 ~ 2500000000` Hz。デフォルト: `868000000` |
| `-s <5-12>` | スプレッディングファクタ | `5 ~ 12`。値が大きいほど低速で遠くまで届きます。デフォルト: `7` |
| `-b <0-9>` | 帯域幅インデックス | `0`=31k、`1`=41k、`2`=62k、`3`=125k（デフォルト）、`4`=200k、`5`=250k、`6`=400k、`7`=500k、`8`=800k、`9`=1000k |
| `-c <1-7>` | 符号化率 | `1 ~ 7`。`1`=4/5 が最速、`4`=4/8 が最も堅牢。デフォルト: `1` |
| `-p <dbm>` | 送信電力 | サブ GHz `-10 ~ +22` dBm、2.4 GHz `-17 ~ +12` dBm。デフォルト: `10` |
| `--crc <0\|1>` | CRC チェック | `0`=オフ、`1`=オン。デフォルト: `1` |
| `--hdr <0\|1>` | ヘッダ種別 | `0`=インプリシット、`1`=エクスプリシット。デフォルト: `1` |
| `--iq <0\|1>` | IQ モード | `0`=標準、`1`=反転。デフォルト: `0` |
| `--net <0\|1>` | ネットワーク種別とシンクワード | `0`=プライベート（シンクワード `0x12`）、`1`=パブリック（シンクワード `0x34`）。デフォルト: `1` |
| `-i <interval_ms>` | パケット間隔 | ミリ秒。デフォルト: `200`。`0`=連続送信 |
| `-d <text>` | ペイロード文字列 | デフォルト: `hello` |
| `-n <count>` | パケット数 | `0`= `Ctrl+C` まで送信。デフォルト: `10` |
| `-hp <n>` | PA ハーフパワーレジスタ | デバッグ専用。通常使用では未指定のままにします |
| `-dc <n>` | PA デューティサイクルレジスタ | デバッグ専用。通常使用では未指定のままにします |
| `-lf <n>` | PA 低周波スライスレジスタ | デバッグ専用。通常使用では未指定のままにします |

**例：**

```bash
lora_tx -f 868000000 -s 7 -b 3 -p 14 -d hello -n 10
```

:::note
まずアンテナを取り付け、2 枚目のボードで `lora_rx` を起動し、`-f`、`-s`、`-b`、`-c`、`--hdr`、`--crc`、`--iq`、`--net` を同じ値に設定してください。範囲外の値を指定すると `out of bounds` 警告が表示され、コマンドはフォールバックします。`-f` はデフォルト周波数、`-s` は `7`、`-b` は `3`、`-c` は `1` に戻ります。`-p` はバンドの上限にクランプされます。数値以外の `-f`、負の `-i` または `-n` を指定すると、コマンドは中止され、何も送信されません。
:::

### 2. lora_rx

**`lora_rx [-f <freq_hz>] [-s <5-12>] [-b <0-9>] [-c <1-7>] [--crc <0|1>] [--hdr <0|1>] [--plen <0-255>] [--iq <0|1>] [--net <0|1>]`**

LoRa パケットを連続受信し、その数をカウントします。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-f <freq_hz>` | 受信周波数 | `150000000 ~ 2500000000` Hz。デフォルト: `868000000` |
| `-s <5-12>` | スプレッディングファクタ | `5 ~ 12`。デフォルト: `7` |
| `-b <0-9>` | 帯域幅インデックス | `0`=31k、`3`=125k（デフォルト）、`9`=1000k |
| `-c <1-7>` | 符号化率 | `1 ~ 7`。デフォルト: `1` |
| `--crc <0\|1>` | CRC チェック | `0`=オフ、`1`=オン。デフォルト: `1` |
| `--hdr <0\|1>` | ヘッダ種別 | `0`=インプリシット、`1`=エクスプリシット。デフォルト: `1` |
| `--plen <0-255>` | 受信側が想定するペイロード長 | バイト数。エクスプリシットモードでは `0`=任意長、インプリシットモードで省略時は `5` とみなします。デフォルト: `0` |
| `--iq <0\|1>` | IQ モード | `0`=標準、`1`=反転。デフォルト: `0` |
| `--net <0\|1>` | ネットワーク種別とシンクワード | `0`=プライベート（`0x12`）、`1`=パブリック（`0x34`）。デフォルト: `1` |

**例：**

```bash
lora_rx -f 868000000 -s 7 -b 3
```

:::note
このコマンドは `Ctrl+C` までコンソールをブロックし、その時点で `rx_done`、`rx_hdr_err`、`rx_crc_err` を表示します。両方のボードは同じ `--hdr` 値を使用する必要があります。一方がインプリシット、もう一方がエクスプリシットでは受信できません。インプリシットモードでは、送信側のペイロード長に合わせて `--plen` を設定してください。長くしすぎると末尾にゴミが付き、短すぎると末尾が切り捨てられます。インプリシットモードで `--crc 1` を指定すると、テストでは CRC エラーが発生したため、`--hdr 0` と `--crc 0` を組み合わせて使用してください。近距離で `hdr err` が長く続く場合は、パケットが連続して到着していることを意味します。送信側の `-i` を `100` ～ `200` に上げ、1 パケットの空中伝送時間より長く保ってください。
:::

### 3. lora_cw

**`lora_cw [-f <freq_hz>] [-p <dbm>]`**

RF 電力測定用に、変調のない連続波を送信します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-f <freq_hz>` | キャリア周波数 | `150000000 ~ 2500000000` Hz。デフォルト: `868000000`。範囲外または数値以外の値はコマンドを中止します |
| `-p <dbm>` | 送信電力 | サブ GHz `-10 ~ +22` dBm、2.4 GHz `-17 ~ +12` dBm。デフォルト: `10`。バンド上限にクランプされます |

**例：**

```bash
lora_cw -f 868000000 -p 10
```

:::note
キャリアは `lora_cw_stop` を入力するまで継続します。テスト中に電力や周波数を変更したい場合は、新しい値で再度 `lora_cw` を実行してください。設定は自動的に再起動されます。
:::

### 4. lora_cw_pa

**`lora_cw_pa [-f <freq_hz>] [-p <dbm>] [-h <n>] [-d <0-31>] [-l <0-15>]`**

PA レジスタを直接制御して連続波を送信します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-f <freq_hz>` | キャリア周波数 | `150000000 ~ 2500000000` Hz。デフォルト: `868000000` |
| `-p <dbm>` | 送信電力 | サブ GHz `-10 ~ +22` dBm、2.4 GHz `-17 ~ +12` dBm。デフォルト: `10` |
| `-h <n>` | PA ハーフパワー値 | 0.5 dB ステップ。サブ GHz `-19 ~ 44`、2.4 GHz `-39 ~ 24` |
| `-d <0-31>` | PA デューティサイクル | `0 ~ 31` |
| `-l <0-15>` | PA 低周波スライス数 | `0 ~ 15` |

**例：**

```bash
lora_cw_pa -f 868000000 -h 22 -d 0 -l 0
```

:::note
`-h`、`-d`、`-l` のいずれか 1 つでも指定すると、コマンドは直接パラメータモードに切り替わり、パワーテーブルを上書きします。範囲外の値は `out of bounds` 警告とともにバンド上限にクランプされます。キャリアの停止には `lora_cw_stop` を使用してください。
:::

### 5. lora_cw_stop

**`lora_cw_stop`**

`lora_cw` または `lora_cw_pa` で開始した連続波を停止します。

このコマンドにはパラメータはありません。

**例：**

```bash
lora_cw_stop
```

### 6. flrc_tx

**`flrc_tx [-f <freq_hz>] [-p <dbm>] [-b <0-7>] [-l <1-255>] [-c <count>]`**

インクリメントするペイロードを持つ FLRC パケットを、1 秒に 1 パケット送信します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-f <freq_hz>` | 送信周波数 | `415000000 ~ 940000000` Hz。デフォルト: `915000000`。範囲外はデフォルトにフォールバック |
| `-p <dbm>` | 送信電力 | `-10 ~ +22` dBm。デフォルト: `22`。上限にクランプ |
| `-b <0-7>` | レートと帯域幅の組み合わせ | `0`=2.6 Mbps（最速）から `7`=0.26 Mbps まで。デフォルト: `0`。範囲外は `7` にフォールバック |
| `-l <1-255>` | パケット長 | バイト数。デフォルト: `200`。範囲外はデフォルトにフォールバック |
| `-c <count>` | パケット数 | デフォルト: `100`。`0`= `Ctrl+C` まで送信。`500` を超える値は `500` に切り詰め |

**例：**

```bash
flrc_tx -f 868000000 -p 14 -l 200 -c 100
```

:::note
1 秒ごとに 1 パケット送信されるため、1 分間の実行で約 60 パケット送信されます。`-c 0` を指定すると、`Ctrl+C` まで停止せずに送信し続けます。
:::

### 7. flrc_rx

**`flrc_rx [-f <freq_hz>] [-b <0-7>]`**

FLRC パケットを受信し、正常パケット数、ヘッダエラー数、CRC エラー数をカウントします。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-f <freq_hz>` | 受信周波数 | `415000000 ~ 940000000` Hz。デフォルト: `915000000`。範囲外はデフォルトにフォールバック |
| `-b <0-7>` | レートと帯域幅の組み合わせ | `0 ~ 7`。デフォルト: `0`。範囲外は `7` にフォールバック |

**例：**

```bash
flrc_rx -f 868000000 -b 0
```

:::note
`Ctrl+C` で受信を停止し、カウンタを表示します。
:::

## BLE {#ble}

Bluetooth は起動時には開始されません。最初の `ble -a 1` で BLE スタックを初期化し、アドバタイズを開始します。`ble -a 0` はアドバタイズを停止し、スタックをアンロードしてメモリを解放します。デバイス名は `wio-lr2021-` で始まり、アドバタイズは接続を受け付けます。

### 1. ble

**`ble -a <0|1>`**

Bluetooth アドバタイズをオンまたはオフにします。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-a <0\|1>` | アドバタイズスイッチ | `1`=アドバタイズ開始（初回はスタックを初期化）、`0`=アドバタイズ停止およびスタック解放。必須 |

**例：**

```bash
ble -a 1
```

:::note
スマートフォンの nRF Connect から `wio-lr2021-` を検索します。リストに表示されればデバイスは正常です。接続後、アプリはデバイスにコマンドを送信し、デバイスが出力するログ行を読み取ることができます。
:::

### 2. ble_status

**`ble_status`**

デバイス名、MAC アドレス、送信電力、アドバタイズパラメータ、および接続状態を表示します。

このコマンドはパラメータを取りません。

**例:**

```bash
ble_status
```

:::note
Bluetooth が初期化されていない場合、このコマンドは最初に `ble -a 1` を実行するように促します。
:::

## Wi-Fi & ネットワーク {#wifi-network}

Wi-Fi は起動時に自動で初期化および開始されるため、これらのコマンドで手動の `wifi init` は不要です。ほとんどのコマンドは Espressif の Wi-Fi テストコンポーネントをラップしており、多くのオプションを持ちます。以下のパラメータ表には、文書化されているものを示します。ルーターへの接続には、ユーザー自身の 2.4 GHz アクセスポイントとそのパスワードが必要です。

### 1. wifi

**`wifi <status|stop|start|restart|init|deinit>`**

Wi-Fi の状態を問い合わせる、または無線を開始・停止・再初期化します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `status` | 初期化状態と接続情報を表示 | 最も一般的な問い合わせ |
| `stop, start` | 無線を停止または開始、ドライバは保持 | 電力試験および干渉除去 |
| `restart` | フル再起動：stop, deinit, init, start | `deinit` 後の復旧 |
| `init, deinit` | ドライバを初期化またはアンロード | 研究開発でのデバッグ専用 |

**例:**

```bash
wifi status
```

:::note
すでに初期化済みのシステムで `wifi init` を実行すると、`WiFi already initialise.` という 1 行の警告を出してスキップされます。`wifi deinit` は無線がまだ動作中であれば先に停止し、`wifi status` は `initialized` と `started` を別々に表示します。
:::

### 2. wifi_count

**`wifi_count [query|clear]`**

Wi-Fi の送受信パケットカウンタを表示またはリセットします。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `query` | カウンタを表示 | 引数がない場合のデフォルト |
| `clear` | 両方のカウンタをゼロにリセット | — |

**例:**

```bash
wifi_count
```

### 3. wifi_mode

**`wifi_mode <sta|ap|apsta>`**

デバイスの Wi-Fi ロールを設定します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `sta` | スマートフォンなど、別のホットスポットに参加 | — |
| `ap` | ホットスポットとして動作 | — |
| `apsta` | 両方のロールを同時に使用 | — |

**例:**

```bash
wifi_mode sta
```

### 4. wifi_protocol

**`wifi_protocol [protocol] [-i <ap|sta>]`**

802.11 プロトコルの組み合わせを問い合わせまたは設定します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `<protocol>` | プロトコルの組み合わせ | `b`, `b/g`, `b/g/n`; デフォルト：現在値を問い合わせ |
| `-i <ap\|sta>` | 設定を適用するインターフェース | `ap` または `sta`; デフォルト：`sta` |

**例:**

```bash
wifi_protocol b/g/n
```

### 5. wifi_bandwidth

**`wifi_bandwidth [20|40] [-i <ap|sta>]`**

チャネル帯域幅を問い合わせまたは設定します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `<20\|40>` | MHz 単位のチャネル帯域幅 | `20` または `40`; デフォルト：現在値を問い合わせ |
| `-i <ap\|sta>` | 設定を適用するインターフェース | `ap` または `sta`; デフォルト：`sta` |

**例:**

```bash
wifi_bandwidth 20
```

### 6. wifi_ps

**`wifi_ps <0|1|2>`**

Wi-Fi の省電力レベルを設定します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `0` | 省電力なし、最高性能 | 必須 |
| `1` | 中程度の省電力 | — |
| `2` | 最大の省電力 | — |

**例:**

```bash
wifi_ps 0
```

### 7. wifi_country

**`wifi_country [code] [-s <start_channel>] [-n <channel_count>] [-p <auto|manual>]`**

国コードと使用可能なチャネル範囲を問い合わせまたは設定します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `<code>` | 2 文字の国コード | 例：`US`; デフォルト：現在値を問い合わせ |
| `-s <start_channel>` | 許可された範囲の最初のチャネル | チャネル番号; デフォルト：未設定 |
| `-n <channel_count>` | 範囲内のチャネル数 | 個数; デフォルト：未設定 |
| `-p <auto\|manual>` | チャネルプランの選択 | `auto` または `manual`; デフォルト：未設定 |

**例:**

```bash
wifi_country US
```

### 8. ap_set

**`ap_set <ssid> [pass] [-a <authmode>] [-n <channel>] [-m <max_conn>]`**

デバイスを Wi-Fi ホットスポットとして動作させ、スマートフォンや PC が接続できるようにします。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `<ssid>` | ホットスポット名 | 必須 |
| `<pass>` | ホットスポットのパスワード | 8 文字以上; 任意 |
| `-a <authmode>` | セキュリティモード | `open`, `wep`, `wpa2`; 認識されない名前は報告され、ホットスポットは `open` にフォールバック; デフォルト：未設定 |
| `-n <channel>` | ホットスポットのチャネル | チャネル番号; デフォルト：未設定 |

**例:**

```bash

```

**エイリアス**: `ap`（`ap_set` と同じ）。

:::note
共有ネットワーク上でホットスポットを有効にしたままにする前にパスワードを変更し、テストが終わったら停止してください。
:::

## IO エクスパンダ {#io-expander}

GPIO 番号は ESP32-S3 の GPIO 番号です。ピン機能は [Wio-LR2021 Dev Kit Pin Map](/ja/wio_lr2021_dev_kit_getting_started) に一覧があります。IO エクスパンダは I²C アドレス `0x21` の PCA9535 です。0 ～ 15 の 16 本のピンを公開しており、そのうち 4 本がカメラ、オーディオ、OLED、Grove の電源レールを切り替えます。

:::note
どのペリフェラルにも割り当てられていないピンは、電源投入後はフローティング入力のまま（プル抵抗オフ）なので、生の `gpio_get` はノイズを読み取ります。まず `gpio_config` を実行してください：入力には `-m 0`（任意でプル指定）、プッシュプル出力には `-m 1`、オープンドレイン出力には `-m 2` を指定します。
:::

### 1. gpio_set

**`gpio_set -g <gpio> -l <0|1>`**

GPIO を High または Low に駆動します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-g <gpio>` | GPIO 番号 | 必須 |
| `-l <0\|1>` | 出力レベル | `1`=High（約 3.3 V）、`0`=Low（0 V）; 必須 |

**例:**

```bash
gpio_set -g 4 -l 1
```

:::note
ピンを駆動する前に `gpio_config -m 1` で方向を設定し、マルチメータまたは別の GPIO へのループバックワイヤでレベルを確認してください。
:::

### 2. gpio_get

**`gpio_get -g <gpio>`**

GPIO の現在のレベルを読み取ります。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-g <gpio>` | GPIO 番号 | 必須 |

**例:**

```bash
gpio_get -g 4
```

### 3. gpio_config

**`gpio_config -g <gpio> -m <0|1|2> [-p <0|1|2|3>]`**

GPIO の方向とプル抵抗を設定します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-g <gpio>` | GPIO 番号 | 必須 |
| `-m <0\|1\|2>` | 方向 | `0`=入力、`1`=出力、`2`=オープンドレイン出力; 必須 |
| `-p <0\|1\|2\|3>` | プル抵抗 | `0`=フローティング（デフォルト）、`1`=プルアップ、`2`=プルダウン、`3`=両方有効 |

**例:**

```bash
gpio_config -g 5 -m 0 -p 1
```

### 4. i2c_scan

**`i2c_scan [-b <0|1>]`**

1 本または両方の I²C バスをスキャンし、応答するアドレスを一覧表示します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-b <0\|1>` | スキャンするバス番号 | `0` または `1`; デフォルト：両方をスキャン |

**例:**

```bash
i2c_scan -b 0
```

:::note
正常なボードでは、バス 0 に `0x21` の PCA9535 が表示され、ディスプレイ電源レールがオンになると `0x3D` の OLED が表示されます。アドレスが見つからない場合、そのチップは実装されていない、電源が入っていない、または応答していないことを意味します。
:::

### 5. io_exp_set

**`io_exp_set -i <0-15> -l <0|1>`**

IOエクスパンダの1本のピンをHighまたはLowに駆動します。

| Item | Description | Data |
| --- | --- | --- |
| `-i <0-15>` | エクスパンダのピン番号 | `0 ~ 15`; 必須 |
| `-l <0\|1>` | 出力レベル | `1`=High、`0`=Low；必須 |

**Example:**

```bash
io_exp_set -i 3 -l 1
```

:::note
ピン `0 ~ 3` は周辺機器レールを切り替えます。これらを駆動すると、カメラ、オーディオ、OLED、および Grove コネクタの電源状態が変化します。
:::

### 6. io_exp_get

**`io_exp_get -i <0-15>`**

IOエクスパンダの1本のピンを読み取ります。

| Item | Description | Data |
| --- | --- | --- |
| `-i <0-15>` | エクスパンダのピン番号 | `0 ~ 15`; 必須 |

**Example:**

```bash
io_exp_get -i 3
```

### 7. io_exp_config

**`io_exp_config -i <0-15> -m <0|1>`**

IOエクスパンダの1本のピンを入力または出力として設定します。

| Item | Description | Data |
| --- | --- | --- |
| `-i <0-15>` | エクスパンダのピン番号 | `0 ~ 15`; 必須 |
| `-m <0\|1>` | 方向 | `0`=入力、`1`=出力；必須 |

**Example:**

```bash
io_exp_config -i 3 -m 1
```

### 8. io_exp_print

**`io_exp_print`**

16本すべてのエクスパンダピンの方向とレベルを1つの表で表示します。

このコマンドにパラメータはありません。

**Example:**

```bash
io_exp_print
```

## Camera {#camera}

カメラはMedia HAT上の2 MP GC2145で、工場出荷時ファームウェアはRGB565として読み取り、JPEGフレームをストリーミングします。`camera_http_start` は、ホットスポット、カメラ、Webサーバを1つのコマンドで起動する、最も短いエンドツーエンドチェックです。

### 1. camera_start

**`camera_start [-q <1-100>] [-r <qqvga|qvga|vga>] [-F <hz>]`**

カメラに電源を投入し、初期化します。

| Item | Description | Data |
| --- | --- | --- |
| `-q <1-100>` | JPEG圧縮品質 | `1 ~ 100`; デフォルト: `80` |
| `-r <qqvga\|qvga\|vga>` | キャプチャ解像度 | `qqvga`=160×120、`qvga`=320×240（デフォルト）、`vga`=640×480 |
| `-F <hz>` | カメラ制御バス（I²C）クロック | Hz；デフォルト: `100000` |

**Example:**

```bash
camera_start -r vga
```

:::note
別の `-r` または `-F` を指定して `camera_start` を再度実行すると、カメラが再起動され、設定が切り替わります。起動直後の最初のフレームはウォームアップとして破棄されます。このコマンドは、カメラが初期化されることを確認する最も手早い方法でもあります。
:::

### 2. camera_stop

**`camera_stop`**

カメラを停止し、電源を切ります。

このコマンドにパラメータはありません。

**Example:**

```bash
camera_stop
```

### 3. camera_http_start

**`camera_http_start [-s <ssid>] [-p <pwd>] [-c <1-13>] [-q <1-100>] [-f <1-30>] [-P <port>] [-r <qqvga|qvga|vga>] [-F <hz>]`**

1つのコマンドでホットスポット、カメラ、MJPEG Webプレビューを起動します。

| Item | Description | Data |
| --- | --- | --- |
| `-s <ssid>` | ホットスポット名 | デフォルト: `wio-lr2021-camera` |
| `-p <pwd>` | ホットスポットパスワード | 8～63文字、空文字でオープンネットワーク；デフォルト: `12345678` |
| `-c <1-13>` | ホットスポットチャネル | `1 ~ 13`; デフォルト: `1` |
| `-q <1-100>` | JPEG品質 | 高いほど鮮明で帯域幅を多く使用；デフォルト: `80` |
| `-f <1-30>` | フレームレート上限 | フレーム/秒；デフォルト: `20` |
| `-P <port>` | Webサーバポート | ビデオストリームはこのポート+1を使用します。動作中に変更するとWebサービスが再起動され、範囲外の値は警告を出してフォールバックします；デフォルト: `80` |
| `-r <qqvga\|qvga\|vga>` | ストリーム解像度 | デフォルト: `qvga` |
| `-F <hz>` | カメラ制御バス（I²C）クロック | Hz；デフォルト: `100000` |

**Example:**

```text
camera_http_start -q 60 -f 10
```

:::note
`-s`、`-p` または `-c` を変更してコマンドを再実行した後は、電話機やPCを一度ホットスポットから切断し、再接続してください。そうしないと、ボードに到達できない状態でもクライアント側では接続済みと表示され続けます。
:::

**使用方法**：パスワード `12345678` でホットスポット `wio-lr2021-camera` に接続し、ブラウザで `http://192.168.4.1` を開きます。ライブ画像が表示されれば、カメラとWi-Fi経路の両方が動作していることを意味します。

:::note
このWebページには認証機能がありません。ホットスポットを共有ネットワークやオフィスネットワークには接続せず、`camera_http_stop` で停止してください。
:::

### 4. camera_http_stop

**`camera_http_stop`**

Webサーバを停止し、カメラとホットスポットの電源を切ります。

## Audio {#audio}

オーディオスロットはRAM上の録音バッファであり、SDカードは不要です。スロットに録音し、その内容をスピーカーで再生するか、デバイスのホットスポット経由でPCにストリーミングできます。

### 1. audio_init

**`audio_init`**

オーディオ回路に電源を投入し、コーデックとマイクを初期化します。

このコマンドにパラメータはありません。

**Example:**

```bash
audio_init
```

:::note
ファームウェアは起動時にこれを1回実行します。`audio_deinit` の後に復旧するために使用します。
:::

### 2. audio_deinit

**`audio_deinit`**

オーディオ回路の電源を切ります。

このコマンドにパラメータはありません。

**Example:**

```bash
audio_deinit
```

:::note
録音と再生は、`audio_init` が再度実行されるまで利用できません。消費電力測定に使用してください。起動後に一度もオーディオが初期化されていない場合、このコマンドは拒否されるため、連続して2回目の `audio_deinit` を実行しても何も起こりません。
:::

### 3. audio_slot_record

**`audio_slot_record [-d <100-60000>] [-m <20.0-37.5>]`**

マイクからオーディオスロットに録音します。

| Item | Description | Data |
| --- | --- | --- |
| `-d <100-60000>` | 録音時間 | ミリ秒；`100 ~ 60000`; デフォルト: `10000` |
| `-m <20.0-37.5>` | マイクゲイン | dB；`20.0 ~ 37.5`; デフォルト: `37.5`（最大） |

**Example:**

```bash
audio_slot_record -d 5000 -m 30
```

:::note
スロットには、ソフトウェア処理を行っていない生のマイクデータが保持されます。録音中はマイクに近づいて話してください。オーディオは起動時に初期化されますが、`audio_deinit` の後は、最初に `audio_init` を実行しないとこのコマンドは拒否されます。
:::

### 4. audio_slot_play

**`audio_slot_play [-v <0-100>]`**

録音済みスロットをスピーカーから再生します。

| Item | Description | Data |
| --- | --- | --- |
| `-v <0-100>` | 再生音量 | `0 ~ 100`; デフォルト: 現在の音量を維持 |

**Example:**

```bash
audio_slot_play -v 80
```

:::note
Media HATの `SPK` コネクタにスピーカーを接続してください。このコマンドは、スロットに現在入っているものを再生するだけなので、先に録音しておく必要があります。オーディオが初期化されていない場合やスロットが空の場合は拒否されます。
:::

### 5. audio_slot_send

**`audio_slot_send [-p <port>]`**

スロットの内容をデバイスのホットスポット経由でPCにWAVファイルとしてストリーミングします。

| Item | Description | Data |
| --- | --- | --- |
| `-p <port>` | PCが接続するTCPポート | デフォルト: `3444` |

**Example:**

```bash
audio_slot_send
```

**使用方法**：PCからパスワード `12345678` でホットスポット `wio-lr2021-audio` に接続し、`python tools/recv_wav_from_device.py -o slot.wav` を実行します。スクリプトは `192.168.4.1:3444` に接続し、8バイトのヘッダ（`AUDF` マジックとオーディオ長）を読み取った後、オーディオバイトを読み込みます。ファイルは書き込みが完了するとすぐに再生できます。

:::note
このコマンドは即座に戻り、転送はバックグラウンドで実行されます。転送が終了してもホットスポットは閉じないため、複数の録音を続けて送信できます。停止するには `audio_slot_stop` を実行してください。
:::

### 6. audio_slot_stop

**`audio_slot_stop`**

進行中の転送を停止し、オーディオホットスポットを閉じます。

このコマンドにパラメータはありません。

**Example:**

```bash
audio_slot_stop
```

:::note
転送が行われていない状態で実行しても安全で、ホットスポットを閉じる以外の効果はありません。
:::

### 7. audio_slot_info

**`audio_slot_info`**

スロットの状態（録音の有無、その長さ、サンプルレート、チャンネル数、再生時間、空きメモリ）を表示します。

このコマンドにパラメータはありません。

**Example:**

```bash
audio_slot_info
```

## Flash {#flash}

フラッシュの耐久性テストと速度テストは、専用の `flashtest` パーティション内でのみ動作するため、ファームウェアイメージやユーザーデータには一切触れません。`flash_endurance` はバックグラウンドタスクとして動作し、コンソールを使用可能なまま書き込みを続けます。

### 1. flash_info

**`flash_info`**

フラッシュのJEDEC ID、ベンダー、容量を読み取り、テストパーティションの開始位置と終了位置を検証します。

このコマンドはパラメータを取りません。

**例：**

```bash
flash_info
```

:::note
リターンコード `0` は合格を意味します。境界書き込みチェックは、容量を過大に表記したフラッシュチップを検出します。
:::

### 2. flash_endurance

**`flash_endurance -a <start|stop|status> [-m <minutes>] [-s <sectors>] [-d <ms>]`**

フラッシュテストパーティションで、消去・書き込み・読み出しの soak テストを実行します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-a <start\|stop\|status>` | アクション | `start`、`stop` または `status`。必須 |
| `-m <minutes>` | 実行時間 | 分。`0` は停止されるまで実行。デフォルト：`1440` |
| `-s <sectors>` | 1 ラウンドあたりに書き込むセクタ数 | `0`=テストパーティション全体。デフォルト：`0` |
| `-d <ms>` | セクタ間のディレイ | ミリ秒。`0`=フルスピード。デフォルト：`0` |

**例：**

```bash
flash_endurance -a start -m 60
```

:::note
このコマンドはすぐに戻り、soak はバックグラウンドで実行されます。`-a status` で進行状況を確認し、`-a stop` で終了します。各ラウンドでフラッシュが摩耗するため、すべてのボードではなくサンプルで実行してください。
:::

### 3. flash_speed

**`flash_speed [-t <kb>]`**

ページプログラム時間、セクタ消去時間、および読み書きスループットを測定します。

| 項目 | 説明 | データ |
| --- | --- | --- |
| `-t <kb>` | スループットテストに使用するデータ量 | KB。デフォルト：`64` |

**例：**

```bash
flash_speed -t 128
```

:::note
リターンコード `0` は、すべての測定値がデータシートの制限内であることを意味します。
:::

## エイリアス

5 つの互換性エイリアスが登録されています。これらはプライマリコマンドとまったく同じ関数を呼び出します。スクリプトやドキュメントではプライマリ名を使用してください。

| エイリアス | プライマリコマンド | 備考 |
| --- | --- | --- |
| `ap` | `ap_set` | 同じ機能。プライマリ名を推奨。 |
| `sta` | `sta_connect` | 同じ機能。プライマリ名を推奨。 |
| `disconnect` | `sta_disconnect` | 同じ機能。プライマリ名を推奨。 |
| `wifi_scan` | `sta_scan` | 同じ機能。プライマリ名を推奨。 |
| `scan` | `sta_scan` | 同じ機能。プライマリ名を推奨。 |

## 結果文字列とリターンコード

ファームウェアは結果をシリアルポート上のプレーンテキスト行として出力し、その後 `cmd>` プロンプトに戻ります。以下のマーカーはファームウェア V2.1.0 で文書化されているものです。ログプレフィックスの完全な一覧は、ハードウェアでのシリアルキャプチャ待ちです。

| マーカー | 表示される場所 | 意味 |
| --- | --- | --- |
| `cmd>` | すべてのコマンド | プロンプト。ファームウェアが次のコマンドを受け付ける状態 |
| `got ip:` | `sta_connect` | ステーションがアドレスを取得し、接続に成功した |
| リターンコード `0` | `flash_info`、`flash_speed` | すべてのチェックに合格。その他のコードは失敗 |
| `AUDF` | `audio_slot_send` 受信ヘッダ | 8 バイトヘッダの先頭にあるマジックで、その後にオーディオ長が続く |
| `Alias of` | `help` リスト | エントリが互換性エイリアスであり、別個のコマンドではない |
| `out of bounds` | パラメータ警告 | 値がクランプまたは置き換えられたが、コマンドは実行される |
| `rx_done` / `rx_hdr_err` / `rx_crc_err` | `lora_rx` 終了時 | `Ctrl+C` 後に表示される受信カウンタ |
| `WiFi already initialise.` | `wifi init` | ドライバはすでに初期化されており、呼び出しはスキップされた |

解析できない値はコマンドを中止し、英語のエラー行を出力します。範囲外の値は通常 `out of bounds` をログに出し、文書化されたデフォルトにフォールバックします。文言はコマンドごとに異なるため、文をパターンマッチするのではなく、指摘された値を修正してコマンドを再実行してください。
