PCBA 機能テストは、定義された操作と測定を用いて、実装済み基板が意図したとおりに動作するかどうかを確認します。テスト要件は、何をテストするか、その条件と手順、および合否判定基準を記述します。これにより、製造チームがテストを実施するために必要な情報が提供されます。

本ガイドは、Seeed Fusion に PCBA 機能テストを依頼するお客様を対象としています。具体的なテスト内容と方法は、製品設計およびプロジェクト要件に基づいて確定されます。

本ガイドはテスト要件の作成に焦点を当てています。テストやカスタム治具を依頼する際に必要となる設計ファイルや製品情報については、[Seeed Fusion PCBA Testing Solutions Guide](https://wiki.seeedstudio.com/ja/service_for_fusion_pcba_testing_solutions/) および以下にリンクされたサービスリソースを参照してください。

## 機能テストの対象範囲

機能テストは、製品が意図された機能を果たしているかを確認します。電源、通信インターフェース、ボタン、インジケータ、センサ、オーディオなどを対象とする場合があります。プロジェクトのテスト計画によって、その範囲が定義されます。

実装検査と機能テストは、基板の異なる側面を検査します。AOI は目視可能な実装不良を確認し、X 線検査は隠れたはんだ接合部を明らかにし、インサーキットテスト（ICT）は電気的なチェックを行います。機能テストは、基板がテスト計画で指定された機能を実行できるかどうかを確認します。使用される方法は、基板設計とテスト要件に依存します。

テスト結果は、計画で定義された項目と基準に適用されます。例えば、コンピュータが USB デバイスを検出できれば、USB 検出テストを満たすことができます。計画では、テストすべきその他の USB 機能を指定する必要があります。

## 各テストに含める内容

各テストでは、何をテストするか、どのように実施するか、何を合格とみなすか、そして必要なテスト条件を記述します。

| 情報 | 指定内容 |
| --- | --- |
| テスト対象 | 電源レール、特定の GPIO、USB インターフェースなど、確認する機能、インターフェース、または信号。 |
| テスト条件 | テストに必要な電源、接続、ファームウェア、およびソフトウェア環境。 |
| テスト手順 | 実行する操作または測定内容とその順序。 |
| 期待される結果 | 操作後に期待される、観測可能な動作、返される情報、または測定結果。 |
| 合否判定基準 | 許容される数値範囲、指定されたデバイスアドレス、期待されるロジックレベルなど、合格または不合格を判断するための条件。 |

電圧測定などの数値テストでは、基準には目標値と許容範囲を含めます。デバイス検出、ボタン、インジケータの場合は、期待される検出結果や、操作後に取るべき状態を指定します。「正常に動作している」などの一般的な記述は、テストオペレータやプログラムが評価できる具体的な基準が必要です。

## テスト環境と接続

テスト環境の説明では、テストを実施するために必要な装置、ソフトウェア、および接続を特定します。以下の表は関連しうる情報を示したもので、詳細はテスト項目に依存します。

| 情報 | 指定内容 |
| --- | --- |
| 電源条件 | 電源入力、電圧、およびそれに対応するテスト手順。 |
| インターフェースとテストポイント | 使用するインターフェース、ピン、またはテストポイントと、それらがテスト装置にどのように接続されるか。 |
| テスト装置 | 測定器、プログラマ、およびその他の補助装置の機種または仕様。 |
| ソフトウェア環境 | オペレーティングシステム、テストソフトウェア、および関連設定。 |
| テスト治具 | 治具を使用する場合、基板の配置方法、接続箇所、および操作方法。 |

接続の詳細は、個々のテスト内容と一致している必要があります。電圧測定では特定のテストポイントを参照し、通信テストではインターフェースと信号を特定し、ファームウェア書き込み手順ではプログラミングインターフェースと接続を特定します。図を用いることで、これらの位置や接続を示しやすくなります。

テスト治具は、基板を固定し、必要なテストポイントやインターフェースへの再現性のある接続を提供します。治具を使用するかどうか、およびその設計方法は、基板とテスト計画によって決まります。

## ファームウェア書き込みとテストシーケンス

ファームウェア書き込みを伴うプロジェクトでは、ファームウェアファイル、バージョン、開発日、および適用可能なハードウェアリビジョンを含めてください。また、プログラマ、接続、書き込みソフトウェア、および操作手順も指定します。同一のテストプロセスで複数のファームウェアファイルを使用する場合は、それぞれのファイルの目的と使用タイミングを明確にしてください。

テスト用ファームウェアは、生産中の機能チェックをサポートします。出荷用ファームウェアは、製品が出荷後に実行するファームウェアです。これらが異なる場合は、テスト用ファームウェアを使用するタイミングと、出荷用ファームウェアを書き込むタイミングを手順で明記する必要があります。

テスト手順は、実行される順番に沿って配置し、それぞれの操作に期待される結果を対応させます。例えば、電源テストでは、基板への給電、指定されたテストポイントの測定、および測定値を許容範囲と比較する手順を記述できます。書き込み手順については、使用するファイルと、書き込み成功を確認する方法を指定してください。

## テスト要件の例と関連リソース

以下の選択されたテストは、**reSpeaker Flex XVF3800 Core Board with XIAO** 向けの Seeed 公式テストリファレンスから抜粋したものです。これらは、テスト項目、方法、および合格基準がどのように関連しているかを示しています。テストポイント、値、およびデバイスアドレスは、このリファレンスプロジェクトにのみ適用されます。

| テスト項目 | テスト方法 | 合格基準 |
| --- | --- | --- |
| VDDIO 電圧 | ADC を使用してテストポイント TP7 を測定します。 | 3.3 V ±5%。 |
| USB Type-C 接続 | コネクタを両方の向きでテストします。 | XMOS デバイスが両方の向きで認識されること。 |
| XIAO I²C デバイス検出 | I²C バスをスキャンします。 | コーデックがアドレス 0x18 で検出されること。 |
| RST リセットボタン | Reset ボタンを押します。 | XMOS がリセットされること。 |

この表には、選択されたテスト項目のみが含まれています。テストを実行するには、電源および接続の詳細、関連するファームウェアとソフトウェア環境、詳細な操作手順、および結果の解釈に関するガイダンスも必要です。

完全なリファレンスでは、テスト要件がアダプタボードの接続およびソフトウェアの実行とどのように対応しているかを説明しています。詳しくは、[Open-Source Modular PCBA Testing: A Complete Guide from Hardware to Test Workflow](https://www.seeedstudio.com/blog/2026/10/08/seeed-fusion-open-source-modular-pcba-testing-a-complete-guide-from-hardware-to-test-workflow/) を参照してください。

治具の用途、適したアプリケーション、および依頼書類については、[What Is a PCBA Test Fixture? How It Works and When You Need One](https://www.seeedstudio.com/blog/2026/09/10/seeed-fusion-what-is-a-pcba-test-fixture-how-it-works-and-when-you-need-one/) を参照してください。PCB 製造および実装ファイルの要件については、[Seeed Fusion PCB & PCBA Service Guide](https://wiki.seeedstudio.com/ja/Service_for_Fusion_PCB/) で説明しています。

機能テスト、ファームウェア書き込み、およびカスタムテスト治具サービスについては、[Fusion Testing Solutions](https://www.seeedstudio.com/fusion-testing-solutions.html) をご覧いただくか、[fusion@seeed.io](mailto:fusion@seeed.io) までご連絡のうえ、プロジェクト要件をご相談ください。
