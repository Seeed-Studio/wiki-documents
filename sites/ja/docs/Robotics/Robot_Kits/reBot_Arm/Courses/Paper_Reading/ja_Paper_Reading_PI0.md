## 要約
### 翻訳
ロボット学習は、柔軟で汎用的かつ巧みなシステムと、AI の根本的な問いへの洞察を約束するものです。実世界のシステムに必要な汎用性を達成するには、データ、汎化、ロバスト性の面で依然として大きな障害があります。

この論文は、ジェネラリストロボットポリシー、すなわちロボット基盤モデルが、複雑で巧みなタスクに対してこれらの課題にどう取り組めるかを問います。インターネット規模データから意味知識を継承する事前学習済み VLM 上にフローマッチングアーキテクチャを構築し、その後、多様な単腕・双腕・モバイルマニピュレーションプラットフォームで学習します。

評価は 3 つの設定を対象とします：直接プロンプト、ヒトまたは高レベル VLM ポリシーからの言語指示の追従、新しいスキルに対するファインチューニングです。タスクには、洗濯物の折りたたみ、テーブルの片付け、段ボール箱の組み立てなどが含まれます。

### 解説
- **アーキテクチャは問題の一部にすぎない。** この論文は 3 つのボトルネックを特定します：十分なデータスケール、連続かつ高頻度のアクションに対応するアーキテクチャ、そして適切な事前／事後学習レシピです。

- **VLM は理解を、アクションエキスパートは制御を担う。** PaliGemma は画像と言語の意味を処理し、エキスパートはロボット状態、ノイズを含むアクション、および連続出力を処理します。

- **フローマッチングは自回帰的なアクショントークン生成に置き換わる。** モデルはノイズから連続アクションチャンク全体を並列に生成します。

- **クロスエンボディメントデータが中核となる。** アームとモバイルベースでは状態空間とアクション空間が異なります。パディングとマスクされた画像スロットによって、共通の学習インターフェースを提供します。

- **事前学習と事後学習は役割が異なる。** 広範な事前学習には、通常とは異なる状態やリカバリ挙動が含まれます。一方、事後学習は一貫性があり流暢な成功を重視します。両者を組み合わせることで、適応性と実行品質を両立させます。

## 序論
![π0 論文ディープダイブ: 3. 序論 (画像 07)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-07-en.png)

### 段落 1：汎用性には物理的経験が必要
- **主張の要点：** AI はタンパク質構造予測や画像生成のような専門的タスクでは優れていますが、環境・制約・言語・予期せぬ出来事にまたがる汎用性では、人間の方がはるかに優れています。LLM や VLM は多様な事前学習の恩恵を受けますが、それ自体として物理的インタラクションの経験を獲得するわけではありません。

- **持ち越される問題：** 画像とテキストによる記述は、物体との接触やダイナミクスの経験の代わりにはなりません。

- **手法へのつなぎ：** ジェネラリストロボットモデルには、インターネット上の意味情報と物理ロボットのデータの両方が必要です。

![π0 論文ディープダイブ: 段落 1：汎用性には物理的経験が必要 (画像 08)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-08-en.png)

### 段落 2：なぜ基盤モデルがロボティクスに適しているのか
- **主張の要点：** ジェネラリストモデルは、他のタスク・ロボット・さらには非ロボットソースからもデータを集約し、単一タスクのデータ不足を緩和します。多様性によって、より多くのシーン・エラー・リカバリをカバーでき、ロバスト性が向上します。

- **持ち越される問題：** 1 台のロボットと 1 つのタスクだけでは、失敗状態を十分にカバーできないことが多いです。

- **手法へのつなぎ：** 広く事前学習し、その後は各タスクをゼロから学習するのではなく、プロンプトやファインチューニングを用います。

![π0 論文ディープダイブ: 段落 2：なぜ基盤モデルがロボティクスに適しているのか (画像 11)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-11-en.png)

### 段落 3：3 つのボトルネック
- **主張の要点：** ジェネラリストポリシーには、十分なスケール、異種データを統合し精密なアクションを表現できるアーキテクチャ、そして適切なデータ選択と学習レシピが必要です。

- **持ち越される問題：** 言語モデルの手法を、そのまま連続・高頻度・プラットフォーム依存の制御にコピーすることはできません。

- **手法へのつなぎ：** π0 はデータ・アーキテクチャ・学習をそれぞれ個別に扱います。

![π0 論文ディープダイブ: 段落 3：3 つのボトルネック (画像 02)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-02-en.png)

### 段落 4：アーキテクチャ上の解答
- **主張の要点：** VLM から初期化し、複数のエンボディメントにまたがって共同学習し、連続制御のためにアクションチャンクとフローマッチングを用い、バックボーンをアクション生成器へ拡張するアクションエキスパートを追加します。

- **持ち越される問題：** ロボットごとにアクション空間が異なり、離散自回帰は速度と精度の両立に苦戦します。

- **手法へのつなぎ：** セクション 5 と 6 で、クロスエンボディメントデータセットとアクションエキスパートを展開します。

![π0 論文ディープダイブ: 段落 4：アーキテクチャ上の解答 (画像 14)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-14-en.png)

### 段落 5：学習レシピ
- **主張の要点：** 事前学習と事後学習は役割分担をします。洗練された成功例だけで学習すると、ミスやリカバリの経験がほとんど得られません。一方で、広範だが品質の低いデータだけを用いると、効率的な実行が得られない可能性があります。事前学習は経験を広げ、事後学習は望ましい振る舞いを形作ります。

- **持ち越される問題：** 「よりクリーンなデータが常に良い」というのは、ロボット学習のすべての段階に当てはまる普遍的なルールではありません。

- **実験へのつなぎ：** 事前学習済みモデルの直接利用、ゼロからの学習、事前学習後のファインチューニングを比較します。

![π0 論文ディープダイブ: 段落 5：学習レシピ (画像 13)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-13-en.png)

### 段落 6：貢献と評価範囲
- **主張の要点：** 貢献には、VLM ベースのフローマッチング汎用アーキテクチャと、事前／事後学習レシピの実証的研究が含まれます。このポリシーは、言語プロンプティング、下流タスクへのファインチューニング、高レベル VLM からの中間指示に対応します。

- **持ち越される問題：** アーキテクチャと学習の両方について、実ロボット上でのエビデンスが必要です。

- **実験へのつなぎ：** 1 万時間を超えるロボットデータに基づき、洗濯物の折りたたみ、テーブルの片付け、電子レンジへの積み込み、卵パック詰め、箱の組み立て、買い物袋詰めなどの評価を行います。

## 関連研究
- **VLA：** RT-2、OpenVLA、Octo は、視覚と言語の表現をロボット制御へ転移します。多くは離散自回帰アクショントークンを用います。π0 は事前学習済み VLM を保持しつつ、条件付きフローマッチングによって連続かつ高頻度のチャンクを生成します。

- **拡散／フローモデルとマルチモーダル Transformer：** Diffusion Policy はマルチモーダルな連続アクションをモデル化し、Transfusion は離散トークンと連続生成目的を組み合わせます。π0 は関連するアイデアを VLA に適用し、画像・言語と状態・アクションの重みがアテンションを通じて相互作用します。

- **大規模ロボット学習：** 以前のデータセットは、より単純な把持や押し動かしに焦点を当てることが多くありました。OXE、Bridge、DROID はタスクとロボットのカバレッジを広げました。π0 は 1 万時間超の内部データ、主に巧みな双腕行動と、2 段階の事前／事後学習レシピを追加します。

- **巧みなマニピュレーション：** ACT や Diffusion Policy は、小規模データセットから精密なタスクを学習しますが、通常はタスクおよびロボット固有です。π0 は代わりに、複数エンボディメントにまたがって事前学習し、その後、データスケールに応じてプロンプトや高品質な事後学習を用います。

## クロスエンボディメントシステムとデータ
### 設計目標と構成要素
π0 は、1 本のアームに結びついたコントローラではなく、クロスエンボディメントなモデル兼データシステムです。その目標は次のとおりです：

1. 単腕・双腕・モバイルマニピュレーションロボット間でデータを共有すること。

2. 言語・視覚観測・ロボット状態・連続アクションをまとめて処理すること。

3. カバーされたタスクを直接実行するか、事後学習を通じて困難／新規タスクを学習すること。

4. 最大 50 Hz で巧みな制御をサポートすること。

![π0 論文ディープダイブ: 5.1 設計目標と構成要素 (画像 15)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-15.png)

| プラットフォームカテゴリ | 画像入力 | 状態／アクション空間 |
|---|---|---|
| 単腕 UR5e | 手首＋肩、2 ビュー | 7D 状態、7D アクション |
| 双腕 UR5e | 3 ビュー | 14D 状態、14D アクション |
| 単腕 Franka | 2 ビュー | 8D 状態、8D アクション |
| 双腕 Trossen | 2 つの手首＋ベース、3 ビュー | 14D 状態、14D アクション |
| 双腕 ARX / AgileX | 2 つの手首＋ベース、3 ビュー | 14D 状態、14D アクション |
| モバイル Trossen / モバイル ARX | 2 つの手首＋ベース、3 ビュー | 14D 状態、16D アクション；非ホロノミックベース制御が 2 次元追加 |
| モバイル Fibocom | 2 本のアーム＋全方向移動ベース | 14D 状態、17D アクション；ベース用に 2 つの並進と 1 つの回転制御 |

**注意:** 運動学的に類似したプラットフォームは構成カテゴリにグループ化されています。7つの構成は7台の物理ロボットを意味するわけでも、OXE に7種類のロボットしかないという意味でもありません。内部の器用操作データは7つの構成をカバーしており、追加された OXE データは22種類のロボットをカバーしています。

### クロスエンボディメントの学習と制御
全体的なワークフローは次のとおりです：

```text
Multi-platform teleoperation + open robot data + internet image-text pre-training
                         ↓
          Weighted cross-embodiment data mixture
                         ↓
      Joint training of PaliGemma + π0 action expert
                         ↓
             Generalist π0 base policy
                  ↙                 ↘
        Direct language prompting        High-quality task post-training
                  ↘                 ↙
           Continuous action chunks across platforms
```

2種類のアラインメントによって、異なるロボットを1つのモデルに適合させます：

- **状態／行動アラインメント:** 最大18次元までパディングします。より小さなロボットは末尾のゼロを使用します。18次元あれば、2つの6自由度アーム、2つのグリッパ、移動ベース、昇降式トルソを収容できます。

- **画像アラインメント:** 3つの画像スロットを確保し、カメラが1台または2台しかないロボットでは存在しないビューをマスクします。

言語ラベルには、完全なタスクと短いセグメントが含まれ、典型的には約2秒です。「ナプキンを拾う」「それをゴミ箱に捨てる」といったセグメント指示により、高レベル VLM がテーブル片付けのような長いタスクを分解し、その間 π0 が物理的な実行を担当できます。

**論文:** サンプル数が $n$ のタスク–ロボットグループには重み $n^{0.43}$ が与えられます。この劣線形の指数により、大量にサンプリングされた洗濯タスクのような非常に大きなグループの支配力が抑えられます。

### センサー、収集方法、および能力
#### データ構成
![π0 論文ディープダイブ: データ構成 (画像 06)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-06.png)

- 内部データは903Mタイムステップを含み、そのうち106Mが単腕ロボット、797Mが両腕ロボットからのものです。

- 68の大まかなタスクと7つのロボット構成をカバーしています。

- オープンデータはミックス全体の9.1%で、OXE、Bridge v2、DROID を含みます。

- オープンデータセットは通常、1台または2台のカメラと 2–10 Hz の制御を持ちますが、物体と環境の多様性は広範です。

- 論文では、ロボットデモンストレーションの合計を1万時間超と要約しています。

- タスクのポストトレーニング時間は、単純なタスクで約5時間から、最も難しいタスクでは100時間以上に及びます。

#### 直接プロンプト
![π0 論文ディープダイブ: 直接プロンプト (画像 03)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-03.png)

論文では、シャツ折りたたみ、簡単および難しいテーブル片付け、食料品の袋詰め、トースターからトーストを取り出すタスクについて、π0、OpenVLA、Octo、および VLM 初期化なしの π0-small を比較しています：

- 70万ステップで学習したフル π0 は、5つすべてのタスクで平均進捗が最も高くなります。

- ベースラインと同程度の更新回数を持つ16万ステップの π0 パリティモデルも、依然としてそれらを上回ります。

- π0-small は通常 OpenVLA と Octo を上回り、連続チャンクアーキテクチャ自体の価値を裏付けています。

- フル π0 は π0-small を大きく上回り、意味理解とタスク間制御における VLM 事前学習の利点を裏付けています。

**注意:** OpenVLA と Octo はフル π0 と同じエポック数では学習されていません。パリティ比較は計算資源の公平性を部分的には扱っていますが、フルモデルの比較は厳密には計算量が一致していません。

#### 新しいタスクでのポストトレーニング
![π0 論文ディープダイブ: 新しいタスクでのポストトレーニング (画像 17)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-17.png)

新しいタスクには、ボウル積み重ね、タオル折りたたみ、食品コンテナを電子レンジに入れること、ペーパータオルロールの交換、Franka での引き出しへの積み込みが含まれます。各手法はタスクごとに10回の試行の平均です：

- π0 は、ゼロからの学習や他の手法と比べて、全体的にも個々のタスクのほとんどでも上回ります。

- 事前学習タスクに類似したタオル折りたたみとボウル積み重ねでは、より少ないデータで大きな進捗に到達します。

- いくつかのタスクでは、事前学習により、ゼロからの学習と比べて性能がほぼ2倍になります。

- 利得はすべてのデータスケールで単調に増加するわけではありません。電子レンジへの積み込みでは、5時間設定はベースラインに近い一方、1時間設定ではより大きな優位性が見られます。

これらのタスクは約5〜20分続き、数十回の把持、積み重ね、塗り広げ、折りたたみ動作を組み合わせます。事前学習とポストトレーニングを組み合わせると、図示されたすべてのタスクで最大スコアの半分を超え、一般にゼロからの学習や事前学習ポリシーの直接使用よりも優れた結果となります。特に難しいタスクで利点が顕著です。

**エビデンスの限界:** すべてのタスクが確実に解けているわけではありません。著者らはまだ、理想的な事前学習ミックスや、新しいタスクにどれだけ、どのような種類のデータが必要かを把握していません。自動運転、ナビゲーション、脚ロボットの運動といった、より遠いドメインへの転移は未検証です。「ジェネラリスト」とは、ここで研究されたタスクとマニピュレーションプラットフォームを指しており、任意のロボットや環境を意味するわけではありません。

## π0: Action Expert と Conditional Flow Matching を備えた VLA
### アクションチャンク化：将来50ステップを生成
π0 は $p(a_t\mid o_t)$ のみではなく、アクションチャンクをモデル化します：

$p(A_t\mid o_t),\qquad A_t=[a_t,a_{t+1},\ldots,a_{t+H-1}],\quad H=50$

チャンク化は次の2つのニーズに対応します：

- **高頻度出力の効率:** 1回の推論で、各アクション次元ごとにトークンを自己回帰的にデコードすることなく、50個の制御点を生成します。

- **軌道の一貫性:** チャンク全体をまとめてモデル化することで、連続アクション間の依存関係を表現します。

$H=1$ では、これは単一ステップ予測に帰着します。大きな $H$ を完全オープンループで実行すると、新しい観測への反応が遅くなります。π0 は $H=50$ を予測しますが、再度観測する前に16または25ステップだけ実行し、推論オーバーヘッドとフィードバック頻度のバランスを取ります。

18次元へのパディングは学習インターフェースです。各ロボットの有効な次元だけが、そのコントローラに送られます。

### Conditional Flow Matching: ノイズから連続アクションへ
![π0 論文ディープダイブ: 6.2 Conditional Flow Matching: ノイズから連続アクションへ (画像 01)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-01-en.png)

### プラットフォーム差を消さない共有インターフェース
ロボットはカメラ数、状態次元数、行動次元数とその意味が異なります。π0 は固定サイズのスロットを使用します：

- 最大3枚の画像で、欠けているビューはマスクされます。

- 状態と行動は18次元までパディングされます。

- 画像、言語、状態、デモンストレーションされた行動に条件付けられた Transformer が、ロボットとタスクの組み合わせ全体にわたる関係を学習します。

これは、行動次元 $i$ がすべてのロボットで同じ物理量を意味することを強制するものではありません。固定インターフェースを提供しつつ、モデルが観測、状態分布、データからプラットフォーム固有の振る舞いを学習します。

2つのエキスパートが異なるモダリティを処理します：

- **VLM バックボーン:** 画像と言語トークンを処理し、PaliGemma のインターネット規模の事前学習を継承します。

- **Action Expert:** ロボット状態 $q_t$ とノイズ付きチャンク $A_t^\tau$ を処理し、連続制御に特化します。

重みは分離されていますが、Transformer の自己注意を通じて情報をやり取りします。これにより、VLM 全体を行動専用ネットワークに変換することなく、行動が言語と画像に依存できるようになります。

### π0 ネットワーク全体像
![π0 論文ディープダイブ: 6.5 π0 ネットワーク全体像 (画像 10)](https://files.seeedstudio.com/wiki/robotics/projects/rebot_arm/paper_reading/pi0/image-10.png)

#### 画像と言語の入力
PaliGemma の SigLIP エンコーダは各 RGB 画像を視覚トークンに変換し、トークナイズされた指示はそれらとともにより大きな VLM エキスパートに入力されます。アーキテクチャ図は、おおよそ4億の SigLIP パラメータと26億の Gemma パラメータを要約しています。

**注意:** PDF には、統一された入力画像解像度や、画像ごとの正確な視覚トークン数は記載されていません。ここでは、一般的な PaliGemma 構成からこれらの次元を推定していません。

#### ロボット状態
状態 $q_t$ は Transformer の埋め込み幅に線形射影され、別個の状態ブロックとして Action Expert に供給されます。

#### ノイズ付きアクションとフロー時間
チャンクには $H=50$ 個のアクショントークンがあります。各ノイズ付きアクション $a_{t'}^\tau$ は、正弦波フロー時間エンコーディング $\phi(\tau)$ とともに MLP を通して結合されます：

$e(a_{t'}^\tau,\tau)=W_3\,\mathrm{swish}\left(
W_2\,\mathrm{concat}(W_1a_{t'}^\tau,\phi(\tau))
\right)$

これらの埋め込みが Action Expert に入力されます。ネットワークは50個のアクション位置出力を読み取り、それらを線形射影してベクトル場 $v_\theta(A_t^\tau,o_t)$ に変換します。

最大のアクションテンソルは $50\times18$ です。各ロボットの有効な次元だけが使用され、パディングはアクチュエータには送られません。

#### デュアルエキスパート Transformer
- PaliGemma バックボーン：約30億パラメータ。

- 追加の Action Expert：約3億。

- 合計：約33億。

- VLM エキスパート：幅2048、18層、MLP 幅16,384。

- Action Expert：幅1024、MLP 幅4096 で、10回の Flow Matching 順伝播のコストを削減します。

エキスパートは別々の重みを使用しますが、そのトークンは各層の自己注意で相互作用します。これは2分岐の Mixture-of-Experts に類似しており、画像／言語トークンは VLM の重みに、状態／行動トークンは Action Expert の重みにルーティングされます。

#### ブロックアテンションマスク
入力シーケンスには3つのブロックがあります：

```text
[Images, language] → [Robot state] → [Noisy action chunk]
```

アテンションは各ブロック内では双方向です。前のブロックは後のブロックを読むことができず、後のブロックは前のコンテキストを読むことができます。これにより、PaliGemma の事前学習分布からの変化が制限され、10回の積分ステップにわたって画像、言語、状態のキー／バリューを固定のままキャッシュし、アクションのサフィックスだけを再計算できるようになります。

#### 学習損失
条件付きフロー・マッチングは、実演されたアクションとノイズから構成されるターゲットベクトル場と、予測されたベクトル場との間の平均二乗誤差を最小化します。これにより、単一の一意なアクションを回帰するのではなく、ノイズからもっともらしい連続アクションの分布への条件付き輸送を学習します。

#### 完全なデータフロー
```text
Training:
Multi-view images + language + robot state + demonstrated 50-step actions
→ Sample ε and τ; construct a noisy chunk
→ Images/language enter the VLM; state/actions enter the action expert
→ Predict the action vector field
→ Compute flow-matching loss against the target field

Inference:
Multi-view images + language + robot state + random action noise
→ Cache the observation prefix
→ Run ten Euler integration steps with the action expert
→ Obtain a 50-step continuous chunk
→ Execute 16 or 25 steps, depending on platform
→ Observe again and generate the next chunk

In one sentence:
PaliGemma interprets what is visible and what the user wants; the expert turns that understanding into continuous high-frequency control.
Chunking provides efficient, coherent trajectories; flow matching models continuous multimodal actions.
Cross-embodiment pre-training supplies broad experience, and high-quality post-training shapes skilled, stable task execution.
```
