Corrigir falha de boot UEFI do JetPack 5.1.3 no Jetson

Problema​

Problema de UEFI da NVIDIA upstream

Essa falha de boot é causada por um bug de firmware UEFI upstream da NVIDIA que afeta o JetPack 5.1.3 e versões anteriores. Ela não é causada pelo hardware do produto Seeed ou pelo design da placa-carregadora. Este FAQ fornece correções para os dispositivos Seeed afetados listados abaixo.

Nos produtos listados abaixo, o JetPack 5.1.3 (Jetson Linux 35.5.0) pode parar de inicializar após ciclos de inicialização repetidos. Discussões no fórum da NVIDIA relatam falhas de boot relacionadas no Orin e corrupção da partição OP-TEE:

  • Orin NX fails to boot: corrupted OP-TEE partition
  • Orin on JetPack 5.1.3

Este problema se aplica a estas famílias de produtos executando L4T 35.5.0:

  • reComputer Classic J40/J30, incluindo variantes B
  • reComputer Industrial J40/J30
  • reServer Industrial J40/J30

Escolha uma das seguintes correções. Se o dispositivo não conseguir inicializar no Ubuntu, use a Opção 1. Se ele conseguir inicializar no espaço de usuário do Ubuntu, a Opção 2 evita o flash a partir de um PC host.

Opção 1: Regravar o pacote QSPI MFI corrigido​

Isso atualiza o bootloader corrigido no QSPI e preserva os dados do usuário armazenados no SSD. Baixe o pacote QSPI-only MFI corrigido para o seu dispositivo exato nas abas abaixo. A preparação do host, as instruções de modo de recuperação e o comando de flash seguem o resumo de gravação do JetPack.

Todos os pacotes abaixo são para JetPack 5.1.3 / L4T 35.5.0. Combine tanto a família de produtos quanto o módulo Jetson antes de baixar. Os pacotes Classic também suportam as variantes B correspondentes.

Preparar o host e entrar no modo de recuperação​

Instale as dependências do host listadas nesse guia antes de fazer o flash. Use o pacote QSPI-only corrigido baixado acima para a etapa de gravação.

Extrair e gravar​

No PC host, extraia o arquivo compactado QSPI MFI corrigido baixado. Substitua <patched-qspi-mfi-archive> pelo nome real do arquivo e <extracted-mfi-directory> pelo diretório extraído que contém tools/kernel_flash/l4t_initrd_flash.sh.

sudo tar xpf <patched-qspi-mfi-archive>
cd <extracted-mfi-directory>
sudo ./tools/kernel_flash/l4t_initrd_flash.sh --flash-only --massflash 1 --network usb0 --showlogs

Aguarde a conclusão bem-sucedida da gravação, depois reinicie o Jetson e confirme que ele inicializa a partir do SSD existente.

Opção 2: Atualizar o bootloader a partir do espaço de usuário do Ubuntu​

Use esta opção quando o Jetson ainda inicializa no Ubuntu. Ela instala o pacote de bootloader fornecido no dispositivo e não requer regravação do sistema.

  1. Baixe o pacote de bootloader reComputer Orin no Jetson.

  2. Em um terminal, vá para o diretório que contém o arquivo baixado e instale-o:

    sudo dpkg -i ./nvidia-l4t-bootloader-recomputer-orin_35.5.0-recomputer20261110.1_arm64.deb

  3. Confirme se a versão esperada do pacote de bootloader está instalada:

    sudo dpkg -l | grep nvidia-l4t-bootloader

    A saída deve incluir este pacote e versão:

    nvidia-l4t-bootloader-recomputer-orin  35.5.0-recomputer20261110.1  arm64

  4. Reinicie o Jetson e confirme que ele inicia normalmente.
