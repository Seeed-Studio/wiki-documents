Usar câmeras GMSL da série ZED X com reComputer Robotics

Seeed Studio × Stereolabs

Visão de profundidade ZED X, pronta para reComputer Robotics

Leve visão estéreo GMSL2 robusta e de longo alcance para robôs compactos, máquinas autônomas e sistemas de IA física. As plataformas reComputer Robotics da Seeed Studio combinam computação NVIDIA Jetson, I/O pronto para robótica e conectividade GMSL escalável em um hardware pronto para implantação.

Jetson Orin & ThorAté 8 câmeras GMSL2JetPack 6.2 & 7.2Pré-visualização de profundidade no ZED Studio

Este guia explica como usar câmeras GMSL2 da série ZED X da Stereolabs com o hardware de robótica da Seeed Studio. As instruções de configuração estão disponíveis para reComputer Robotics J50 Mini, J50 (J501) e J40 (J401). Recursos de driver específicos para o J601 estão sendo preparados.

reComputer Robotics J50 Mini​

O que você precisa​

  • reComputer Robotics J50 Mini com a placa de extensão GMSL
  • Uma câmera ZED X-series GMSL2 compatível
  • Um cabo ou chicote GMSL2 Fakra/Mini-Fakra compatível
  • JetPack 6.2.x ou JetPack 7.2
  • Acesso à Internet, um monitor, teclado e mouse para o ZED Studio
info

Este guia abrange a configuração do driver da plataforma Seeed e do ZED SDK. A compatibilidade do modelo de câmera pode depender da versão do ZED SDK instalada. Use o ZED SDK mais recente compatível com a sua versão JetPack/L4T.

1. Conectar a câmera​

  1. Desligue completamente o reComputer.
  2. Desconecte a entrada de alimentação DC.
  3. Conecte a câmera ZED X a uma porta GMSL2 usando o cabo ou chicote compatível. Certifique-se de que o conector esteja totalmente encaixado e travado.
  4. Reconecte a alimentação e inicialize o dispositivo.
atenção

Não conecte ou desconecte a câmera GMSL com o sistema ligado (hot-plug). Sempre remova a alimentação antes de conectar ou desconectar a câmera ou o chicote GMSL.

2. Ativar o suporte a ZED X GMSL​

Escolha um dos caminhos a seguir. Gravar o BSP mais recente é recomendado para uma implantação limpa; instalar o DEB é mais rápido quando você deseja manter um sistema existente.

  • Opção 1 · Gravar BSP mais recente
  • Opção 2 · Instalar DEB

Verifique as informações da compilação do BSP já instalado no dispositivo:

cat /etc/nv_tegra_release

Procure pelo campo DATE. Se o BSP tiver sido compilado em 24 de setembro de 2026 ou depois, o suporte a ZED X GMSL já está incluído e você pode continuar para a instalação do ZED SDK.

Se a compilação for mais antiga, grave a imagem mais recente JetPack 7.2 / L4T 39.2.0 datada de 24 de setembro de 2026 seguindo as etapas abaixo. As duas variantes de módulo usam imagens diferentes, então selecione a aba que corresponde ao módulo Jetson instalado no seu J50 Mini.

atenção

A gravação reescreve o armazenamento de destino. Faça backup dos dados de aplicativos, arquivos de configuração e credenciais antes de começar.

Preparar o host e baixar a imagem​

Prepare um computador host físico com Ubuntu 20.04, 22.04 ou 24.04, um cabo de dados USB Tipo C e o J50 Mini com seu SSD NVMe instalado. Baixe a imagem que corresponde ao seu módulo diretamente no host Ubuntu:

  • AGX Orin 64GB
  • AGX Orin 32GB

  2. Pressione e segure o botão REC.
  1. Conecte o cabo de alimentação e então solte o botão REC.
  2. Conecte o J50 Mini ao host Ubuntu com um cabo de dados USB Tipo C através da porta de gravação mostrada abaixo.
  1. No host Ubuntu, verifique o modo de recuperação:

Primeiro, identifique a versão do Jetson Linux instalada:

3. Instalar o ZED SDK​

Acesse a página de download do Stereolabs ZED SDK e selecione o instalador NVIDIA Jetson que corresponde à versão informada por cat /etc/nv_tegra_release:

sudo apt update

cd ~/Downloads

Siga as instruções do instalador e mantenha as ferramentas ZED selecionadas. Reinicie após a conclusão da instalação:

reComputer Robotics J50 (J501)​

Use esta seção para o reComputer Robotics J501 com a placa de extensão GMSL e uma câmera compatível da série ZED X. As duas opções de configuração são: gravar um BSP com suporte a ZED X GMSL ou manter o sistema atual e instalar o driver DEB correspondente. Consulte o guia de hardware e primeiros passos do J501 para o layout da placa e instruções completas de gravação.

1. Conectar a câmera​

Desligue o J501 e desconecte a alimentação DC. Conecte a câmera a uma porta GMSL2 com um cabo Fakra/Mini-Fakra compatível, trave o conector e então reconecte a alimentação e inicialize o dispositivo.

2. Ativar o suporte a ZED X GMSL​

Escolha uma opção. Grave o BSP para uma instalação limpa do JetPack 7.2; instale o DEB para manter um sistema JetPack 6.2.1 ou 7.2 já suportado.

  • Opção 1 · Gravar BSP do JetPack 7.2
  • Opção 2 · Instalar driver DEB

Os pacotes BSP JetPack 7.2 / L4T 39.2.0 abaixo incluem suporte a ZED X GMSL. Selecione a imagem que corresponde ao módulo AGX Orin instalado no Robotics J501:

Modelo Robotics J501Módulo JetsonBSP
J5011AGX Orin 32GBDownload J5011 BSP
J5012AGX Orin 64GBDownload J5012 BSP
atenção

A gravação apaga os dados no SSD NVMe de destino. Faça backup dos dados importantes antes de começar e mantenha a alimentação e o USB conectados até a conclusão da gravação. Use a Opção 2 se quiser manter o sistema atual.

Preparar o host e o J501​

Prepare o seguinte equipamento:

  • reComputer Robotics J501 com o módulo AGX Orin correspondente
  • SSD NVMe instalado no J501
  • PC host físico com Ubuntu 20.04, 22.04 ou 24.04
  • Cabo USB Tipo-C para transmissão de dados
  • Monitor, teclado e mouse para a configuração do primeiro boot

Recomendamos um host Ubuntu físico em vez de uma máquina virtual. Para o JetPack 7.2, o Ubuntu 24.04 oferece suporte à gravação e à instalação de componentes no alvo; use Ubuntu 20.04 ou 22.04 se você precisar de componentes de desenvolvimento no host.

Baixe o BSP para o módulo do seu J501 no host Ubuntu. O arquivo compactado é grande e pode levar cerca de 60 minutos para baixar; aguarde o término do download antes de extraí-lo.

Entrar no modo Force Recovery​

  1. Desligue o J501. Conecte um cabo USB Tipo-C para dados entre o PC host e a porta USB 2.0 DEVICE do J501.
  2. Use um pino para pressionar e manter pressionado o botão RECOVERY.
  1. Mantendo o RECOVERY pressionado, conecte a fonte de alimentação do J501.
  2. Solte o RECOVERY.
  3. No host Ubuntu, execute lsusb para verificar se o J501 entrou no modo force recovery:
Módulo J501ID lsusb esperado
AGX Orin 32GB (J5011)0955:7223 NVidia Corp.
AGX Orin 64GB (J5012)0955:7023 NVidia Corp.

Se o ID esperado não aparecer, verifique se você usou a porta USB DEVICE e um cabo com suporte a dados e repita os passos de recuperação.

Extrair e gravar o BSP​

No host Ubuntu, extraia o arquivo específico do módulo que foi baixado. Substitua o placeholder pelo nome exato do arquivo baixado acima:

cd ~/Downloads
sudo tar xpf <downloaded-J501-BSP>.tar.gz

Acesse o diretório BSP extraído. Use ls -d mfi_* para identificar o nome, se necessário:

cd <extracted-J501-BSP-directory>

Com o J501 ainda conectado em modo force recovery, grave o JetPack no SSD NVMe:

sudo ./tools/kernel_flash/l4t_initrd_flash.sh \
  --flash-only --massflash 1 --network usb0 --showlogs

O comando de gravação geralmente leva de 2 a 10 minutos. Uma gravação bem-sucedida termina com a mensagem de conclusão mostrada abaixo:

Após a gravação, desconecte o cabo USB e desligue e ligue novamente o J501. Conecte-o a um monitor usando um adaptador PD-para-HDMI ou use um monitor que aceite vídeo USB-C/PD diretamente e então conclua a configuração inicial do Ubuntu:

Conclua a Configuração do sistema conforme necessário. Este BSP já inclui o driver ZED X GMSL para o Robotics J501, portanto prossiga diretamente para 3. Instalar o ZED SDK.

Use esta opção para manter o sistema existente. Primeiro verifique a versão instalada do Jetson Linux:

cat /etc/nv_tegra_release

Escolha o pacote Robotics J501 para a versão L4T informada. Não use o pacote J501 Mini; as placas carrier Robotics e Mini usam device-tree overlays diferentes.

  • JetPack 6.2.1 / L4T 36.4.4
  • JetPack 7.2 / L4T 39.2.0
Download J501 JetPack 6.2.1 DEB ↗
cd ~/Downloads

reComputer Robotics J40 (J401)​

Esta seção abrange as placas carrier Robotics J401 com módulos J3010 / J3011 (Orin Nano) ou J4011 / J4012 (Orin NX) e a placa de extensão GMSL. Use uma câmera GMSL2 ZED X-series compatível e um cabo Fakra/Mini-Fakra adequado. O guia da placa carrier Robotics J401 fornece o layout da placa e detalhes das interfaces.

1. Conectar a câmera​

  1. Desligue o reComputer e desconecte a alimentação DC.
  2. Conecte a câmera ZED X a uma porta GMSL2 na placa de extensão. Encaixe totalmente e trave o conector.
  3. Reconecte a alimentação e inicialize o dispositivo.
atenção

Desligue o equipamento antes de conectar ou desconectar a câmera ou o chicote GMSL.

2. Ativar o suporte ZED X GMSL​

Escolha uma opção: grave um BSP com o driver ZED X GMSL incluído ou instale o DEB correspondente para manter o sistema existente.

  • Opção 1 · Gravar Robotics J401 BSP
  • Opção 2 · Instalar driver DEB
Prepare o host e o hardware​

Prepare os seguintes equipamentos:

  • Placa carrier Robotics J401 com um módulo Orin Nano 4GB/8GB ou Orin NX 8GB/16GB e refrigeração ativa
  • SSD NVMe M.2 2280 instalado na placa
  • PC host com Ubuntu e um cabo de transmissão de dados USB Type-C
  • Fonte de alimentação, monitor, teclado e mouse para a configuração da primeira inicialização

Use um host físico com Ubuntu. Selecione a versão do Ubuntu de acordo com a versão do JetPack no BSP baixado:

Versão do BSP JetPackHost Ubuntu 20.04Host Ubuntu 22.04Host Ubuntu 24.04
JetPack 6.xSuportadoSuportado—
JetPack 7.2SuportadoSuportadoSuportado para gravação e instalação de componentes no alvo

Para componentes de desenvolvimento de host JetPack 7.2, use Ubuntu 20.04 ou 22.04.

atenção

Solução de problemas​

  • Câmera não detectada: Confirme que o DEB, o BSP e o ZED SDK correspondem à versão L4T instalada. Em seguida, desligue e reconecte o cabo da câmera.
  • APT relata incompatibilidade de pacote: Não force a instalação. Baixe o pacote para a versão L4T exibida por cat /etc/nv_tegra_release.
  • ZED Studio não abre: Confirme que a área de trabalho gráfica está em execução e inicie /usr/local/zed/tools/ZED_Studio a partir de um terminal para ver a saída de erro.
  • A imagem aparece, mas a profundidade não está disponível: Confirme que você instalou o ZED SDK completo com ferramentas e que o modelo de câmera selecionado é suportado por essa versão do SDK.
  • Vídeo intermitente: Desligue e verifique o cabo Fakra/Mini-Fakra, a posição de travamento e o comprimento de cabo suportado antes de testar novamente.
