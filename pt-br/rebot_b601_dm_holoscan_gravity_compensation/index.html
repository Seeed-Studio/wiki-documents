reBot-DM Holoscan5 Gravity Compensation

Adquira agora

Taxa alvo de 400 Hz · Dinâmica Pinocchio · Análise de latência com Nsight Systems

Este tutorial usa o NVIDIA Holoscan 5 para executar um loop de controle de três estágios. O loop lê os ângulos atuais das juntas, usa o Pinocchio e o modelo do robô para calcular o torque necessário para contrabalançar a gravidade e, em seguida, envia comandos para os motores. O Holoscan agenda o loop com uma taxa alvo de 400 Hz e executa todos os três estágios em uma única thread para reduzir a latência e o jitter causados pela troca de threads.

Com a compensação de gravidade ativada, os motores ajustam seu torque conforme a pose muda e suportam o peso do reBot Arm B601-DM. Como resultado, é necessário menos esforço para guiar o braço manualmente. NVIDIA Technical Blog

Pré-requisitos​

ItemRequisito
Braço robóticoreBot Arm B601-DM com motores Damiao e o gripper instalado
ConectividadeFonte de alimentação do B601-DM, placa controladora USB-para-CAN e um cabo de dados USB
HostUbuntu 24.04 x86_64 com acesso à internet para baixar o código-fonte e as dependências
RuntimePython 3.12, Holoscan 5.0.0 e um driver NVIDIA compatível com CUDA 13

Se o braço ainda não estiver montado, siga o guia de início rápido para fixar a base, concluir a fiação e verificar os IDs dos motores e as posições zero das juntas. Desligue a alimentação antes de conectar ou desconectar a alimentação ou o chicote CAN. B601-DM Quick Start

Verifique o sistema e o driver no host.

uname -m
getconf GNU_LIBC_VERSION
nvidia-smi

Espere x86_64, glibc 2.39 ou posterior e saída do nvidia-smi que liste sua GPU. A NVIDIA especifica um driver R580 ou posterior compatível com CUDA 13 para o Holoscan 5. Se o driver estiver ausente ou for muito antigo, use o utilitário Drivers Adicionais do Ubuntu ou sudo ubuntu-drivers list para encontrar um branch de driver para o seu hardware. Siga o guia de instalação do Ubuntu, reinicie e verifique novamente. No Jetson, primeiro verifique a versão correspondente do JetPack SDK. Requisitos de instalação do Holoscan SDK · Instalando drivers NVIDIA no Ubuntu

dica

O Ubuntu 22.04 é fornecido com glibc 2.35. Mesmo com o Python 3.12 instalado no Conda, execute o Holoscan 5 em um host ou em um contêiner que atenda ao requisito de glibc. Os comandos neste guia usam o ambiente Python nativo do Ubuntu 24.04. Requisitos do wheel do Holoscan

Executar a compensação de gravidade​

1

Configure o ambiente e verifique o grafo de controle​

Baixe o exemplo da NVIDIA em Bash. Use a revisão fixada para que os comandos, a configuração e os testes abaixo correspondam ao código-fonte.

sudo apt update
sudo apt install -y ca-certificates git nano python3.12-venv libgl1 libglib2.0-0t64 libgomp1 psmisc

git clone https://github.com/nvidia-holoscan/holoscan-tutorials.git
cd holoscan-tutorials
git checkout --detach e79b1a662f358dca734d8a4426c0aeb60699e264
cd tutorials/rebot-gravity-compensation

Escolha uma forma de criar um ambiente Python 3.12.

  • Python venv
  • Conda
python3.12 -m venv .venv
source .venv/bin/activate

Se você já tiver o Conda, crie um ambiente dedicado. Você pode escolher um nome de ambiente diferente. Guia de instalação do Conda

conda create -n holoscan-rebot python=3.12 pip -y
conda activate holoscan-rebot

Permaneça no diretório do exemplo com o seu ambiente ativo. Baixe o modelo e instale as dependências do exemplo.

python --version
python scripts/fetch-urdf.py
test -s urdf/DM/urdf/ReBot_Arm_DM.urdf

python -m pip install --only-binary=:all: -r requirements-python.txt \
  'holoscan==5.0.0' 'nvidia-cuda-runtime==13.0.96'
python -m pip check

O script de download obtém o URDF de uma revisão fixada da Seeed Studio, verifica o arquivo-fonte e preserva os dados de dinâmica. O arquivo de requisitos instala Pinocchio 3.9.0 e motorbridge 0.5.0. O pacote pip do Pinocchio é pin, e o nome de importação em Python é pinocchio. Código-fonte oficial do exemplo e dependências

O grafo de controle é executado na CPU, e importar o Holoscan ainda carrega o runtime CUDA. Esses comandos adicionam as bibliotecas compartilhadas do wheel ao caminho de busca de bibliotecas do terminal atual. Sempre que você abrir um novo terminal, volte ao diretório do exemplo, reative seu ambiente e execute esses comandos novamente. Bibliotecas de runtime do wheel do Holoscan

CUDA_LIB_DIR="$(python - <<'PY'
from importlib.metadata import distribution

runtime = distribution("nvidia-cuda-runtime")
library = next(file for file in runtime.files if file.name == "libcudart.so.13")
print(runtime.locate_file(library).parent)
PY
)"
test -n "$CUDA_LIB_DIR" && export LD_LIBRARY_PATH="$CUDA_LIB_DIR${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
python python/gravity_compensation.py --help

Antes de conectar o braço, você pode carregar o modelo e compilar o grafo de controle. Essa verificação inicializa o modelo e compila o grafo sem abrir a porta serial ou ativar os motores.

PYTHONPATH=python python - <<'PY'
import holoscan as hsdk
from gravity_compensation import build_graph, load_configuration
from rebot_gravity import GravityCompensation
from rebot_robot import Robot

config, params = load_configuration("config/rebotarm_dm.yaml")
controller = GravityCompensation(config, params)
controller.initialize()
plan = hsdk.compile(build_graph(Robot(config), controller), hsdk.CompileOptions())
if not plan:
    raise SystemExit(plan.summary())
print(f"URDF loaded: nq={controller.model.nq}, nv={controller.model.nv}")
print("Control graph compiled successfully.")
PY

Espere nq=8, nv=8 e uma mensagem de compilação bem-sucedida. O modelo tem seis coordenadas do braço e duas coordenadas dos dedos. O braço físico tem sete motores. Para uma verificação de regressão de software mais completa, execute os testes de motores falsos mais adiante neste guia.

2

Conecte o braço e configure a porta serial​

Certifique-se de que a base esteja firme, conecte o cabo de dados USB e ligue o braço. Execute o seguinte comando para conceder acesso de leitura e escrita aos dispositivos seriais.

sudo chmod 666 /dev/ttyACM*

Copie a configuração oficial e edite channel na cópia. Substitua o caminho de exemplo pela sua porta serial real.

cp config/rebotarm_dm.yaml config/rebotarm_local.yaml
nano config/rebotarm_local.yaml
channel: "/dev/ttyACM0"
ConfiguraçãoValor do exemplo oficial
IDs dos motores e IDs de feedback1–7 e 17–23, respectivamente, em decimal
Modelos dos motores4340P para joint1–joint3, e 4310 para joint4–joint6 e o gripper
Taxa de baud serial921600
Ganhos do braçokp: 1.5 e kd: 1.0
Escala de torque de gravidade e direção das juntastau_scale e joint_direction são ambos 1 por padrão para todas as seis juntas do braço
Watchdog de comando100 ms

Mantenha os ganhos, direções e escalas oficiais para a primeira execução. Se os IDs dos motores, orientações de montagem ou posições zero das juntas forem diferentes do hardware real, verifique-os primeiro em relação ao guia de início rápido. Se você alterar a orientação da base ou adicionar uma carga útil, use um modelo de dinâmica que considere a mudança. Configuração oficial dos motores

3

Inicie, verifique e pare o controlador​

atenção

O comando de início ativa os motores físicos. Remova qualquer carga útil extra, libere a faixa de movimento e coloque o braço em uma posição em que ele permaneça apoiado se o torque for perdido. Certifique-se de que alguém no local possa cortar a alimentação prontamente. Uma falha também pode fazer com que o controlador remova o torque de suporte.

Execute os comandos no mesmo ambiente. Certifique-se de que o controlador tenha acesso exclusivo à porta serial.

unset MOTORBRIDGE_LIB
python python/gravity_compensation.py config/rebotarm_local.yaml

O programa verifica o modelo, a pose atual e o estado do motor, depois configura o watchdog e começa a enviar comandos. Quando você vir a mensagem abaixo, guie lentamente o braço por um pequeno movimento. Verifique se ele sustenta seu próprio peso e se move com a sua mão. Se ele reagir com força perceptível, cair, oscilar ou relatar um erro de motor, dê suporte ao braço e pare o controlador antes de iniciar a solução de problemas.

Gravity compensation active.

Para desligar normalmente, primeiro guie o braço de volta para uma posição apoiada e depois pressione Ctrl+C. O programa tenta desativar os motores ao encerrar, o que remove o torque de sustentação. Em uma saída normal, o terminal mostra uma mensagem de parada e a contagem de lotes de comandos.

Como o loop de controle funciona​

OperadorFunção
joint_feedbackExecuta em um agendamento de 2,5 ms e lê posições das juntas, velocidades e status dos motores
gravityCalcula o torque de gravidade feedforward a partir do URDF e dos ângulos atuais das juntas e gera parâmetros de rigidez e amortecimento
motor_commandsValida comandos e envia comandos de controle MIT para todos os sete motores por meio do motorbridge

Os três operadores são executados em sequência na mesma partição control do Holoscan. Cada fila entre operadores mantém uma mensagem pendente. O Pinocchio calcula o termo de gravidade como g(q) = RNEA(q, 0, 0). A meta de agendamento é 400 Hz. Use o Nsight Systems para medir o intervalo real entre iterações.

O watchdog verifica lotes de comandos atrasados. O motorbridge retorna feedback em cache. Se o feedback do motor parar enquanto ainda for possível enviar comandos, o exemplo pode continuar a ler valores obsoletos. Peça para alguém monitorar o braço localmente durante os testes de hardware. Guia técnico oficial

Testes opcionais com motores falsos​

As duas suítes de teste oficiais cobrem torque de gravidade, o grafo de controle, desligamento em caso de falha e manutenção de ponto cartesiano. Pare o controlador de hardware antes de executar os comandos a seguir. Você pode desconectar o cabo USB do braço para esses testes. Execute-os a partir do diretório do exemplo com o ambiente ativo. Os comandos compilam a biblioteca de motor falso usada pelos testes sem exigir o SDK em C++.

sudo apt install -y curl g++
mkdir -p build/wiki-test

curl -fL \
  https://raw.githubusercontent.com/motorbridge/motorbridge/082cbb8c36dfdc8fbf9baa4cc02c5992ab0dc2ad/motor_abi/include/motor_abi.h \
  -o build/wiki-test/motor_abi.h

g++ -std=c++20 -shared -fPIC -I build/wiki-test tests/fake_motor_abi.cpp \
  -o build/wiki-test/librebot_fake_motor_abi.so

REBOT_FAKE_ABI="$PWD/build/wiki-test/librebot_fake_motor_abi.so"
REBOT_TEST_MOTOR_LIBRARY="$REBOT_FAKE_ABI" python tests/test_python_gravity.py
REBOT_TEST_MOTOR_LIBRARY="$REBOT_FAKE_ABI" python tests/test_python_cartesian.py

Na revisão fixada, espere 20 testes na primeira suíte e 15 na segunda, cada um terminando com OK. Os testes de injeção de falhas produzem logs de erro esperados. A aprovação desses testes verifica o caminho de software. Siga as Etapas 2 e 3 para verificar a fiação, direções dos motores, posições zero das juntas e comportamento no braço físico.

Comparação opcional de fixação de CPU com Nsight Systems​

Instale o Nsight Systems e execute nsys --version para verificar se a CLI está disponível. As duas execuções de perfil dirigem o braço físico. Execute-as uma de cada vez e confirme que o processo anterior foi encerrado antes de iniciar outro. Ao final de cada execução, retorne o braço para uma posição apoiada antes de pressionar Ctrl+C. Download do Nsight Systems

Primeiro, capture uma execução com o agendamento padrão e sem fixação de CPU.

mkdir -p build/profiles
nsys profile --trace=nvtx --sample=none --backtrace=none --cpuctxsw=none \
  --output=build/profiles/gravity-unpinned \
  python python/gravity_compensation.py config/rebotarm_local.yaml

Em seguida, verifique quais CPUs lógicas estão disponíveis e escolha um número de CPU permitido. O valor 2 abaixo é um exemplo.

lscpu -e=CPU,CORE,SOCKET,NODE
taskset -pc $$
REBOT_CPU=2
nsys profile --trace=nvtx --sample=none --backtrace=none --cpuctxsw=none \
  --output=build/profiles/gravity-pinned \
  python python/gravity_compensation.py config/rebotarm_local.yaml --cpu "$REBOT_CPU"

Inspecione ambos os relatórios. Use novos nomes de arquivo de saída para execuções repetidas.

nsys stats --report nvtx_sum build/profiles/gravity-unpinned.nsys-rep
nsys stats --report nvtx_sum build/profiles/gravity-pinned.nsys-rep

Abra os relatórios .nsys-rep na interface gráfica do Nsight Systems e inspecione os intervalos NVTX dos três operadores na linha do tempo. Mantenha a pose do braço, a duração da captura e a carga do host o mais consistentes possível entre as duas execuções.

MétricaComo medi-la
Duração do operadorVerifique as estatísticas para o intervalo NVTX correspondente em nvtx_sum.
Intervalo do loop e jitterCompare timestamps de entrada sucessivos de joint_feedback. O intervalo alvo é 2,5 ms.
Latência dentro do grafoUse marcadores de mensagem para corresponder eventos da mesma iteração e, em seguida, meça da entrada em joint_feedback até a entrada em motor_commands. Meça a transmissão serial separadamente.

Para análise em lote, exporte o relatório para SQLite. Execute nsys export --help para verificar a presença de --include-blobs. Se a opção estiver ausente, atualize o Nsight Systems antes de exportar cargas úteis de mensagens estruturadas. Para corresponder eventos de publicação e recebimento na mesma aresta, use source_identity e sequence. Em seguida, siga a entrada e a saída do operador para rastrear a mesma iteração de controle. Anotações NVTX do Holoscan

nsys export --type sqlite --include-blobs=true \
  -o build/profiles/gravity-pinned.sqlite build/profiles/gravity-pinned.nsys-rep

--cpu define afinidade apenas para a thread de controle. A NVIDIA também isolou um núcleo físico e seu SMT sibling, descartou os primeiros 10 segundos como aquecimento e manteve mais de um milhão de iterações por execução. Registre sua própria contagem de amostras, topologia de CPU e configurações de isolamento ao reproduzir o experimento. Use um rastreamento curto para inspecionar o comportamento do grafo e uma amostra suficientemente grande para percentis de latência de cauda. Condições de benchmark da NVIDIA · Guia de correlação de mensagens

Comparação opcional em C++​

Instale o Holoscan SDK 5.0 com seus componentes de desenvolvimento, um compilador C++20, CMake 4 ou posterior, Ninja, Rust/Cargo e Python 3.12. A NVIDIA usou o build 5.0.0.7 do SDK para este exemplo. Guia de instalação do SDK · Instruções de compilação do exemplo em C++

Execute estes comandos a partir do diretório do exemplo. Se você já verificou que o arquivo de modelo existe, pule a primeira linha.

python3.12 scripts/fetch-urdf.py
./scripts/bootstrap-deps.sh
cmake --preset default
cmake --build --preset default
ctest --preset default

Depois que os testes forem aprovados, use as Etapas 2 e 3 para verificar o hardware e a pose inicial. Em seguida, use o comando a seguir no lugar do comando de inicialização em Python. Para fazer o perfil de C++ com o Nsight Systems, altere o executável e o nome de saída nos comandos de perfil. Mantenha a configuração serial e as condições de comparação iguais.

./build/rebot_gravity_compensation config/rebotarm_local.yaml

Solução de problemas​

SintomaO que verificar
o pip não encontra o wheel do HoloscanVerifique python --version, uname - m e getconf GNU_LIBC_VERSION, depois use uma versão de Python e um sistema compatíveis.
libcudart.so.13 está ausenteVerifique se o wheel do runtime CUDA está instalado no ambiente Python ativo e defina LD_LIBRARY_PATH novamente.
libcuda.so.1 está ausenteVerifique o driver NVIDIA do host e a saída de nvidia-smi. O wheel do runtime CUDA não inclui o driver do host.
O URDF está ausente ou o Pinocchio falha ao importarExecute novamente o script de download do modelo a partir do diretório do exemplo. Verifique a versão de pin e o caminho de importação no ambiente ativo. Evite carregar extensões ROS de um ambiente Python diferente.
A porta serial falha ao abrir ou está ocupadaVerifique o cabo de dados USB, o caminho de channel e as permissões da porta serial. Use fuser -v /dev/ttyACM0 com o caminho real do seu dispositivo para identificar o processo que está usando a porta e, em seguida, pare-o a partir de seu terminal original.
Um motor para de relatar feedback ou relata uma falhaPrimeiro, dê suporte ao braço e pare o controlador. Verifique os IDs dos motores, a fonte de alimentação, a fiação e as instruções de firmware. Salve o erro completo e o número da junta e mantenha o watchdog ativado.
O braço cai, reage com força ou oscilaPrimeiro, dê suporte ao braço e pare o controlador. Verifique a orientação da base, as posições zero das juntas, o modelo e a carga útil.
O grafo falha ao compilar ou iniciar com uma CPU especificadaExecute taskset -pc $$ para verificar quais CPUs são permitidas ou remova --cpu para restaurar o agendamento padrão.
