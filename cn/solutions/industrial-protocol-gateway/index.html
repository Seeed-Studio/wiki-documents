工业多协议数据中枢：选型、部署与实测数据

使用须知

这是协议融合与数据中枢层，不是经过认证的控制或计量系统。

这套方案是干什么的​

做楼宇、能源或设备管理方案的集成商到了现场，会发现数据本来就有——只是分别待在 OPC UA 控制器、Modbus 电表、BACnet/IP 空调机组和 MQTT 传感器网关后面，四套寻址方式、四种故障表现。这个方案把四者放进同一台 边缘主机上的同一张点位注册表，对上层只给一套 MQTT 读写契约。换到新现场时，重新接控制器、映射点位即可， 协议适配层不用改。

部署容器、添加数据源、让自动发现给出候选、确认需要的点位、核对数据质量，然后把它们提供出去——本地 1883 端口、北向到云端 Broker 的 8883 端口，或者两者都要。

  • 选型与部署：可部署方案页

  • 现有设备直接接入

    已支持 OPC UA、Modbus、BACnet/IP 或 MQTT 的设备不用替换，进同一台边缘主机上的同一张点位注册表，对上层只有一套 MQTT 读写契约。

  • 自动发现，确认后受管

    OPC UA 浏览、Modbus 站号扫描、BACnet Who-Is、MQTT 主题观察给出候选点位，确认后才成为受管点位；发现不全时可以手工填写。

  • 2,000 点位、349.99 events/s

    4 个数据源各 500 点，采集周期 5/10 秒，在 reComputer R2000 系列上本机回环实测一次 180 秒。

  • 北向断网可补传

    云端 Broker 断网 300 秒期间事件写入本地缓存；重连后持久化 Broker 下补传完整率 1.000，内存 Broker 为 0.9839。

点位页是全部受管点位的总表，逐点显示数据质量，支持筛选与控制：

数据服务页配置内置 Broker，并展示它发布的主题契约：

以上截图为控制台连接协议模拟器与测试从站时的运行界面。现场开通后，受管点位与实时遥测将按实际配置的控制器点表刷新。

网关采用标准工业 DIN 导轨外壳，设备进场后可直接卡装在控制柜 35mm 导轨上，配合 24V 工业开关电源与屏蔽双绞线完成就地接入。

需要哪些硬件​

两样东西：现场已经装好的设备，以及一台能访问它们各自网络的主机。

① 现场设备 —— 凡是已经支持 OPC UA、Modbus（TCP 或 RTU）、BACnet/IP 或 MQTT 的设备都算，机组侧 不做替换。按数据源你必须先有：OPC UA 的服务地址与凭据；Modbus 的从站地址、寄存器映射、字节序与字序； 一块位于 BACnet 网段、广播能到达的网卡；MQTT 作为数据源时，明确的主题到点位映射。Modbus RTU 另需一个 USB 转 RS-485 适配器，除非主机自带 RS-485。

② 数据中枢主机 —— 一台普通 Docker 主机，x86-64 或 arm64。它决定你不加适配器就能拿到哪些现场接口， 以及现场没有电脑时能不能操作：

主机板载现场接口什么时候选它
reComputer R1000 系列
基于 CM4 的物联网网关		RS-485、RJ45 以太网现场设备都在以太网上，最多一路 RS-485
reComputer R1100 系列
基于 CM4 的物联网网关与控制器		RS-485、RS-232、DI/DO、千兆以太网、CAN现场还有 RS-232 设备或 DI/DO 干接点
reTerminal DM 系列
10.1 寸 HMI，跑同一套服务		RS-485、CAN、以太网（CM4104032 型号另有 RS-232、DI/DO、接线端子）机房没有常驻电脑，配置与巡检要在设备上完成

三台机器的软件点位上限相同：2,000 个点位，其中 50 个可写，由代码强制。2,000 点负载在 R1000 同代的 CM4 级平台（2 GB 配置，在开发板上测）上未通过容量测试，到这个规模选 R1100 或 reTerminal DM；R1000 用于更小规模时，可承载的点位数暂无实测数据。eMMC 容量决定本机保留多少北向断网缓存与命令回执历史；服务本身约需 4 GB 可用磁盘。

其他前置条件：Docker Engine 20.10 及以上，8280 与 1883 端口空闲（或在部署前另选未占用端口），以及主机 到各协议网络的可达性。

选型排他边界​

  • 现场接口与点位数：若现场有 RS-232 设备、DI/DO 开关量需求，或总点位数超过 1,000 点，请勿选择 R1000（仅一路 RS-485），应选配 R1100 或 reTerminal DM。
  • 免电脑现场交互：若弱电间或机房没有常驻电脑且需就地配置与看板巡检，请勿选无屏网关，应选用带 10.1 寸触控屏的 reTerminal DM。

现场怎么部署​

一、装硬件：机柜施工、供电与总线接线​

  1. DIN 导轨安装与供电：

    • 使用标准 35mm DIN 导轨卡扣将网关牢固安装在弱电井或自控机柜中。
    • 推荐采用工业级 DC 12V/24V 稳压开关电源（允许宽压范围 DC 9–36V）。
    • 接地防浪涌：主机的保护接地端子（PE）建议通过截面积 ≥2.5mm² 的接地线连接至机柜等电位接地排，以抑制现场电机与变频器引入的共模干扰。

  2. 网络与 BACnet/IP 规划：

    主机要有一块在 BACnet 网段上的网卡

    BACnet/IP 的发现基于广播。主机必须有一块位于 BACnet 网段上的网卡，并且广播不被网络交换机过滤。远程 Linux 部署建议使用主机网络模式（network_mode: host）。Docker Desktop 的本机桥接部署可能不转发广播——那种情况下可手动填写 BACnet 设备 IP 地址。

  3. Modbus RTU / RS-485 接线与串口设备直通：

    • 接线规范：必须采用屏蔽双绞线（STP），A+ 与 B- 分别接控制器对应端子，屏蔽层在网关侧单端接地。RS-485 总线须为“手拉手”菊花链拓扑，禁止星型或树型分支；总线末端设备建议接入 120Ω 终端电阻。
    • Docker 串口挂载配置：标准容器配置默认不挂载宿主机串口。若使用 USB 转 RS-485 适配器或板载串口，需在 docker-compose.yml 中显式挂载设备节点并配置用户组权限： 
      services:
        gateway:
          devices:
            - "/dev/ttyUSB0:/dev/ttyUSB0"  # USB转485适配器，或板载串口 /dev/ttyAMA0
          group_add:
            - "20"  # dialout 组 ID，确保容器内非 root 用户具备串口读写权限

    开生产写入前，先在本地控制台使用实际的从站地址与寄存器地址进行单点回读验证。

二、装软件：安装并接入第一个数据源​

逐设备步骤和应用包在可部署方案页，按现场条件选好配置后下载。

选配置并下载应用包 🖱️

  1. 部署 —— 本地目标装在运行 SenseCraft Solution 的这台机器上；远程目标经 SSH 装到控制器网段上的 reComputer R2000 系列或 reTerminal DM。
  2. 创建首个管理员 —— 首次运行不需要注册令牌。
  3. 添加数据源 —— OPC UA、Modbus、BACnet/IP 或 MQTT，然后在支持的地方运行发现：OPC UA 浏览、 Modbus TCP 站号扫描、BACnet Who-Is、MQTT 主题观察。它们产生的都是候选项。向导按协议逐项问地址与 轮询周期：
  1. 确认点位 —— 只有被确认的候选才成为受管点位。发现不完整或不可用时，可以手工填写 点位。
  2. 授予写权限之前先核对质量 —— 先在点位页看实时值与逐点数据质量。
  3. 配置数据服务 —— 内置 Broker，以及可选的北向上送。

难度中等，到控制台跑起来预计 15 分钟；接入第一台控制器并核对数据质量耗时更长。

有哪些接口​

数据从三个接口离开主机：

  • 运维人员 —— HTTP 8280 上的浏览器控制台：数据源管理、点位总表、命令回执、插件管理。
  • 现场系统（SCADA、能耗平台、自有服务） —— 订阅 1883 上的内置 Broker。点位遥测在 missionpack/v1/{gateway}/points/{point_id} 下，在线状态、命令与回执主题共用同一套契约。
  • 云端或总部系统 —— 启用到外部 Broker 的北向上送，端口 8883。遥测按 QoS 1 批量发送，每个数据源 的健康与遗嘱状态是 retained，另有 QoS 0 心跳。当前发布的镜像不含北向上送。

{gateway} 是部署时自己设的网关标识，因此多台中枢可以向同一个 Broker 上送而不互相覆盖。

主题契约​

主题 / 端口内容retained
HTTP 8280 /浏览器控制台—
missionpack/v1/{gateway}/points/{point_id}（1883）带版本的点位遥测——值、质量、时间戳、revision否
同前缀下的在线状态 / 命令 / 回执主题（1883）数据源与网关在线状态、下发的命令，以及每条命令的回执在线状态为是
missionpack/v1/{gateway}/telemetry（8883）北向批量遥测信封，QoS 1否
每个数据源的健康与遗嘱主题（8883）数据源健康与网关状态是

北向信封是 missionpack.northbound.v1：

{
  "schema_version": "missionpack.northbound.v1",
  "message_id": "0f3a...",
  "gateway_id": "gw-01",
  "created_at": "2026-09-05T05:01:19.045514Z",
  "samples": [
    {
      "source_id": "ahu-bacnet",
      "point_id": "analog-value:12",
      "ts": "2026-09-05T05:01:18.900000Z",
      "quality": "good",
      "value": 23.5,
      "source_revision": 4,
      "point_revision": 7
    }
  ]
}

source_revision 与 point_revision：点位被重新映射时 revision 会变，据此区分「配置变了」和「现场值 变了」。不检查 revision 的消费方会把配置变更前后的数据接成同一条序列。

契约的两条限制：

  • 协议是 MissionPack v1，当前版本不兼容 Sparkplug B，Sparkplug 宿主应用需要加一层转换。
  • 明文 MQTT 只允许遥测。 开放远程控制前必须启用 TLS 并配置具有控制权限的身份。

性能与实测数据​

负载由四协议模拟器生成，每档在一台设备上本机回环实测，没有现场部署数据。

2,000 点规模的刷新周期​

三档的共同条件：4 个数据源共 2,000 点（每源 500），运行时长如表所注，仅本机回环，设备为 reComputer R2000 系列（arm64）。

档位采集周期结果
稳定档OPC UA/Modbus 5 秒、BACnet 10 秒，运行 180 秒349.99 events/s（目标 350.0 的 99.99%），预测 0.939 cycle/s，进程组 RSS 峰值 217.3 MiB，1 分钟 CPU 峰值 22.1%，failed_sample_deltas 为 0
下降档OPC UA/Modbus 2 秒、BACnet 4 秒跑满 900 秒，吞吐 718.9 events/s（99.1%），但预测降到 0.872 cycle/s，以 PREDICTION_CYCLE_RATE_LOW 判失败
失败档OPC UA/Modbus 1 秒、BACnet 2 秒148.2 秒即 PREDICTION_WRITE_CHAIN_TIMEOUT 终止，远未到 900 秒目标；首个 warmup 周期就已有 2 个 Modbus 输入点缺失

复现：上游提交 b5fe4cc，四协议模拟器；原始运行记录见上游包 description.md

北向断网恢复​

条件：云 Broker 断网 300 秒（杀掉 Broker 进程或容器，不是链路劣化），事件率约 350 events/s，spool 上限 512 MB / 86,400 秒，运行 1,800 秒，arm64 主机。

指标数值条件
断网期 spool 增长queued_bytes 60.1 KB/s；峰值 18.33 MB / 325 批重连后排空到 0
Broker 重启到首条重放1.2–2.2 秒量的是「重启→首条重放」，是「CONNACK→首条重放」的上界
补传完整率，持久化 Broker1.000持久订阅会话，按 message_id 取集合交集
补传完整率，内存 Broker0.9839 ▲同样 300 秒断网

▲ 缺失的 58 条都在 Broker 重启后 0.496–1.058 秒，早于测试订阅者 1.069 秒的 SUBACK，属于订阅建立前的观测空窗，网关侧没有丢弃。

复现：上游提交 f831bae；原始运行记录见上游包 description.md

运行时与关键参数​

运行时以容器镜像形式从 sensecraft-missionpack.seeed.cn 分发（x86-64 与 arm64），目前没有公开的源码仓库。

  • 点位上限：2,000 个受管点位，其中 50 个可写，由代码强制。
  • 采集周期：决定 2,000 点规模能否稳定运行，见上表：OPC UA/Modbus 5 秒、BACnet 10 秒通过，收紧到 2 秒 / 4 秒即判失败。
  • 北向 spool：容量与时长上限（实测用 512 MB / 86,400 秒）决定本机能扛多久断网；另可配批大小与是否启用 QoS 0 心跳。

已知退化​

  • 采集周期每收紧一档，结果从通过变为下降、再变为中止；判失败的指标都来自预测插件（PREDICTION_*）。
  • 预测插件速率有结构上限（未修复）：循环是「跑完一个 cycle 再固定 sleep」，速率为 1/(1.0 + t_cycle)。2,000 点规模下 t_cycle 约 0.119 秒，上限约 0.894 cycle/s，低于长稳测试要求的 0.90 门槛。

下一步​

  • 在同类目标主机上跑 72 小时无人值守运行，期间做网络、Broker、进程与设备恢复演练。
